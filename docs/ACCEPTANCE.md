# 完整验收：不靠成功提示蒙混过关

**状态：规格用例，尚未在产品上执行。**
**对应规格：SPEC.md 0.2.0 · 2026-10-02。**

本文件定义成品需要证明的行为。自动化测试、真实软件行为、安装验收与真人体验是不同证据。每次记录 OS/架构、目标产品版本、浏览器版本、adapter/rule 版本、执行入口与观察能力；不能以 mock 或 CI 数量替代真实目标测试。

## A. 四个端到端金标准旅程

### G01 · 第一次装好后真的用起来

**场景。** 一台没有本工具的新 Mac；已安装一个受支持 Claude Code 和 Chrome；有既有配置与个人浏览器数据。测试者没有读开发文档。

**操作。** 打开应用 → 选择 CC → 选择减少外发 → 确认功能影响 → 应用 → 在该环境打开新会话 → 接入目标浏览器扩展 → 应用浏览器设置。

**通过。** 不要求模型 key、不安装完整新浏览器、不全局改 shell；CC 的实际作用域与效果被检查；个人登录与工作内容保持；扩展在正式浏览器中可持续使用。常规路径不要求逐文件理解。

**观察。** 修改前后结构化差异、真实启动上下文、浏览器原生有效设置、允许与拒绝的合成网络对照；真人能准确说出“改了哪个环境、哪些功能受影响”。

### G02 · 账号问题后的完整清理与重建

**场景。** 合成旧登录/状态、会话、指令、MCP/hook 配置混在一个目标中，另有完全无关的实例；浏览器目标站点和同域/异域站点均预种植数据。账号异常用合成状态替代真实封禁。

**操作。** 选择重建 → 确认共享范围 → 暂停目标 → 归档 → 清除选中本地状态 → 创建新环境 → 选择迁入工作内容 → 重新启动检查。

**通过。** 目标旧状态不再被误用；不影响另一个实例；工作内容可读取，兼容会话可按实际能力续用；执行配置没有无声启动；新登录未因旧任务重放被删除。

**观察。** 原始/归档内容摘要、凭据元数据而非值、浏览器 fixture 验证、启动入口、回写来源。输出分别报告本地清理、远端撤销和重新登录状态。

### G03 · VPS 任务中断不重做破坏性操作

**场景。** Linux VPS 有两个服务，目标服务带自动重启；SSH 可人为断开；客户端/服务端能注入“执行成功但 ACK 丢失”。

**操作。** 从 Mac 提交维护 → durable accept → 断网 → 重新连接 → 查询同一任务 → 在 Linux CLI 查看同一 receipt → 恢复可逆设置。

**通过。** 不影响 SSH 与另一服务；未重新执行已完成注销/清理；任务进度不因 GUI 重开丢失；恢复不覆盖用户后续编辑。

### G04 · 升级之后仍值得保留这个工具

**场景。** 完成保护后，外部管理器改变一项配置，浏览器扩展失去一个权限，产品版本升级导致一条规则需复查。

**操作。** 触发漂移检查 → 查看具体原因 → 接受一个差异、恢复一个差异、对新版本做复验。

**通过。** 不重复制造告警；不会后台注销、删除历史或重启；“接受当前值”被尊重；失效保护不继续亮绿；结果可以直接驱动修复而非只出现建议。

## B. 配置、认证与范围

| ID | 输入/故障 | 必须观察到的结果 |
|---|---|---|
| C01 | shell、user settings、project settings 对同一键有不同值 | 按被测键的真实规则解释，不能套通用优先级 |
| C02 | 从 GUI、终端、IDE、systemd 启动同一程序 | 每个入口分别确认；终端通过不能给其他入口盖章 |
| C03 | settings 新增 env 与删除 env | 生效时机正确区分；旧进程不能被假装已 unset |
| C04 | 只在一个 profile 应用方案 | 其他 root、通用代理、AWS/Google 配置不变 |
| C05 | Keychain 锁定并存在 credential file fallback | 定位到实际使用的存储，不出现“双凭据漏清” |
| C06 | 两个 config root 实际共享某类认证 | 计划报告共享范围，不给“单环境注销”假承诺 |
| C07 | 较旧版本的 auth status 无较新字段 | 使用有证据的替代识别或精确降级，不把缺字段当默认 root |
| C08 | 高层组织策略控制设置 | 不通过低层隐藏覆盖；显示控制者 |
| C09 | 配置损坏/重复键/不支持格式 | 保留原始文件，不整份覆盖；其他独立动作可继续 |
| C10 | apiKeyHelper 或 shell rc 含副作用 | 被动发现不执行它，不启动 agent/hook/MCP |
| C11 | 用户预览后换了账号或 config root | 原计划失效；新数据不自动加入旧授权 |
| C12 | Product-managed telemetry 与用户自设 OTel 并存 | 方案按类别改变，不以通配符清空监控配置 |

## C. 浏览器实测

测试应在 Chrome、Edge、Firefox 的正式支持版本分别执行，不以 Chromium 单次通过覆盖所有浏览器。

| ID | 输入/故障 | 必须观察到的结果 |
|---|---|---|
| B01 | 同一扩展 ID 在两个 profile 安装 | 两个配对实例；A 的任务不能落到 B |
| B02 | profile 被复制，扩展 storage 标识也被复制 | 冲突被识别并重新配对，不默默合并 |
| B03 | 在目标与邻域预种 Cookie/localStorage/IndexedDB/SW/CacheStorage | 目标按已批准类型清理，邻域按明确范围保留 |
| B04 | Cookie 的 origin 指向一个子域 | 预览展示实际可注册域影响，不声称仅该子域 |
| B05 | Firefox 请求站点级 HTTP cache 清理 | 不调用忽略范围的全缓存清理来假装完成；全 profile 选项另行确认 |
| B06 | Firefox 容器 Cookie store 中同站点数据 | 依据支持能力限定 store；不串删其他容器 |
| B07 | 目标页、service worker 正在写入存储 | 控制新加载并处理写入者；删除后复查，不以早到 callback 结算 |
| B08 | 删除完成后用户重新登录；旧 ACK 丢失 | 不自动再删新登录；查询持久结果/重新确认 |
| B09 | 隐私选项被其他扩展或策略控制 | 返回控制权冲突，不能显示已生效 |
| B10 | WebRTC 设置在整个 profile 生效 | 界面明确范围；通话/媒体负例可重现，支持单项恢复 |
| B11 | 专用 browser 启动参数被现有实例接管 | 不误认隔离成功；纠正启动/实例绑定 |
| B12 | 扩展被禁用/卸载/升级，native port 丢失 | 任务不丢、不擅自重放；保护状态变更有精确原因 |
| B13 | 实际 API 没有列举某类存储的能力 | 只报 browser-acknowledged；不编造零残留数字 |
| B14 | 未批准第三方邮箱/SSO 域 | 清理流程不能退出这些站点登录 |
| B15 | 恢复 WebRTC/代理时其他软件已经改值 | 显示冲突而非用旧备份覆盖 |

## D. 网络与真实覆盖

| ID | 输入/故障 | 必须观察到的结果 |
|---|---|---|
| N01 | 相同 host 上混合模型请求与额外请求 | 不按 host 把模型请求一起封掉，也不从 CONNECT 推断请求类型 |
| N02 | 仅写 HTTPS_PROXY 后目标直接连接外网 | 不显示强约束；覆盖标签只对应受控通道 |
| N03 | 允许与拒绝的合成请求 | 允许成功、拒绝失败，两者日志与真实结果一致 |
| N04 | 观察器失效而目标没有观测事件 | 不给“零外发”结论；正对照失败使验证无效 |
| N05 | 同一程序从另一个未登记入口启动 | 不错误继承已验证标签；提示覆盖不同 |
| N06 | IPv6、UDP、DNS、子进程直接 socket | 强约束下都按规则验证；任何未覆盖项不得忽略 |
| N07 | helper/namespace/extension 未加载或能力不足 | 拒绝显示强约束生效，不以配置文件存在判成功 |
| N08 | 浏览器只能识别到应用级身份 | 不静默扩大 profile 范围，需用户批准应用级范围 |
| N09 | proxy 崩溃、上游失效 | 强约束目标不静默直连；普通模式准确报告状态 |
| N10 | 目标使用本地 MCP/回调/SSH | 精确批准的本地例外正常；不为方便开放整个 LAN |
| N11 | 上游是 SOCKS，但目标不支持 SOCKS | 使用明确转换适配器或报配置不兼容，不直接写错 URL |
| N12 | NO_PROXY/大小写代理变量/PAC 造成分流 | 报告实际差异；不能用一个 echo 请求代表所有目标 |
| N13 | 只查看配置，没有 DNS 外部观测服务 | 不报 DNS 泄漏测试通过 |
| N14 | 网络日志中出现 Authorization、Cookie 或 prompt | 测试失败；导出不能带出这些字段 |
| N15 | 用户没同意网络诊断 | App 不运行 STUN、IP/ASN 查询或公共探针 |

## E. 清理、迁入与恢复

| ID | 输入/故障 | 必须观察到的结果 |
|---|---|---|
| R01 | 目标由 supervisor 自动重启 | 先处理已批准重启来源，再清理；不留下立即回写窗口 |
| R02 | supervisor 与另一工作实例共享 | 不全局 stop，计划揭示完整影响或改变操作方式 |
| R03 | 备份空间不足/目标只读 | 破坏性动作尚未执行；提供有效改路径方式 |
| R04 | 内容归档中夹有凭据或混合状态 | 不明文导出；敏感分类与不自动迁入标记有效 |
| R05 | 原始 archive 包含旧 hooks/MCP/插件 | 恢复内容不自动启用这些执行能力 |
| R06 | 原始会话跨版本不能续用 | 原始可读/完整性保持；不谎报可续聊恢复 |
| R07 | 删除之后同名文件重新生成 | 区分新合法状态与旧来源回写，不按文件名误判 |
| R08 | 运行中用户改变了选中 root | 原操作不能作用到新对象 |
| R09 | 远端注销失败，本地删除成功 | 分字段给结果，不“全部成功”也不抹掉本地完成 |
| R10 | 恢复时用户后续编辑了同一配置 | 按字段冲突处理，不整文件盖回旧版本 |
| R11 | 扫描受预算限制，只覆盖部分候选 | 不能生成声称“全部”的破坏性计划；需要续扫/缩小明确范围 |
| R12 | 回收区只移动未释放空间 | 不报告为已释放磁盘空间；这是恢复存储，不是垃圾清除 |

## F. 远程任务与并发

| ID | 故障注入点 | 必须观察到的结果 |
|---|---|---|
| J01 | accept 前断网 | 客户端可查询同一 idempotency key；不假定已执行 |
| J02 | durable accept 后、返回 ACK 前断网 | 重连得到原 job，不建立第二份清理 |
| J03 | 某个不可逆 action 成功后 ACK 丢失 | reconciliation，不直接重跑 |
| J04 | 服务端进程/主机重启 | job 从 journal 恢复，已完成步骤不重复；不确定步骤独立核对 |
| J05 | 两个客户端同时改同一目标 | 一个拥有操作权；另一个得到冲突，不产生交错状态 |
| J06 | 客户端取消/超时 | 服务端 deadline 起效；已完成副作用仍被记录 |
| J07 | 修改文件时另一个编辑器写入 | 检测或避免冲突；不能以脆弱先读后写宣称原子 CAS |
| J08 | SSH logout 杀掉 user service | 被实际检测；未验证存活时不承诺断线继续 |
| J09 | SSH host key 改变 | 停止并重新确认；不使用自动忽略模式 |
| J10 | macOS 缓存显示旧远端目录 | 远端 runner 重新核验；不按旧缓存删除 |
| J11 | 浏览器 service worker 重启 | extension journal 与消息去重保持，不删除新的登录 |
| J12 | plan 期间规则更新 | 使用已冻结版本或使计划失效，不换规则执行旧授权 |

## G. 安全与数据最少化

| ID | 输入/攻击样例 | 必须观察到的结果 |
|---|---|---|
| S01 | 目标路径 symlink 指向未批准目录 | 拒绝 mutation；检查最终对象而非仅字符串前缀 |
| S02 | 归档含 `../`、绝对路径、symlink 与压缩炸弹 | 导入拒绝，不写出目标根，不耗尽磁盘 |
| S03 | 文件名/日志内嵌 HTML 或指令文本 | 仅作为转义数据呈现，不执行、不改权限 |
| S04 | 网页向扩展发送伪造 cleanup 消息 | 不到达系统执行器；无 capability 不产生 mutation |
| S05 | 未配对 profile 或错误 extension ID | native host 拒绝，不能读取其他环境状态 |
| S06 | 规则包包含任意 shell/未知 action | 解析拒绝；签名有效也不能越过编译能力集 |
| S07 | 过期/回退攻击或签名失败的规则更新 | 不激活，保留可用已知版本 |
| S08 | 含个人路径/域名/账号的支持报告 | 默认脱敏，可预览；不自动上传 |
| S09 | 未启动任何网络功能 | 应用空闲无 analytics、license、远程资源请求 |
| S10 | 卸载产品 | 移除自己的组件；保留原始工作内容；恢复设置须尊重后续修改 |

## H. 体验验收与真实安装

| ID | 验收任务 | 通过标准 |
|---|---|---|
| U01 | 非开发者首次安装与扩展配对 | 无需终端临时加载、修改 flags 或猜 profile |
| U02 | 普通减少外发任务 | 默认一份预览、一次授权；系统必要授权除外，不逐文件问答 |
| U03 | 正在进行的重置任务切换窗口/重开 GUI | 能回到相同进度和目标，按钮不变成重复执行 |

| U10 | 性能预算 | 记录实测时间/内存/包体，未达标写原因，不靠删除任务能力达标 |

## I. 合成环境材料要求

准备两个服务、两个 CLI config root、两个浏览器 profile、至少一个 Firefox container、相关/无关站点、混合字段文件、可执行 hooks 的无害哨兵、外部管理器回写器、模拟凭据存储、正负网络探针与受控故障注入。

敏感字段使用明显合成值；不要把 个人、其他用户或第三方工具的真实 token/会话装进 fixtures。安装验收需要真人正常授权，测试账号使用自有、获授权的环境，不用真实账号做封禁实验。

## J. 发布记录格式

每一支持组合提供一份证据条目：版本与架构、用例 ID、fixture、步骤、结果、观察来源、已知限制。结果可为 pass/fail/not-run/not-applicable，但 not-run 不能计入通过率。

产品完成由 G01–G04 及其依赖用例共同决定；网络强约束单独列覆盖矩阵。不能拿配置解析单测通过，替代浏览器真实删除、远程断线恢复或真人用起来的结果。
