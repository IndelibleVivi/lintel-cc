## 1. 本轮完成标准

用户应能在 App 中完成以下工作，并在需要时让 Agent 通过同一 CLI 接手：

1. 从自己的目标找到操作入口，持续辨认主机、配置环境及实际作用范围。
2. 理解配置方案、工作保全、登录修复、清理重建、退役和恢复各自的结果。
3. 保存旧会话原件，查看内容，选择并审阅继续工作所需的上下文，在准确的项目与配置环境中开始新会话。
4. 通过独立入口尝试受支持的 Claude 原生续聊，理解格式识别、客户端支持与实际恢复证据的区别。
5. 在批准前看到目标、最终文件落点和用途；执行后沿原任务查询、恢复或继续下一步。
6. 找到并选定 CLI，核对实际执行上下文，把当前任务交给 Agent。
7. 在当前页面读懂关键步骤，必要时进入与候选版本对应的完整帮助。

前端、CLI、文档和回执必须描述同一种行为。完成状态按实际证据更新，保留平台差异和未验证项。

## 3. 前端成品要求

### 3.1 视觉方向

以 docs/visual-language.md 和当前身份资产为准：

- Day：纸色 #FAF9F5、文字 #3D3D3A、陶土强调 #C16A47。
- Night：底色 #24231F、文字 #EAE5DA、强调 #E0A485。
- 标题与字标沿用 serif，正文与控件使用 sans，路径、命令和证据使用 mono。
- 通过留白、细线、字重和内容分组建立层级；品牌强调色与成功、警告、失败的功能色分开。
- 保留 brand.svg、提供的 Tauri 图标、theme-aware Brand()、侧栏 lintel_、既有慢闪与 reduced-motion 行为。
- Clawd、风景、口袋互动和 playroom 保持伙伴层次。小游戏继续使用 App／官网共用的唯一实现。

同步消解主 SPEC 中仍残留的旧配色候选描述，避免与当前视觉权威冲突。

**目标观感是完成度高的桌面工具：安静、清爽、温暖，信息密度经过整理，操作关系容易辨认。** 每个主要页面都需要明确的构图。卡片用于独立对象或独立选择；普通字段、状态和说明使用连续内容组织，避免层层套框。

主操作使用可见动词，例如“预览变更”“批准并执行”“查看归档”“查询原任务”。影响、限制与失败原因保持可读字号，不能退成浅灰装饰小字。可亲近的标题与 Clawd 继续保留，实际操作说明使用具体语言。

新增阅读器和 Agent 页面应按用途设计，不能将现有大弹窗或首页框架直接放大后充当全部新界面。

- 完整路径可换行、查看和复制，不挤压操作按钮。
- sticky footer 不遮正文，模态关闭入口和主操作始终可达。
- loading、empty、unsupported、blocked、accepted、uncertain、partial、failed、completed 都有完整布局。
- 关键反馈留在任务表面，toast 只承担辅助反馈。

## 4. 共享目标与结果合同

这些是语义要求；最终字段名按现有代码约定确定，并由 operations/core 统一。

### 4.1 目标上下文

目标包含：

- 执行主机：本机或精确 SSH alias／绑定。
- Lintel 执行上下文：实际 state 来源与路径，必要的执行用户事实。
- 环境：environment ID、显示名称、配置 root。
- 项目工作目录：独立于配置 root，按目标主机上的实际路径验证。
- 客户端：准确 executable 与静态版本证据。
- 独立对象：浏览器 profile／instance、service unit、工作包来源分别明确，不借用当前环境标签冒充同一作用范围。

没有环境时也能切换主机。任务开始后，计划与回执使用冻结的目标；随后切换首页选择不会给原任务重新贴上新目标标签。草案按实际主机与环境隔离。

### 4.2 启动上下文

新的 App 流程让用户明确选择项目工作目录。客户端进程使用项目目录作为 cwd、配置 root 作为 CLAUDE_CONFIG_DIR，两者分别校验。

project cwd 属于一次启动，同一配置环境可用于多个项目；可以按主机／环境记住上次选择，但每次展示实际值。执行端核对目录存在、可访问及其身份，不为了启动创建项目、移动代码或修改权限。

已有 raw protocol-1 和普通 CLI launch 的兼容默认值保留；旧调用没有 project cwd 时保留既有行为。新 App 对未选择项目的情况给出清楚选择，不把“新配置目录”显示成已恢复的项目工作区。

版本识别沿用静态安装元数据。认证检查继续使用现有显式有限入口，区分未检查、认证方法与已观察状态；仅创建新 root 不得推导已经得到独立身份或已完成登录。

SSH 启动继续经过有限 controller、绑定 runner 和 PTY。远端返回的路径或 executable 不插入本地 shell。路径在所属主机验证。

为带项目目录及会话模式的新入口建立小型、不可变的启动请求，保存准确目标、mode 与输入引用，由目标 runner 根据有限 request ID 解析。沿用已有存储与核对机制，不增加启动队列。启动请求独立于 preserve 等 mutation job；查询保全回执不会再次发起会话。

### 4.3 资料用途

归档选择与启用选择分开，至少表达：

| 用途 | 语义 |
| --- | --- |
| 原件 | 保持字节完整，供未来阅读、检查或兼容处理 |
| 待用资料 | 位于参考区，不由 Lintel 注册成活跃原生会话 |
| 个人指令 | 放入会被客户端按其规则发现的指令位置，用户审阅后选择启用 |
| 工作交接文本 | 本次选定的工作上下文，由用户明确用于新会话 |

CLAUDE.md 单独说明其指令角色，修正“所有迁入内容不会自动启用”的笼统表述。原件中的秘密识别与文件选择范围是不同事实；没有内容审查时不宣称正文已经脱敏。

### 4.4 结果与覆盖

继续保留既有 status、steps、coverage、恢复信息和兼容字段；新增用户任务结果时使用结构化字段及稳定语义。

界面分别展示：

1. 本次所选步骤实际完成了什么。
2. 哪些范围未请求、未检查或未验证。
3. 接下来可以采取的动作。

用户只选择本地清理且这些步骤成功时，主要结果写“所选本地清理已完成”，同时说明官方注销未请求、服务端状态未核验。原始 legacy 状态可以保留在证据中；不能单纯改成 completed 来抹掉覆盖限制，也不能按中文 message 推测成功和下一步。

## 5. 首页与完整任务旅程

### 5.1 一份任务映射

复用当前六类任务，整理稳定 task ID、用户名称、App 路由、相关 operation、适用目标、前置条件和帮助锚点：

- 减少外发，保留需要的功能。
- 保存工作资料，或准备新配置环境。
- 修复登录、清理重建、退役环境。
- 处理具体浏览器 profile。
- 连接 SSH 主机并操作远端环境。
- 找回结果、恢复配置或服务。

首页、帮助、CLI 任务说明与文档从同一受维护来源生成或校验。它是有限元数据，不引入新的执行层。已有主导航可保留专业工作区，任务首页负责帮助用户进入正确路径。

### 5.2 前置条件与受阻处理

前置检查显示缺少什么，并提供已有能力能完成的修正动作：

- 未选目标：选择或登记目标。
- 缺少客户端／runner：进入准确的检查、选择或安装说明。
- 写入者未停止：显示已识别对象与已有控制入口。
- 浏览器未配对／未完成真实重启：进入对应面板及具体步骤。
- 计划过期或条件改变：重新预览。
- 已接受或副作用不确定：只查询原任务。

复用结构化 error code、phase、diagnostic 和 recovery。Work、Cleanup、Browser 等页面不再把结构化错误统一压成一条 message。关闭页面后，待处理任务仍能从记录找回。

### 5.3 按意图区分工作与清理

| 用户意图 | 必须明确的执行结果 |
| --- | --- |
| 只备份工作 | 生成加密工作包；不创建新配置环境 |
| 保留旧环境，准备新的 | 归档、创建新 root、按用途准备内容；旧环境和旧登录保留 |
| 修复本地登录 | 按批准范围处理已识别状态，官方注销单独表达 |
| 准备新环境后处理旧状态 | 保留现有归档／新 root／迁入先于批准注销和移除的顺序；资料与目录准备完成不代表新账号登录已完成 |
| 退役旧环境 | 保全、处理批准的状态、停用登记；原始工作目录的保留事实可见 |

归档、新环境准备、旧状态处理、登录检查和启动是不同结果阶段。用户可以从已完成阶段继续，不重新提交原副作用。

## 6. 计划、迁入与原任务恢复

### 6.1 批准前确定落点

对本轮新生成的 plan_preserve、plan_reset(recipe=rebuild)、plan_cleanup(recipe=reset_client) 和 plan_import，提供一致的公开清单：

- 来源主机／环境／工作包与摘要。
- 每个文件的原相对路径、类别、大小、摘要。
- 目标主机、配置 root、最终相对路径与用途。
- 创建新目标或使用既有目标。
- 名称冲突的具体分配与已有目标文件处理。

plan_preserve、plan_reset(recipe=rebuild) 和 plan_cleanup(recipe=reset_client) 在计划阶段确定新环境 ID、规划 root 和迁入映射，并纳入批准内容。规划不创建目标目录；执行时复查父目录身份，并要求这个规划的新 root 仍不存在。

plan_import 使用已登记、已存在的目标 root，执行时复查该 root 的身份，并要求本次规划的各目标文件仍不存在。这里不能要求配置 root 本身缺失。所有入口保留整批命名与冲突复查；条件变化使原计划失效，不在执行时静默改名、换 root 或采用另一套内容。

用户已经有登记目标时，从独立迁入入口使用该目标，不再强制创建第二个新环境。

### 6.2 兼容与恢复

只扩展公开 allowlist，不暴露内部 extra、秘密或文件正文。App 与 CLI 使用同一公开计划。

新计划记录合同修订号。旧持久计划与旧回执按既有合同读取，不补写新 UUID 或改 hash。尚未接受的创建新环境类旧计划若缺少冻结目标字段，在接受和任何副作用之前返回 stale_plan，要求重新预览；旧 raw API 仍可生成新合同计划，旧 rebuild 的结果语义保留。其他兼容计划沿用原合同。

已接受、执行中或不确定的任务始终查询原记录。远端已经存在提交 intent 或任务记录时，继续遵守原记录 query-only 规则，不删除记录来重新提交；只有确认尚未接受且没有待核对副作用的旧计划，才引导用户另行生成新计划。

保留创建／文件发布前写入准确 intent、原任务去重、readback 确认、阶段失败的准确残留记录。恢复只处理能证明由原任务拥有的内容，保留外部编辑与相邻环境。

cleanup 必须在需要的归档和新资料准备阶段成功后，才进入该计划批准的后续旧状态处理；某一阶段失败不能继续越过。

## 7. 旧会话资料与新上下文

### 7.1 原件

继续保留 lintel.work/1 与原始文件字节，不重写 JSONL 的 ID、未知字段、signature 或关系信息。包摘要证明文件完整性，不能显示成协议签名有效性。

分类命中的 JSONL 数量称为文件数；只有识别出相应关系并有来源依据时才称会话数。根级索引、附件和其他未被现有规则纳入的文件不能暗示已完整备份。

沿用现有大小与扫描预算，对超限、扫描不完整、格式不识别明确显示结果。扩大上限需有针对性验证，不能为阅读器无条件读入全部历史。

### 7.2 按需阅读器

从用户明确打开的本机任务或目标主机上的独立工作包读取，继续使用 exact-one job_id/archive_path 与现有秘密输入通道。

实现以下视图：

- 来源信息、文件清单、格式识别结果。
- 已识别的用户／assistant 消息、工具调用与结果。
- 原始文本视图和未知记录的回退表示。
- 对超一页内容进行有界分页／加载；显示是否还有内容、截断或解析失败。
- 返回索引后保留阅读位置。
- 选择一个或多个内容片段进入交接稿。

未知块仍保全，不因为 parser 不认识就静默丢弃。消息中的命令、链接、工具内容和路径只按资料显示；读取记录不会自动执行它们或抓取外部资源。Markdown 使用项目既有安全渲染规则。

分页与选择绑定具体包／文件摘要。源变化后旧分页位置和选择不能对应到另一份内容。原件以字节为准，显示层的编码替换与解析限制要可知。

解锁秘密仅在必要的当前交互内持有，关闭或切换资料后清理；不用新的后台全文索引或常驻解密服务完成本轮需求。

### 7.3 生成可审阅的工作交接稿

用户选择需要继续的内容，交接稿至少支持：

- 目标与约束。
- 已作出的决定。
- 关键文件及实际位置。
- 当前工作状态。
- 下一步。
- 待验证事项。

采用确定性选择、整理和用户编辑，不以外部模型摘要服务作为本轮前提。保留来源包／文件摘要和可定位片段，用户能回看根据。旧绝对路径的存在与映射需核对，不能把旧路径机械替换后宣称可用。

交接稿是派生材料，不修改原件，不生成伪造的 Claude transcript。opaque thinking 不进入供新会话发送的文本；用户可读的正文与工具材料按选择处理。

资料内容留在相应的私有内容通道。普通 job、日志、诊断导出与 Agent 操作交接包只记录必要元数据，不持久化整段工作正文。需要保存独立明文交接稿时，明确显示位置和用途，并采用批准后的私有文件发布与 readback；用户可仅复制而不落盘。

### 7.4 实际进入新会话

本轮采用清楚的人类交互路径：

**审阅最终文本 → 点击“复制上下文并打开新会话” → 在准确项目和配置环境中打开 Claude → 用户粘贴并发送。**

- 点击组合动作时核对当前文本、目标、项目目录和客户端仍对应最后审阅版本。
- 捕获当前编辑稿和启动目标的同一份快照，操作进行中锁定该提交版本；编辑、切换主机或后台选择变化不会替换正在复制和启动的对象。
- 复制失败时保留可选择文本和具体错误，不声称复制成功；组合动作停止在该阶段。
- 普通 launch 继续使用真实交互终端、无 prompt 的既有合同。
- App 分别反馈“已复制”“已请求打开”“打开失败／结果待核对”。实际发送和模型读取没有观测证据时保留为待用户完成。
- 交接稿内容、目标或项目改变后，审阅状态失效；已复制旧内容的事实不能替代当前版本核对。
- 复制到系统剪贴板是明确的用户动作，不在后台自动发生。
- 复制成功而启动失败时分别保留这两个结果，提供仅重试启动；结果不确定时先核对原启动请求。不会监听剪贴板来推测用户是否发送，也不会自动清除用户后来复制的内容。
- 保存文件、复制内容、打开终端和模型接收分别验收。

该路径交付完整的人类继续工作流程。自动发送、系统提示词注入、键盘自动粘贴和任意 prompt launcher 不混入现有启动接口。

## 8. Claude 原生续聊

原生 resume 是独立任务，与归档、导入和新上下文明确区分。本轮实现有限入口和结果处理，并建立它实际支持的客户端／平台证据。

### 8.1 输入与检查

用户明确选择原生续聊后，检查：

- 原始 transcript 及其摘要、可识别的来源／项目信息。
- 目标主机、配置 root、项目 cwd、静态客户端版本。
- 原生入口是否受该客户端版本支持。
- 已知的会话格式情况；未识别内容保持 unknown。
- 当前认证检查事实，以及可能影响启动的已知配置／hooks／MCP 信息；不能用“未迁入这些文件”推导当前运行环境不存在它们。
- 原会话是否可能仍在运行、此入口是否可能连接现有会话。无法判断时清楚显示，不承诺创建了新的独立进程。

优先复用官方客户端支持的按 transcript 绝对路径等入口，使用有限 adapter 组装参数。路径在目标端解析和验证，原件继续保留，不通过改写 ID、删除签名或伪造索引来“修复”会话。

将归档中的原件与客户端可写的运行输入分开。为选定 transcript 准备私有运行副本并核对字节，预览其位置与用途，原归档不交给原生客户端写入。副本包含解密后的会话资料，按私有文件权限与本轮批准的输出管理；不写入普通日志或支持包。

Claude 可以按自身规则更新所选配置环境中的运行状态，这项影响需在续聊预览中说明。复制输入文件本身不能证明客户端不会按内部路径或索引访问原会话位置；adapter 的支持证据需要覆盖该行为。无法约束到所选目标的组合标明不支持，不把“已做副本”当作目标隔离证明。

### 8.2 启动与结果

新增原生续聊入口保持严格有限参数，复用已有 launch_context、Terminal／PTY 和 remote controller。它不开放任意 shell、任意 argv 或通用代理执行器。

用户能在启动前看到此次采用的模式、目标与已知状态恢复影响；客户端权限模式与是否可能 attach 现有进程需明确。能力不支持时返回具体原因和可读原件／提取新上下文入口。

原生启动必须由明确动作触发；import/preserve 成功不会自动 resume。取消和重复点击不重复启动；连接中断或结果不确定时先核对原启动请求，不能自动换另一种方式再次启动。交互启动不包装成可脱离终端的 mutation job，也不新增后台存活承诺。

区分以下证据：

1. 静态元数据／官方资料表明该入口存在。
2. 合成客户端证明参数、路径和流程正确。
3. 具体原生客户端实际恢复成功。

只有第 3 项可以支持相应范围的“实际续聊已验证”。开发期间没有真实认证授权时完成前两层，第三层保留为明确验收项；不能据此将整个原生入口做成空占位页面或从完整目标中删除。

### 8.3 thinking 说明口径

帮助文档使用以下准确口径：

- signature／redacted thinking 作为不透明原件保存，Lintel 不解析或修复其协议签名。
- 当前官方规则存在模型、对话前缀及特定模型的账户适用条件；具体行为按支持版本的资料维护。
- Sonnet 5.5 的 originating／linked account 规则约束 thinking 可用性，不代表当前请求自动采用旧认证。
- resume 会接续历史及客户端支持的部分状态；认证来源、配置目录、项目目录和原生会话分别核对。
- 不把新目录、新 session ID 或删掉某字段描述成独立身份／不可关联保证。

这些机制写入完整说明；普通用户界面优先解释选择后的具体结果。官方资料入口见文末。

## 9. 终端与 Agent

### 9.1 明确可发现入口

增加“终端与 Agent”入口，至少可从帮助和主要导航区域直接找到。环境、计划、回执各自提供“交给 Agent”，携带当前精确上下文。

CLI 是使用方式；相关任务继续使用第 5 节的共同映射。

### 9.2 选定并核对 CLI

用户选择准确 executable 后，通过有限 native 检查入口执行固定的静态命令，限时、限输出、无 shell：

- version。
- capabilities。
- describe／schema 的必要操作。
- 新增的只读执行上下文描述，命令形式可采用 lintel context --json。

上下文描述复用 core 的路径解析，返回必要的执行用户、HOME/state 来源与实际路径、目录是否存在；不得初始化 state、执行 discover 或启动 Claude。仅打印版本和帮助也不得创建 state。

候选包从其 candidate.json 等既有资料核对平台、候选标识及当前二进制字节。sidecar 缺失时可以显示“独立构建／候选身份未知”，同时保留已观察到的接口可用事实。checksum 一致与来源认证分别说明，裸 0.1.0 不能作为唯一候选身份。

App 与 CLI state 不同时显示差异，让用户选择正确上下文。核对不会自动更改 PATH、HOME、shell profile、服务或复制 state。远端任务继续使用原绑定 runner，保留历史查询兼容路径。

### 9.3 Agent 操作交接包

操作交接与第 7 节的工作正文交接分开。默认在内存生成有限、可审阅的展示对象：

| 内容 | 要求 |
| --- | --- |
| task | 用户目标、稳定 task ID、所选非秘密参数 |
| target | 本机／SSH／浏览器精确目标、环境 ID、完整配置 root、必要的项目 cwd |
| executor | 选定 CLI 路径、平台／协议／候选核对事实 |
| state context | 足以定位同一份 Lintel state 的来源与路径；远端保留原 runner 绑定 |
| plan or job | 原 ID、hash、已观察状态及观察时间 |
| next action | 检查目标、准备计划、查询原任务或独立恢复的准确入口 |
| authorization | 已有授权对应的任务和范围；复制内容不会产生新授权 |

不读取工作正文来填充操作交接包；口令、令牌、Cookie、私钥、完整 state 与原始聊天正文不进入其中。需要正文时走第 7 节的明确选择与审阅。

有原 accepted／uncertain job 时，交接指向原 ID 查询。Agent 接手不能把相同操作重新生成和提交一次。用户更改目标、内容或任务后重新审阅材料，不能沿用旧包的目标声明。

复制的命令和材料可直接使用，所有 ID／路径从真实上下文组装；缺失信息清楚标注，不能填充貌似可运行的伪值。

### 9.4 子命令帮助

在 state 初始化与参数执行前处理各命名子命令的帮助，覆盖 env、policy、work、job／restore、remote、launch 和新增会话入口。

describe 提供相应命令用法及必要人工步骤。现有清理／service 能力可继续清楚映射到 call OPERATION，不为名称对称另建执行路径。对外示例必须由实际 parser/schema 验证。
