# 环境覆盖与使用收尾开发方案

2026-10-06 · 接续开发方案。完整目标仍由 [SPEC](../SPEC.md) 与 [产品基线](product-baseline.md) 定义；本文件标明已接通的第一步及后续实现与验收。后续计划不能作为能力已经交付的说明。当前交付事实见 [current-state](../current-state.md)。

## 本轮范围与接续顺序

已完成首页问候合并、原远端回执主机绑定、参考指令重复保全和官方注销的认证状态绑定；本次接续新增 core／CLI／App 的有限关联组件清单与元数据容量预检。更完整的环境覆盖、大文件保全、完整退场、启动收尾及非开发者发行继续保留，未在这轮加入生产操作。

| 工作线 | 当前基础 | 下一份可验收交付 | 前置条件与边界 |
| --- | --- | --- | --- |
| 认证与恢复可靠性 | 原任务只查询；官方注销冻结认证状态，主体缺失时拒绝；参考指令能重复归档 | 独立测试真实 Keychain、文件 fallback、多 root 与同账号凭据更新；准确报告观测来源和未知项 | 本轮只有 synthetic CLI 证据；真实账号操作需要单独授权，CLI 状态不能证明 Keychain token 世代 |
| 关联组件与处理范围 | 同一主机／环境的有限组件清单、原记录与只查询原 ID 的入口已接通源码 | 补已支持组件的真实 runtime 证据；再增加有限 IDE／Desktop adapter 与更多来源 | 从现有 inspection/receipt 投影；探针失败显示访问受限或未知；不另建通用 workflow 平台 |
| 工作保全与完整退场 | instructions/memory/sessions；精确文件清理；加密包与逐文件核对；元数据容量预检 | 按项目／会话／文件选择、有界内存大文件路线；随后才开放独立完整退场配方 | 保住全部选定内容及资产分类先于扩展删除；不修改现有 retire 的含义；包兼容与原任务恢复独立验收 |

“组件清单＋容量预检”已接通源码，让用户看见当前有限可处理范围与阻塞项；接通选择性、大文件保全和启动来源核对后，再扩展完整退场。非开发者安装可独立推进，但不能以源码或解包成功替代完整用户旅程。

## 关联组件清单

清单附着于原 environment 和任务，不用模糊名称重新猜主机。每项保留观察时间、来源、覆盖范围和下一步；事实变化后重新读取对应 owner，不把旧回执当作当前运行状态。

| 组件 | 要观察的事实 | 可复用 owner／入口 |
| --- | --- | --- |
| CLI | PATH 实际选择、其他可核对安装、executable、静态版本及安装来源置信度 | core 静态发现；明确选定 native executable 的有限 CLI inspector |
| 配置与项目 | config root、project cwd、user/project/local/managed 来源，hooks/MCP 是否可能参与 | core inspection、launch；仅列存在和来源，不执行配置内容 |
| 认证 | CLI 报告的来源、主体是否可核对、已识别文件、Keychain／目录外共享范围是否未知 | cleanup 的显式 auth probe 与共享来源限制；普通扫描不调用 Claude |
| IDE／Desktop | 是否支持、已验证版本与存储 owner、关联 root 和后台写入者 | 分别补有限 adapter；没有 adapter 时显示暂不支持，不宣称未发现 |
| 服务 | 确切 unit、manager、root 绑定、暂停回执、当前 blocker/cgroup 与后续外部编辑 | service 的 inspect／批准 pause/resume；PM2、Docker、cron 仍需独立实现 |
| 浏览器 | 确切配对 profile、原 clear ID、准备／等待 startup／待批准完成／已完成 | browser 原状态机和原任务；不将 extension worker 重启当浏览器重启 |

结果使用“已检查且未发现、已处理、用户保留、访问受限、未知、暂不支持”等可区分事实。配置根已处理、浏览器待完成、服务仍暂停时，原回执保留三个不同结论，并连接已有继续入口。下一步只生成对应有限预览；点击建议不自动执行。

## 大文件与多轮保全

当前单文件 8 MiB、所选合计 32 MiB、10,000 文件及扫描预算继续有效；超限拒绝保护原件，但当前只能按整类选择，还没有完成大文件出路。

容量发现已经与正文读取分离：在有界扫描中给出阻塞文件的相对路径、项目／会话、字节数、选择总量与超限原因；无权读取或超过扫描预算时明确标注未覆盖，不以空结果代替完整检查。下一轮支持用户按项目、会话或有限明确文件集合选择，冻结完整清单与落点，再读取选中文件核对身份和摘要。

大文件路径先比较兼容 `lintel.work/1` 的流式读写与显式分批独立包，按内存峰值、原字节保全、解密读回、跨 state 迁入、恢复与实现成本选定机制。不能只抬高内存限额，也不能截断 session；若必须改变包格式，先明确版本边界，保留旧包 reader。分包不隐式拆坏单个 transcript，每包独立完整清单、摘要、读回与来源；中断只核对原发布路径。

重复迁移继续区分资料类别与本次用途。参考 `CLAUDE.md`、活跃指令及重名参考均保留类别和摘要；映射说明来源与目的地，不覆盖、不自动启用。skills、agents、rules、hook 源文件与其他用户资产先增加可解释的保全和用途合同，再允许完整退场处理它们。

## 完整退场配方

将来作为“清理与重建”中的独立明确配方提供，不扩张当前 `retire`。准确区分 CLI 本体卸载、配置／历史／缓存、认证、编辑器与 Desktop、浏览器、服务和 shell 的处理范围；确认每个路径或组件的 owner、共享影响及恢复能力。

安装来源按实际 npm/native/Homebrew 或其他已支持方式核验，不能只删除 PATH 中一份入口。npm 的缓存是内容寻址结构，包名通配符未命中不能证明缓存不存在；编辑器状态也可能位于共享数据库或 secrets，未核验的共享存储不得整体清空。见 [npm cache](https://docs.npmjs.com/cli/v11/commands/npm-cache/) 与 [VS Code storage 能力](https://code.visualstudio.com/api/extension-capabilities/common-capabilities)。

版本适配可以考虑官方 `claude purge PATH --dry-run`，但先冻结明确项目、版本、预览输出与保留范围；重新核对并批准后才能执行，失败或输出不识别不能当清理成功。官方 purge 处理项目本地数据，不能视为卸载或全局认证清理，见 [Claude 目录与项目清理](https://code.claude.com/docs/en/claude-directory)。

全局 shell 的隐私变量和其他工具配置默认保留；若以后支持精确修改，应按字段或可证明的语法边界处理，保留同行其他内容。服务按确切身份和状态处理，不按名称杀全部进程；各用户、Docker volumes、PM2 与 cron 的发现和操作必须有独立支持合同。执行后复查已支持回写来源，所有未知范围保留在结果中。

## 启动收尾与发行验收

新 root 与旧项目 cwd 的组合仍可能加载项目 settings、hooks、MCP 和 managed 配置。启动前显示实际选择的 root/cwd、来源清单、认证位置与尚未核验入口，随后另行登录和启动；归档／迁入不自动启动。依据 [settings scopes 与优先级](https://code.claude.com/docs/en/settings)。

普通用户、容器、权限规则和网络代理分别解决不同范围。权限规则的文件系统绝对路径使用 `//`；工具权限规则不能证明任意子进程的文件／网络访问受 OS 限制。OS sandbox、用户边界和进程网络约束必须各自提供运行证据，见 [permissions](https://code.claude.com/docs/en/permissions)。

非开发者候选由一位没有开发环境的人，从明确版本产物开始完成 App／CLI 核对、正式持久扩展安装与配对、可逆设置、真正浏览器重启后的原 clear 完成、升级后原任务查询。Linux 支持、其他架构、native WebKit、真实认证分别验收；构建、安装、启用与正式发布保留不同状态。

## 必须能够拒绝错误行为的场景

| 场景 | 验收结果 |
| --- | --- |
| 一个大 session 与几份普通会话 | 指出阻塞对象；用户能选择完整资料并沿可核对的大文件／分批路线保全；原件不变 |
| A→B→C，指令始终作为参考；B 又有自己的活跃指令 | 两份及其重名副本均按类别、路径、字节和摘要核对；C 不自动激活旧参考 |
| 本机／B 打开 A 的原回执 | 查询、Agent 包、启动预览始终使用 A、原环境、原 ID 与绑定 runner |
| 预览后换账号、同账号文件凭据更新、Keychain fallback | 旧批准不能作用于可观察到的新认证；不可核验的来源明确限制；真实 Keychain 世代单独验收 |
| 配置根已处理、浏览器未完成、服务仍暂停 | 从原记录看见各项现状，继续正确步骤；不重做已完成副作用 |
| 新 root 加旧项目 cwd | 明确列出仍参与的项目／受管配置；“准备新 root”不能显示为全运行环境隔离成功 |
| 无开发工具的安装和升级 | 从版本产物完成旅程，升级保留 state 与原任务；不依赖源码 checkout 或猜路径 |

本方案不采用整目录通配清除、缓存包名匹配即验收、全局进程终止、“搜索不到 Claude 即完成”或绕过平台登录限制。它们不能保持现有用户资产、范围核对与原任务恢复合同。
