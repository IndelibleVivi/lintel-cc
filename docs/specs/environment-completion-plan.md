## 本轮范围与接续顺序

已完成首页问候合并、原远端回执主机绑定、参考指令重复保全和官方注销的认证状态绑定；接续增加 core／CLI／App 的有限关联组件清单与元数据容量预检。本轮按项目／会话／原件的精确选择已接通并通过 synthetic core、CLI、有限 SSH transport 和 built App 验证，可明确排除超限文件后保全其余完整原件；分层证据与未验证项见 current-state。本批已接通兼容包格式的流式大文件保全与启动来源核对；当前检查与 source／候选边界见 current-state。更完整的环境覆盖、完整退场、启动收尾及非开发者发行继续保留，未在这轮加入生产操作。

## 参考教程核对与采纳边界

完整核对提供的教程正文、表格及附件目录后：文档描述本地 CLI／Desktop／IDE、浏览器、各 VPS 用户与服务、安装与缓存、shell 变量、Keychain、新主机与低权限隔离等范围；提到的两份 shell 脚本没有随文档内嵌提供，其实现未经审查。正文中的 dry-run／apply 建议是参考材料，不授予修改真实账户或机器的权限。

| 原目标或建议 | Lintel 的处理与理由 |
| --- | --- |
| 先辨认旧状态，再明确预览、保全与清理 | 采纳目标；沿 core 冻结计划、独立批准、逐步读回和原 ID 查询，不以一次搜索或命令成功代替覆盖验收 |
| 一次覆盖 CLI、客户端、扩展、浏览器与服务 | 按独立 owner 适配；有限清单明确显示已检查、未知、访问受限与暂不支持。Desktop／IDE、PM2／Docker／cron 不以名称猜归属 |
| 整个旧配置目录都作为账号残留删除 | 不采用：里面同时有 transcript、memory、skills、agents、rules 和 hooks 源文件。必须先建立这些用户资产的可解释保全合同，才能推进独立完整退场配方 |
| npm 缓存包名通配、编辑器日志通配、shell 整行删除、按名称终止进程 | 不采用：内容寻址缓存、共享存储、同行变量和邻居进程不能用模糊匹配证明独占归属；各路径需有限身份与恢复合同 |
| Keychain 搜索后手动删条目、旧账号痕迹全部切割 | 真实凭据操作与 Keychain 世代需要单独授权和证据；文件状态／CLI auth 输出不证明服务端撤销或全设备清理，不增加盲删 Keychain 操作 |
| 旧 profile 清站点数据，专用新 profile 授权 | 目标已有独立 browser 状态机；按准确配对 profile、真实 browser startup 和另行批准 finishClear 完成。专用 profile 的建立／日常认证仍单独核对 |
| 新 VPS 干净重建，只搬确认过的项目与数据 | 作为主机管理选择保留；不是 Lintel 当前远端变更 endpoint，也不自动镜像、迁移数据库、改 SSH／防火墙或下线旧主机 |
| 非 root／容器与有限权限、联网控制 | 保留完整产品目标；运行身份、OS sandbox、配置权限和网络强制各有独立证据。修正绝对权限路径语法；不把工具规则当作任意子进程的 OS 约束 |
| 新环境使用前收拢授权链路 | 本批接通有限启动来源预览及变化复查，明确 root／cwd、hooks／MCP 声明、认证位置和终端后续核对；实际加载与登录仍单独观察 |
| 强清后按名字搜索不到即验收 | 不采用：范围外、访问受限、共享来源和服务端状态保留未知，不能用空搜索结果得出全清结论 |

## 关联组件清单

清单附着于原 environment 和任务，不用模糊名称重新猜主机。每项保留观察时间、来源、覆盖范围和下一步；事实变化后重新读取对应 owner，不把旧回执当作当前运行状态。

| 组件 | 要观察的事实 | 可复用 owner／入口 |
| --- | --- | --- |
| CLI | PATH 实际选择、其他可核对安装、executable、静态版本及安装来源置信度 | core 静态发现；明确选定 native executable 的有限 CLI inspector |
| 配置与项目 | config root、project cwd、user/project/local/managed 来源，hooks/MCP 是否可能参与 | core inspection、launch；仅列存在和来源，不执行配置内容 |
| 认证 | CLI 报告的来源、主体是否可核对、已识别文件、Keychain／目录外共享范围是否未知 | cleanup 的显式 auth probe 与共享来源限制；普通扫描不调用 Claude |
| IDE／Desktop | 是否支持、已验证版本与存储 owner、关联 root 和后台写入者 | 分别补有限 adapter；没有 adapter 时显示暂不支持，不宣称未发现 |
| 服务 | 确切 unit、manager、root 绑定、暂停回执、当前 blocker/cgroup 与后续外部编辑 | service 的 inspect／批准 pause/resume；PM2、Docker、cron 仍需独立实现 |
| 浏览器 | 确切配对 profile、原 clear ID、准备／等待 startup／待批准完成／已完成 | browser 原状态机和原任务；不将 extension worker 重启当浏览器重启 |

结果使用“已检查且未发现、已处理、用户保留、访问受限、未知、暂不支持”等可区分事实。配置根已处理、浏览器待完成、服务仍暂停时，原回执保留三个不同结论，并连接已有继续入口。下一步只生成对应有限预览；点击建议不自动执行。

## 大文件与多轮保全

当前源码支持单文件 256 MiB、所选合计 1 GiB、10,000 文件，仍有有限扫描预算；超限拒绝保护原件。精确选择可排除超限对象，其余限额内的完整原件沿流式路线归档与迁入。旧候选仍保留 8 MiB／32 MiB 限额，App 读取实际 runner 容量而不猜默认值。

容量发现已经与正文读取分离：在有界扫描中给出阻塞文件的相对路径、字节数、选择总量与超限原因；无权读取或超过扫描预算时明确标注未覆盖，不以空结果代替完整检查。精确选择沿用现有 work owner 与 lintel.work/1，传递有限明确原件路径集合；项目／会话只作为 App 的路径分组，不建立第二套 scope 解释器。分页摘要绑定完整 metadata 清单，正式预览另行读取全部选中原件并冻结内容摘要和落点，执行复查同一选择。文件勾选留在当前操作，未选文件变化不会扩张批准范围；不支持精确选择的旧 runner 必须明确拒绝。

大文件机制已选择兼容 `lintel.work/1` 的流式读写：显式独立分包可以收拢合计容量，却不能让一个超限 transcript 完整通过现有单文件 reader；新包格式则额外需要 reader 版本与恢复路线。现有 age Read/Write 与 serde streaming 能让原 byte-array 语义保持不变，preview 全文摘要、解密暂存、迁入读回和有限阅读仍沿同一 owner。此选择由真实 CLI 合成端到端、旧 v1、错误输入与独立进程资源测量验收；完整核验每次先展开包到私有磁盘，页面窗口不超过 256 KiB，scrypt log N reader 上限 20。实际峰值须连同主机、build、KDF 成本和文件大小读取，不能推广成 1 GiB 包的实跑证据。不能只抬高内存限额，也不能截断 session；若必须改变包格式，先明确版本边界，保留旧包 reader。分包不隐式拆坏单个 transcript，每包独立完整清单、摘要、读回与来源；中断只核对原发布路径。

重复迁移继续区分资料类别与本次用途。参考 `CLAUDE.md`、活跃指令及重名参考均保留类别和摘要；映射说明来源与目的地，不覆盖、不自动启用。skills、agents、rules、hook 源文件与其他用户资产先增加可解释的保全和用途合同，再允许完整退场处理它们。

## 完整退场配方

将来作为“清理与重建”中的独立明确配方提供，不扩张当前 `retire`。准确区分 CLI 本体卸载、配置／历史／缓存、认证、编辑器与 Desktop、浏览器、服务和 shell 的处理范围；确认每个路径或组件的 owner、共享影响及恢复能力。

安装来源按实际 npm/native/Homebrew 或其他已支持方式核验，不能只删除 PATH 中一份入口。npm 的缓存是内容寻址结构，包名通配符未命中不能证明缓存不存在；编辑器状态也可能位于共享数据库或 secrets，未核验的共享存储不得整体清空。见 [npm cache](https://docs.npmjs.com/cli/v11/commands/npm-cache/) 与 [VS Code storage 能力](https://code.visualstudio.com/api/extension-capabilities/common-capabilities)。

版本适配可以考虑官方 `claude purge PATH --dry-run`，但先冻结明确项目、版本、预览输出与保留范围；重新核对并批准后才能执行，失败或输出不识别不能当清理成功。官方 purge 处理项目本地数据，不能视为卸载或全局认证清理，见 [Claude 目录与项目清理](https://code.claude.com/docs/en/claude-directory)。

全局 shell 的隐私变量和其他工具配置默认保留；若以后支持精确修改，应按字段或可证明的语法边界处理，保留同行其他内容。服务按确切身份和状态处理，不按名称杀全部进程；各用户、Docker volumes、PM2 与 cron 的发现和操作必须有独立支持合同。执行后复查已支持回写来源，所有未知范围保留在结果中。

## 启动收尾与发行验收

新 root 与旧项目 cwd 的组合仍可能加载项目 settings、hooks、MCP 和 managed 配置。启动前显示实际选择的 root/cwd、有限候选来源、认证位置与尚未核验入口，随后另行登录和启动；归档／迁入不自动启动。候选只观察路径、存在与声明，不执行 hooks／MCP／helper；首次请求前复查私有冻结绑定，变化需新预览，原启动记录仍只查询。有限路径最多 32 个 cwd 上级、64 个 managed drop-in；settings／MCP 正文限制单个 1 MiB／合计 16 MiB，只公布声明存在和认证 selector 名字，不公布值或指令正文。未尝试旧计划缺少新私有绑定需要重新预览，旧 runner 缺少来源投影时 App 不开放新批准。上级配置的实际版本优先级、worktree 主 checkout、组织下发、目录内资产及 Terminal shell 环境保留未核验，不能把静态清单命名成实际加载结果。依据 [settings scopes 与优先级](https://code.claude.com/docs/en/settings)。

普通用户、容器、权限规则和网络代理分别解决不同范围。权限规则的文件系统绝对路径使用 `//`；工具权限规则不能证明任意子进程的文件／网络访问受 OS 限制。OS sandbox、用户边界和进程网络约束必须各自提供运行证据，见 [permissions](https://code.claude.com/docs/en/permissions)。

非开发者候选由一位没有开发环境的人，从明确版本产物开始完成 App／CLI 核对、正式持久扩展安装与配对、可逆设置、真正浏览器重启后的原 clear 完成、升级后原任务查询。Linux 支持、其他架构、native WebKit、真实认证分别验收；构建、安装、启用与正式发布保留不同状态。

## 必须能够拒绝错误行为的场景

| 场景 | 验收结果 |
| --- | --- |
| 一个大 session 与几份普通会话 | 指出阻塞对象；用户能选择完整资料并沿可核对的大文件／分批路线保全；原件不变 |
| A→B→C，指令始终作为参考；B 又有自己的活跃指令 | 两份及其重名副本均按类别、路径、字节和摘要核对；C 不自动激活旧参考 |
| 本机／B 打开 A 的原回执 | 查询、Agent 包、启动预览始终使用 A、原环境、原 ID 与绑定 runner |
| 预览后换账号、同账号文件凭据更新、Keychain fallback | 旧批准不能作用于可观察到的新认证；不可核验的来源明确限制；真实 Keychain 世代单独验收 |
| 配置根已处理、浏览器未完成、服务仍暂停 | 从原记录看见各项现状，继续正确步骤；不重做已完成副作用 |
| 新 root 加旧项目 cwd | 明确列出仍参与的项目／受管配置；“准备新 root”不能显示为全运行环境隔离成功 |
| 无开发工具的安装和升级 | 从版本产物完成旅程，升级保留 state 与原任务；不依赖源码 checkout 或猜路径 |

本方案不采用整目录通配清除、缓存包名匹配即验收、全局进程终止、“搜索不到 Claude 即完成”或绕过平台登录限制。它们不能保持现有用户资产、范围核对与原任务恢复合同。
