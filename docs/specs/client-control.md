# Lintel｜客户端控制增强 Mini Spec

日期：2026-10-16

仓库：IndelibleVivi/lintel-cc

性质：补充实施规格；以本地当前 HEAD 为施工基线，接入现有产品，不重写应用。

## 1. 产品决定

Lintel 继续围绕外发控制、旧状态清理、工作保全与环境重建发展。这轮把已有的保护方案、清理和记录做得更细、更直接：用户能控制额外记录什么、留下什么、删除什么，以及升级后保留什么设置。

交付下面四项能力及完整 App／CLI 操作链。默认用方案完成任务，高级用户可以展开原值、编辑具体设置、精确选择文件。环境检查服务于操作，不独立扩张成安全评分或观察平台。

典型旅程：选环境 → 关闭不需要的内容记录 → 保全并清理选中残留 → 执行并复查 → 继续启动使用。常规同目标任务一份完整预览、一次批准；中间的备份、修改、校验由工具完成。

## 2. 本轮交付

### A. 外发与内容记录控制

扩展现有“保护方案／外发与权限”。保留现有隐私开关，补全 OpenTelemetry 启用、日志／trace exporter、提示词／工具内容记录、原始 API body 记录、正文落盘目录等已核实控制。反馈上传、Remote Control 和 WebFetch 安全检查分别解释，并接入客户端实际提供的控制方式。

用户可以保持、开启、关闭、移除本环境覆盖、编辑值；支持批量修改和保存个人方案。既有“保持功能／减少外发／自定义”直接容纳新字段，不新增一套互相竞争的预设。

每一行呈现行为、当前设置、来源、接收端或落盘位置、主要功能影响；展开后看版本依据。对冲突定位实际来源，允许选择可写的 user／project-local 等合法位置。具体字段的允许来源、优先级、布尔语义和重启条件由规则决定。GUI 所在进程的环境变量不能当作另一个终端或 IDE 的实际启动环境。

接入现有精确代理规则及测试：允许用户从相关条目打开通道配置、测试和连接记录。配置写入、实际观察、约束范围各自呈现；完成文案按取得的结果填写。

高级编辑支持目标环境明确选中的用户可写配置文件：提供校验、精确 diff 和原任务恢复。没有专门控件的键仍可编辑，语义未知只影响解释能力；组织强制配置保留其权限边界。所有修改复用现有计划与执行链。

### B. 本地数据与身份管理

在现有清理／工作保全中加入统一清单，分类展示：

- 工作内容：会话、子代理记录、自动记忆、指令。
- 运行残留：debug 日志、工具结果、文件修改快照、图片缓存、正文落盘、配置备份。
- 身份与登录材料：已核实的持久身份字段、混合客户端状态、凭据所在位置。

以受支持版本的已知位置和用户明确指定的目录为扫描入口。显示路径、归属、大小、修改时间和可执行操作；可按环境、项目、类别、时间和大小筛选，多选后批量处理。分类不清的文件标为未分类，用户仍可定位原文件。

操作必须接通：查看／定位、复制路径、加密归档、归档后清理、精确清理、清理后重建。默认选中可清理运行残留，工作内容由用户选择是否删除；批准页明确展示保留内容。无法安全自动处理的特定项单列原因，其余独立任务仍可继续。

持久标识默认遮蔽，用户可按需显示、复制及对照。提供独立的“重置本地客户端标识”选项：对已核实的字段及明确选中的备份先保全，再移除或按该版本受支持方式重置，其他配置保持原值；注销与凭据清理独立选择。标识后续是否由客户端重新生成，依据重新检查的结果展示。对于尚无字段级适配的位置，提供现有精确文件级备份／清理／重建路径，并明确附带影响。

扩展清理必须覆盖选中的原件，不能只清顶层状态文件。运行残留及身份备份与可迁入工作内容分开分类和恢复，不自动作为工作资料导入新环境。

### C. 环境快照、对照与恢复

扩展现有 drift／baseline。保存脱敏语义快照；支持同环境前后比较及两个已登记环境比较。内容包括外发设置、配置来源、hooks／MCP／插件声明、身份同异和残留清单统计。

用户可筛选新增／修改／删除，逐项接受当前值、预览恢复，或选择一组普通配置应用到目标环境。跨环境复制显示目标 diff；登录凭据与本地身份不随普通配置方案复制。

打开环境或经 Lintel 启动时做轻量变化检查，完整扫描按需执行。默认不常驻；将来可接可选 watcher。没有变化保持安静，发现变化在当前工作区留轻量提示。

区分真实文件变化、解释规则更新和未完成读取。旧快照用于比较；恢复值来自原任务或加密备份，不能用摘要假装可恢复。恢复只改选择的字段，后续无关编辑保留，冲突具体到字段处理。

### D. 快捷配方与连续操作

预置三条可编辑配方：“减少正文记录”“清理运行残留”“保住工作并重建”。方案选项允许保存为个人默认，每次运行按当前主机和环境重新生成计划，绝不重放旧审批。已保存的个人默认若与预置不同，按实际意图显示“个人默认”名称与说明，不沿用原预置的承诺。

同目标动作先汇总为一份变更清单：改哪些字段、处理哪些文件、保留什么、是否需退出目标进程或重新启动。执行端按步骤完成，持久记录结果；中断后查询原任务，已完成的破坏性步骤不重做，整体不伪装成跨文件原子事务。

读取和编辑草案无需额外批准；常规提交一次批准。确需系统权限或外部服务交互时只在必要边界征求授权。运行中阻碍操作时指出具体目标和解决入口；能够准确归属且用户选定的服务沿用现有暂停／恢复能力。

## 3. 界面与实现落点

保留现有首页、Clawd、Day／Night 和六任务入口。增强环境详情中的“外发与权限”“本地数据与身份”“变化与对照”；当前主机、配置 root 与项目 cwd 持续可见。

主区域使用可搜索、可多选的连续列表；侧面按需展开来源、原值、差异及关系。固定底栏显示待修改和待清理数量，提供“预览并应用”。来源关系图只在需要时展开，无需独立图工作区；旧草模仅作参考，视觉以仓库现行规范为准。

复用并扩展：

- `crates/core/src/policy.rs`：内容记录规则、来源适用性、开／关／移除覆盖、功能影响。
- `startup.rs`、`components.rs`：来源观察、字段级身份适配、扩展声明与共享观察结果。
- `work.rs`、`cleanup.rs`、`archive.rs`：残留清单、精确选择、保全、字段／文件清理及恢复。
- 当前 baseline／drift、plan／approval／job／receipt：扩展快照和批量计划，不再建另一套执行器。
- `crates/egress/src/telemetry.rs`、现有 TelemetryPanel：复用目录、通道、规则测试与连接证据。
- operations／App bridge／CLI／有限 SSH runner：同步暴露新观察和新计划；机器端能力通过对应 runner 报告。

建立一个轻量版本化“观察结果＋动作描述”合同即可，不引入云端资产库或通用图数据库。规则记录字段／路径、允许来源、版本证据、读取方式和操作能力；有限读取、分页与单项错误复用既有约束。

脱敏快照不保存秘密正文。原始标识按需读取，比较使用本地受限比较材料；恢复需要的敏感内容进入加密备份。新增字段 patch 与批量操作需保持准确对象绑定、写前冲突检查和原任务恢复。

## 4. 验收

1. 外发控制：在两个隔离环境及项目配置中构造来源冲突、特殊布尔值和内容记录设置；App 与 CLI 得出一致解释，能实际修改并读回，未选设置不变。对可本地验证的 exporter 行为使用合成内容与本地接收器；未做真实客户端实验的部分单列。
2. 清理重建：合成身份字段、备份、日志、缓存、会话与记忆；一次批准完成所选保全／清理，保留项字节不变，加密归档能独立打开，身份重置不顺带注销。暂停、重开与复查按实际结果记录。
3. 比较恢复：模拟客户端更新、外部改写、不可读文件和规则升级；差异分类准确，配置应用到正确目标，字段恢复保留无关编辑。切换环境后原任务仍绑定原主机和 root。
4. 连续使用：保存个人方案，再次运行生成新计划；批量执行中断后原 ID 可查询，重试不重复删除；正常用户能在一次预览与批准后完成主要旅程。
5. 成品：真实接线 App／CLI／runner、更新帮助与现有测试；实际打开构建，验收 900×640、默认窗口和 Day／Night。原始标识／秘密不进入普通快照、支持导出及日志。交付范围中的按钮全部可用。

## 5. 开工与交付

直接按当前 HEAD 实施，先复用已完成能力，再补缺口。提交顺序建议：规则与计划合同 → 观察／清理／快照 → App／CLI 接线 → 完整旅程及文档。允许并行处理独立模块，不以只读报告、mock 页面或再次提交计划作为完成。

本轮不新增独立 IDE 常驻监听、TLS 正文捕获或系统级网络执行器；现有网络／浏览器功能继续使用。产品行为针对本地可控制的结果，不承诺改变服务端关联或封禁判断。

开发和测试使用隔离 fixture；正式账号、个人凭据、生产环境、发行和部署另行授权。最终报告已交付的用户操作、实际运行结果及确实剩余的缺口。
