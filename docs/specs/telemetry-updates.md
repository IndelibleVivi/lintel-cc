# 遥测控制与 App 更新准备

本轮给现有外发与保护方案补上精确遥测规则，并让未来签名 App 可以检查、下载、安装更新。完整产品目标仍由 [SPEC](../SPEC.md) 管理；这里的源码、合成证据与实际发行分别记录。参考讨论中的发布、系统设置和账号操作不构成本轮执行授权。

| 项目 | 验收行为 |
| --- | --- |
| T01 目录 | 静态 exact-host 目录含用途、适用客户端/provider、版本适用证据、官方来源、核对日期和附带影响；混合模型／登录／下载域名不推荐阻断。 |
| T02 组合 | 用户显式选取规则，合入现有通道 `blocked`，保留其它规则、上游与地址族；启动仍需显式操作。Claude 设置、通道配置、请求结果、实际约束分别呈现。 |
| T03 核验 | 已运行的原通道能发起有限受控请求，并得到真实规则命中；受控测试有 native origin 标记，不冒充 Claude 自身流量，也不向公网发送遥测。CLI 与 App 共用目录与代理 owner。 |
| T04 设置影响 | 细粒度减少遥测保持原有语义；说明 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` 同时关闭 Claude Code 自动更新及 feature flags，不能宣传为只关闭遥测。 |
| U01 更新检查 | App 显示自身版本、固定通道、更新状态与错误；手动检查可用，后台检查默认关闭、可选启用，离线失败不能显示为最新。未配公钥／feed 明确不可用。 |
| U02 验签与安装 | 使用官方 Tauri updater；冻结检查所得候选，明确下载、验签、安装与重启阶段。签名失败不能安装；安装／重启在 native 层排除正在执行的 App 操作与活跃代理。 |
| U03 恢复 | 安装前记录原更新意图；中断不自动重放安装。重新打开只核对原记录和当前版本；只有明确完成可显示安装成功。 |
| U04 发布准备 | 一个版本记录产生 Tauri 构建配置、updater feed 与官网首次下载资料；校验 SemVer 升序、平台、签名、字节与来源声明。DMG 与 updater archive 分开，不把二进制装入静态 Pages payload。 |
| U05 发行边界 | 只准备本地候选和 operator 流程。Apple 签名／公证与 Tauri 更新签名分别解释；先上传核验二进制，再激活 feed。旧无 updater 的 App 需手动升级一次；外部浏览器组件与远端 runner 不自动更新。 |

实现状态与证据见 [current-state](../current-state.md)。遥测操作由 [telemetry](../telemetry.md) 说明；App 与发行准备由 [app-updates](../app-updates.md) 说明。当前 `0.1.0` 源码不是新正式 Release；不生成假公钥、假签名、可用下载或已激活 feed 的声明。
