# Core and CLI

[简体中文 (canonical)](core.md) · English · [Documentation](index.en.md)

`crates/core` is the sole implementation of local environment inventory, plans, file operations, task journals and field restoration. GUI and `apps/runner` call the same `handle_request`. [SPEC (Chinese)](SPEC.md) retains the full target; this page describes current implementation only.

`jobs.rs` validates the original ID, finite status and fields needed for reconciliation. Incomplete records return `invalid_job_record` without rewriting originals. Legacy `jobs` retains complete receipts for compatibility. The App and named CLI use readonly `jobs_page` summaries and `job_detail_page` sections, each bounded to 256 KiB including the envelope. Lists sort by modification time/ID and enumerate at most 100000 files of metadata without writing an index or clearing journals; each page scans at most 100 candidates. Later pages bind the original digest and filters; changes return `stale_history`. `scan_complete` and `records_complete` distinguish end-of-scan from bad-record gaps on this page, and an empty page may still have `next_offset`. `record_errors` reports finite IDs/codes. Oversized single detail items return `detail_item_too_large`; small full receipts still open the original outcome and restoration actions. Environment discovery loads independently of history failures. I/O keeps the stable `io_error` code and adds a finite `reason`, such as `permission_denied`, `storage_full` or `read_only_filesystem`, without raw OS messages or paths. The CLI adapter retains its 20-second deadline and 64 KiB bound, with nonblocking stdout reads so an escaped descendant holding the pipe cannot block a reader join. Timeouts still require querying the original ID.

## Host-shared IPv4 / IPv6

`telemetry_catalog` returns the compiled [exact catalog](../contracts/telemetry-destinations.json) before runtime-path/state initialization and accepts only command. Named CLI/finite SSH share operations' static field contract. No plan/task/network request is created. Policy records nonessential-traffic update/feature-flag collateral; the original egress Proxy owns controlled tests. [Telemetry](telemetry.en.md) defines observation boundaries. Independent native `app_updates.rs` owns App updates outside Claude mutation plans; original update intent lives in App data. See [App updates](app-updates.en.md).

`network.rs` owns offline observation, finite-probe metadata/baselines and exact macOS IPv6 plans/approval/journal/restoration; egress probe is the sole HTTPS-byte implementation. `network_inspect`, `network_probe`, `plan_network_ipv6`, `plan_network_restore` need no environment ID; plans/receipts explicitly use `environment_id:null`, `scope:host_shared`. Generic execute admits these two supported mutation kinds without changing separate launch/resume/unknown admission. Generic plan_restore routes original network jobs correctly, never as settings restoration. Linux is readonly; synthetic homes cannot touch host networking. [Network](network.en.md) owns fields/restoration/uncertainty.

## Reads, plans and approval

`lintel request` reads one JSON object ≤1 MiB from stdin, returns one envelope and exits nonzero on errors. Other commands: `lintel --help`. Obtain environment ID, preview, then submit the exact returned hash:

```json
{"command":"plan_policy","environment_id":"00000000-0000-4000-8000-000000000001","preset":"reduce","keep_remote_control":false}
```

```json
{"command":"execute","plan_id":"00000000-0000-4000-8000-000000000002","approval":"exact-hash-returned-by-plan"}
```

Replace example IDs/hash with executor results; never mutate real data from examples. `plan_policy` freezes rule version, configuration snapshot, root identity and fields. Changed files/replaced roots/wrong approval refuse. Strict parsing refuses duplicate keys/damaged JSON rather than silently normalizing and overwriting.

Plans freeze settings.json **raw bytes** and root identity. Preconditions follow actual read/write scope: rebuild/cleanup/import without settings edits can preview/execute with damaged/duplicate-key settings, preserving bytes; policy/field restoration require full parsing. Rules are `claude-privacy-v5-2026-10-16` over 27 recognized fields: of the seven leading privacy switches, `DISABLE_TELEMETRY`, `DISABLE_ERROR_REPORTING`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` use nonempty strings, including `"0"`/`"false"`; feedback/survey/`DO_NOT_TRACK`/`DISABLE_GROWTHBOOK` parse standard booleans, with `0/false/no/off` ineffective. Every remaining OTel field keeps its own verified reading: the OTel switches and content fields parse as booleans, `OTEL_METRICS_INCLUDE_ACCOUNT_UUID` and `OTEL_METRICS_INCLUDE_SESSION_ID` are default_on (absent already means on; `0/false/no/off` excludes them), exporters use finite selectors (`none` disables exporting), while value fields such as the receiver endpoint report whether a value is configured, and `OTEL_LOG_RAW_API_BODIES` additionally reads `0`/`1`/`file:<dir>`. Recognized env keys require strings; unverified boolean forms are uncertain. One core model returns rules/scope/product evidence/impacts; GUI does not infer.

Discovery follows PATH, falling back statically to current-user `~/.local/bin/claude` only when absent from noninteractive PATH. No other-user scan/shell initialization. Versions come only from native `claude/versions/<version>` or npm package.json, without running Claude/accounts. Unknown installs/families/prereleases stay unknown. discover/inspect/plans reidentify; changed executable/version evidence before execution requires preview again. Current official docs are never treated as installed version.

`inspect` returns all 27 recognized env values, settings path/state, `effect_timing: next_launch` and `runtime_verified: false`. The masked key (`OTEL_EXPORTER_OTLP_HEADERS`) reports only `masked: true` and `value: null`; its value never reaches ordinary inspection, plan, receipt or snapshot output. Explicit `config_read` in advanced editing returns the selected file text through its private interaction channel. Work statistics read metadata only, without content/digests/archive-admission limits. Budget/unreadable gaps mark each category `complete: false` rather than failing unrelated settings inspection.

| Preset | Exact current changes |
| --- | --- |
| `preserve` | `DISABLE_ERROR_REPORTING=1`, `CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY=1`; current metrics/proactive-feedback values retained |
| `reduce` | Above plus `DISABLE_TELEMETRY=1`, `DISABLE_FEEDBACK_COMMAND=1` |
| `custom` | Per-field `custom_settings` keep/disable/enable/remove/set; missing means keep; a `set` value comes from `custom_values` |
| `keep_remote_control=true` | preserve/reduce evaluate version/Trusted Devices for telemetry coexistence; custom records intent/evaluates exact diff without overriding choices |
| `release_settings` | preserve/reduce selected conflicting fields become explicit `after:null` deletions, removed only with exact approval and individually restorable |

preserve/reduce act only on the four switches in that table plus explicit `release_settings`; every OTel field is reachable through `custom` alone and is never silently turned on or off by a preset.

Custom example:

```json
{"command":"plan_policy","environment_id":"00000000-0000-4000-8000-000000000001","preset":"custom","custom_settings":{"DISABLE_ERROR_REPORTING":"disable","DO_NOT_TRACK":"keep","OTEL_LOGS_EXPORTER":"set","CLAUDE_CODE_DISABLE_WEB_FETCH":"remove"},"custom_values":{"OTEL_LOGS_EXPORTER":"none"},"keep_remote_control":true,"trusted_devices":"not_required"}
```

`custom_settings` accepts all 27 v5 keys in `policy.rs` `catalog()` order: the seven privacy switches (`DISABLE_TELEMETRY`, `DISABLE_ERROR_REPORTING`, `DISABLE_FEEDBACK_COMMAND`, `CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY`, `DO_NOT_TRACK`, `DISABLE_GROWTHBOOK`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`) plus the OTel and remaining fields (`CLAUDE_CODE_ENABLE_TELEMETRY`, `OTEL_LOG_USER_PROMPTS`, `OTEL_LOG_ASSISTANT_RESPONSES`, `OTEL_LOG_TOOL_CONTENT`, `OTEL_LOG_TOOL_DETAILS`, `OTEL_LOG_RAW_API_BODIES`, `OTEL_LOG_MANAGED_SETTINGS`, `CLAUDE_CODE_OTEL_CONTENT_MAX_LENGTH`, `OTEL_LOGS_EXPORTER`, `OTEL_TRACES_EXPORTER`, `OTEL_METRICS_EXPORTER`, `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_EXPORTER_OTLP_HEADERS`, `OTEL_METRICS_INCLUDE_ACCOUNT_UUID`, `OTEL_METRICS_INCLUDE_SESSION_ID`, `OTEL_METRICS_INCLUDE_VERSION`, `OTEL_METRICS_INCLUDE_ENTRYPOINT`, `OTEL_METRICS_INCLUDE_REPOSITORY`, `CLAUDE_CODE_ENABLE_FEEDBACK_SURVEY_FOR_OTEL`, `CLAUDE_CODE_DISABLE_WEB_FETCH`). keep retains string bytes; disable retains already-disabled values or writes that variable's off value (DISABLE_*-style switches, i.e. the seven privacy switches and `CLAUDE_CODE_DISABLE_WEB_FETCH`, `"1"`; positive content/telemetry Boolean `"0"`; default_on `"false"`; an exporter `"none"`; any other free-value field can only be removed); enable turns a signal on (a default_on field is enabled by deleting the key, marked `restores_default: true`); remove deletes that user-settings key without promising enabled features, absent keys produce no change. Missing custom_settings means `{}`.

A `set` value travels outside the action channel as `custom_values: {"<FIELD>": "<string>"}`: it applies only to fields whose action is exactly `set`, both must appear together (a `set` without a value and a value without a `set` both refuse), and it is accepted only under `preset: "custom"`. The core validates each value against its field semantics (the content-length limit must be digits only, the receiver endpoint may not contain whitespace, each exporter accepts only its own documented selectors, raw bodies accept only `0`/`1`/`file:<dir>`) and refuses control characters or newlines. The masked key `OTEL_EXPORTER_OTLP_HEADERS` admits only keep/disable/remove: it usually carries receiver credentials, the policy editor does not accept new credential values, so this field cannot be written or replaced there and never accepts a `custom_values` entry — a violation returns `masked_setting_not_writable`. If a policy change removes or replaces an existing masked value, the Engine routes it through the same `config_edit` path: passphrase-encrypted preservation of the complete configuration precedes writing. The public diff carries no original value; selected-field restoration uses the original task. The seven privacy switches, like every other recognized field, admit all five actions (`keep`/`disable`/`enable`/`remove`/`set`); the direction of `disable`/`enable` follows the switch's DISABLE_* meaning. Empty diffs preserve bytes/permissions/existence, update drift baseline and complete with `restorable: false`. Other presets reject custom_settings; null/arrays/unknown keys/nested objects/actions refuse. Custom rejects nonempty release_settings; use remove.

Per-field behaviour, current setting, source, receiver or on-disk destination, main impact and version evidence all come from the same core rule model (`inspect.policy.rules`, carrying `category`, `semantics`, `sources`, `default_state`, `impact`, `version_floor`, `depends_on`); the GUI does not infer them. Conflict attribution lists the actual source paths and permits a writable user/project-local location, but never treats the GUI process environment as another terminal's or IDE's real launch environment. `OTEL_EXPORTER_OTLP_HEADERS` reports only `masked: true` and never reaches ordinary output; a credential-bearing `OTEL_EXPORTER_OTLP_ENDPOINT` (`user:pass@host`, `?query`, `#fragment`) is treated the same way.

Edits target registered-root `settings.json.env`. preserve/reduce do not add blanket disable; custom explicitly selects any of the 27 fields. All share diff/approval/readback/restoration. No wildcard OTel cleanup or proxy/AWS/Google/permissions/hooks/MCP edits. Private writes retain existing read permissions while removing group/other writes. Readback does not affect existing processes; UI says next launch. Project/organization/IDE/service/auth sources are incompletely discovered. Known local managed-settings prevents lower-level override.

Default state: macOS `~/Library/Application Support/Lintel`, Linux `~/.local/share/lintel`. ## Concurrency and recovery boundaries

The local operation lock serializes mutation only **within the same state directory**. Different states targeting one root rely on snapshots/rechecks, without shared exclusion. jobs/job and the new jobs_page/job_detail_page can read atomically persisted journals during execution. The new page interfaces remain readonly without reconciling or updating records; a real writer holding lock prevents interrupted classification. Without a writer, legacy job queries of nonterminal records become needs_reconciliation. Receipt ID equals plan ID; repeated execute returns original without repetition.

Durable acceptance precedes execution/verification/result. request runs foreground; submit accepts execute only, passes stdin to worker and ACKs after accepted journal persistence. Linux PID 1 systemd/euid 0 uses system transient; nonroot needs preexisting Linger=yes/current-UID user bus for user transient. Original environment travels via private same-host stdin pipe and cwd remains, preserving auth/proxy checks without values in units/argv/receipts/disk. Worker checks actual cgroup before acceptance; Restart=no, no resubmission or second launcher after manager uncertainty. Others retain setsid with explicit limits for macOS/non-systemd/ineligible users. Internal execution mode/manager/unit/continuation/limitation/reboot_survival:false persists before ACK, not caller-spoofable. Old receipts remain without invented facts. Lost connections query original, restoration separately approves. PAM/logout/reboot/VPS evidence: [current state (Chinese)](current-state.md).

Before settings atomic rename, original job settings_write persists synced staged object's identity/digest/permissions/frozen hash. After publication-before-receipt interruption, job/plan_restore under lock compares current/original/staged objects and persists settings_recovery state/reason/message. Only staged-object-matching written permits restorable; original still present is not_written, other bytes/objects/changed plan/root ownership_unproven. Neither rewrites/deletes/restores automatically. Original remains needs_reconciliation, never retrospective full success. Equal fields after outside atomic rewrite do not prove owned publication; legacy jobs get no fabricated intent.

Restore only edited fields still equal original written values; conflicts refuse, unrelated edits remain. Snapshot/recheck/atomic replacement is **not atomic compare-and-swap with uncooperative editors**; a final-check/rename race remains. [Service pause](services.en.md) proves only specific unit/hold, not all Claude/IDE/terminal/supervisor writers.

## Local data, identity, snapshots and configuration editing

These groups reuse the same plan/approval/job/receipt chain without adding a second executor. Every observation reads metadata or finite static sources only; nothing runs Claude, executes hooks or contacts public endpoints, and writes happen only inside an approved plan.

`residue_inventory` (`residue.rs`) scans local data through a finite known-location table plus up to eight caller-supplied `extra_roots`. Known locations carry `work`/`residue`/`identity`/`config` classes; version-dependent ones are `unclassified`; anything outside the table is *not covered* rather than assumed absent. Rows carry only path, category, class, size and mtime and can be filtered by `class`/`category`/`project`/time/size; `offset`+`limit` (≤200) page over one `expected_digest`, and a change returns `stale_inventory`. `complete` describes the whole observation independently of paging; depth/entry/row budgets, read failures and skipped special/unsafe entries stay explicit. Only clearable `residue` is a default clear candidate; `unclassified` requires explicit selection in the current preview, `work` requires `delete_work`, and an identity location reports presence only and is never a clear target.

`identity_inspect` (`client_data.rs`) recognizes only the verified persistent field `userID` and the account trace `oauthAccount`, returning presence/persistence by default without values. Only `reveal: true` places the raw `userID` in this response (`reveal_scope: private_response_only`); `oauthAccount` stays presence-only, and the raw value never enters a plan, job, receipt, snapshot or Agent metadata.

`snapshot_save`/`snapshot_list`/`snapshot_compare`/`env_compare` (`snapshot.rs`, `comparison_control.rs`) save sanitized semantic snapshots and compare them: egress settings, configuration sources, hook/MCP/plugin declarations, identity same/different and residue counts. Request headers, credential-bearing receivers and raw identities stay out; identity comparison material stays in private local state, comparisons expose only same/changed/unknown, and different salt domains cannot attest a change. An immediate `env_compare` shares one temporary salt and saves neither a snapshot nor a persistent salt. Missing/damaged/unreadable configuration is marked incomplete rather than "off", and hidden values stay undetermined. `snapshot_accept` accepts selected differences as the comparison baseline: it means *accept the current value*, is not a restoration source and is not one simultaneous full observation; restoring original values still needs the original task or an encrypted backup and a new approval. `drift` with `lightweight: true` reads finite configuration sources only when an environment opens or a launch happens and returns `configuration_sources_only`; there is no resident watcher, and residue/identity need an explicit full comparison. Once a semantic baseline exists, `accept_drift` refuses to overwrite it with `semantic_baseline_selection_required`; use per-item `snapshot_accept`.

`config_inspect`/`config_read`/`plan_config_edit`/`plan_config_apply`/`config_restore_inspect`/`plan_config_restore` (`config_control.rs`) edit the writable user configuration files an environment explicitly selects. `source_scope` classifies a file as `user`/`project`/`project_local`/`project_mcp`/`explicit_user_config`; managed and identity files stay read-only and refuse writes. `plan_config_edit` needs a strict JSON `document` plus the read-time `expected_digest` and computes a per-field diff; `public_change` reports an unrecognized or credential value (`masked_setting`) only as `masked: true` with `before`/`after` null, so raw text appears only through an explicit advanced edit. Execution first seals the current configuration as an age `lintel.config/1` backup (`config_archive_path`), then publishes and reads back byte-for-byte; `plan_config_restore` touches only the fields the original task changed, requires the current value to still equal the written value (else `restore_conflict`) and preserves unrelated later edits; `plan_config_apply` copies only recognized ordinary configuration and refuses to carry identity or receiver credentials across environments. `plan_client_workflow` composes configuration edits, residue clearing and identity reset into one `client_workflow` plan with one approval and one original job; a file cannot belong to two steps (`overlapping_actions`), each step completes or is skipped independently, and an interruption is queried by the original ID only.

`plan_cleanup`'s `clear_residue` recipe and the standalone `plan_identity_reset` each act on exactly the selected originals: `clear_residue` needs a non-empty `residue_paths`, optionally writes an independent `lintel.residue/1` encrypted backup before deleting, rechecks each file's identity and lets one file's failure skip only that file; `identity_reset` removes only the verified `userID` (plus explicit `identity_backup_paths`), preserving it in an encrypted backup first, keeping every other key value-by-value and **never logging out or clearing credentials**. `residue_archive_inspect`/`plan_residue_restore` are the finite read/restore entries for those backups: `lintel.residue/1` is separate from the work package, restores only the original paths recorded in the package, refuses to overwrite an existing file (`restore_conflict`), and is not a work import.
