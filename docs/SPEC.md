## 0. 已确认、提议与当前材料

### 0.1 已由作者明确的目标

- 面向 macOS 与 Linux VPS；Windows 不在目标中，没有实机就不宣布支持。
- 核心是 Anthropic/Claude 相关遥测与探针顾虑、机器和浏览器的环境暴露、账号问题或封禁后的本地清理重置，而非磁盘清洁。
- 必须实际好用，能完整完成任务；不能只做扫描、风险解释和若干设置跳转。
- Better UI 是产品要求，不是完成脚本后再加的皮肤。
- 独立设计与实现，不以复制第三方应用代码为起点。

### 0.2 本规格提出、尚非作者最终拍板的决定

采用“环境”作为操作对象；采用预设方案与任务配方；采用 Mac GUI＋浏览器伴随扩展＋独立 Rust runner；以 Tauri 2 作为桌面实现首选；将高权限网络约束做成可选安装但有完整规格的模块。具体品牌、许可证、签名账号投入和视觉候选仍可调整，不需要为了这些选择停下其余实现。

### 0.3 当前检查过的材料

本次读取了 Soundings 的 Shape/Search 方法及当前对话，检查了官方配置、认证、网络、浏览器扩展和平台机制资料。能访问的第三方应用材料只有两张截图；未收到 ZIP 或 `.app`，未分析其二进制、授权机制、依赖、真实清理逻辑或网络行为。截图证明它展示了哪些按钮，不能证明那些按钮的效果、安全性或技术栈。

## 1. 用户为什么安装它

### 1.1 首要用户与购买替代理由

**普通 Claude 用户。** 知道自己不想交出额外信息，但不想研究环境变量、浏览器存储、权限和代理规则。安装之后选择一个明确方案，工具负责定位、修改、复验与恢复。

**账号出问题的人。** 不确定哪些本地登录、状态文件和浏览器站点数据需要处理，也不愿把自己的会话、指令、记忆和项目一起删掉。工具将“清除旧使用状态”和“保留工作成果”分开完成。

**Mac＋VPS 的 Claude Code 用户。** 不想分别摸清终端、后台服务、IDE 的配置来源，更不想因维护切断自己的 SSH 或停止另一台机器上的工作。工具在同一界面操作不同目标，但状态和凭据留在所属机器。

### 1.2 对比替代方案的具体价值

| 用户现有办法 | 本工具必须提供的增量 |
|---|---|
| 复制一段关闭遥测的命令 | 找到实际启动入口，设置持久生效，识别例外与功能影响，更新后检查是否漂移 |
| 手动删 `.claude`、Cookie | 定向清理完整目标范围，展示会退出哪些登录，保留与迁出工作内容，并检查旧状态是否回写 |
| 通用浏览器隐私扩展 | 同时处理 CLI、桌面入口、配置根、远程服务与清理生命周期 |
| 通用防火墙 | 将可验证的产品规则、进程/环境身份、官方设置和浏览器站点权限连起来，而非让用户判每个域名 |
| Provider 管理器 | 以外发控制与状态重建为主，而不是多模型切换、额度与协议转换 |
| 群内“防封套餐” | 每个动作有具体作用、明确范围、可检查结果；不靠神秘评分或“机器已洗白”的文案 |

CC Switch 与 LuLu 已经覆盖配置管理和通用出站控制的部分能力；它们不是本工具不存在的假想对手。[S18][S19] 本工具需要赢在完整工作流程，而不是工具数量更多。

### 1.3 成功时的体验

第一次使用无需登录本工具、购买卡密或输入模型 API key。用户看见已识别的使用环境，选一个目标和方案，只确认实际变化；完成后能直接打开受控环境继续使用。账号出问题时，同一个工具能清掉目标的旧状态、保留选中的工作内容，并准备好下一次正规的登录与启动。

**重复使用的理由**是配置漂移、软件升级、环境变化、浏览器权限恢复、远端维护以及重置后的残留检查，而不是每天制造“你有 37 项隐患”的焦虑。

## 2. 核心产品判断

### 2.1 “防封”是用户动机，功能结果必须更具体

用户因遥测、探针、环境关联和封号风险而来。界面可以直接承接这些场景，不应改名成磁盘维护。但工具只能对本机可控制、可验证的事情给出完成结果：关闭指定可选外发、约束受控连接、调整指定浏览器设置、移除旧本地状态、建立独立数据目录。

服务端是否封禁、采用什么判断组合、是否认定为同一主体，不作为本工具可测量的状态。尤其不能把“本地环境已重建”写成“服务端已解除关联”。这条区别应体现在结果字段与测试里，而不是每次弹出长免责声明。

### 2.2 不能把所有流量统称为遥测

当前官方网络资料列明 `api.anthropic.com` 同时承载模型请求及部分其他请求。只按域名阻断无法细分同一 TLS 通道内的用途。[S02] 本规格因此采用：**产品原生控制优先、浏览器原生能力配合、受控网络通道补强、实际观察校验**。

“不做 TLS 解密”意味着默认不读取路径、请求正文和令牌；也意味着不能声称从 CONNECT 域名识别出了其中每条请求的用途。

### 2.3 更强不是把所有开关关掉

减少外发与保留功能需要可组合方案。系统定位、WebRTC、自动更新、域名安全预检查各有不同含义；不能在同一“推荐全选”中默认一起关闭。未知网络目的地也不自动等于恶意探针。

### 2.4 轻松操作来自预先做完判断

默认不让用户面对几十条变量和路径。由规则引擎产生完整方案，用户只需决定有真实代价的差异：例如是否依赖 Remote Control、是否保留当前登录、是否暂停正在运行的目标。完整路径的普遍情况应当一份预览、一次授权、一次执行，不为每个文件再询问。

### 2.5 独立目录不是安全沙箱

本地状态分离用于减少误用、旧状态混入和配置互相覆盖，不限制同一用户进程读取其他文件，也不保证平台无法关联账户。更强的进程网络约束是另一项能力；文件系统沙箱不是被一个 `CLAUDE_CONFIG_DIR` 自动实现的。

### 2.6 保留内容不等于恢复整个旧目录

默认保留原始工作内容，但迁入新环境时只迁移用户选择的类别。原始归档、可继续使用的工作数据、可执行配置、凭据必须分层，否则“备份恢复”会把旧问题原样带回。

## 3. 整版范围与支持矩阵

### 3.1 完整交付由什么组成

**标准安装：** Mac GUI、共享执行核心、Linux CLI/TUI、浏览器配对入口、内置规则、方案预览、实际配置变更、状态清理、迁入、恢复、结果导出、更新后复查。

**用户按需启用：** Chrome/Edge/Firefox 伴随扩展；受控出站通道；后台漂移检查；高权限网络约束。按需启用不等于只写“未来支持”：对应模块要么有可安装、可验证的实现，要么明确标为未交付，不能拿整版完成的名义藏掉。

**不需要：** 新的产品账号、云端个人数据库、LLM 调用、常驻浏览器自动化框架、远端公网管理端口、默认 root 或全磁盘访问。

### 3.2 平台矩阵

| 表面 | 整版要求 | 不宣称的能力 |
|---|---|---|
| macOS Apple Silicon | GUI、CLI、CC 环境管理、浏览器能力、远程 VPS、恢复 | 未经测试的系统版本全覆盖 |
| macOS Intel | 同源可构建；取得实际环境并验收后列入支持 | 交叉编译即实机支持 |
| Linux x86_64 VPS | 无 GUI 依赖的 runner、CLI/TUI、配置/清理/重建、SSH 任务、服务适配 | 需要安装 WebKitGTK 或桌面环境 |
| Linux arm64 | 独立构建与测试；实机覆盖单列 | 仅构建通过就宣布支持 |
| Windows | 不实现、不测试、不显示功能入口 | 复用名称即支持 |
| Claude Code 终端 | 主支持对象 | 任意未来版本自动兼容 |
| IDE 包装的 Claude Code | 识别实际二进制/配置来源；对适配版本完成同类任务 | 只改 shell 就证明 IDE 已生效 |
| Claude Desktop | 独立适配安装与数据状态、权限建议、目标暂停与重建 | 把 CLI 的变量或 Desktop 3P 文档无条件套给消费版 |
| 云端 Cowork/云会话 | 标明执行地点与本工具不可直接控制的范围 | Mac 本地清理会删除云端任务与数据 |

Linux 首批正式验证目标建议为 Ubuntu 24.04 与 Debian 12/13 中实际取得的环境，记录发行版、内核、systemd、libc 与架构。兼容是能力协商结果，不依赖一串操作系统名称。

### 3.3 浏览器支持

**Chrome 与 Edge：整版的一等公民。** 伴随扩展真实执行站点数据清理、可控制的站点权限、WebRTC 策略、规则和受控代理设置；每个浏览器分别安装、配对与实测，不能以 Chromium 血缘代替兼容验收。

**Firefox：独立适配，而不是改 manifest 名字。** 必须覆盖指定站点的数据清理、WebRTC 设置、配对和恢复；容器 store 与缓存清理使用各自能力边界。[S11][S12]

**Safari：兼容入口，不列入“完整自动化支持”。** 可以识别并给出原生管理入口；不能以 `WKWebsiteDataStore` 清掉本工具自己的 WebView 后，宣称清掉 Safari 主浏览器数据。Safari 深度适配需要独立研究与验收，不能阻塞已经明确的三种浏览器整版交付。

### 3.4 不扩张的产品方向

不做通用磁盘/内存优化、驱动清理、批量注册或账号交易、硬件身份伪造、验证码绕过、平台风控模拟器、VPN 节点售卖、自动换身份/出口，也不把服务器端账号解封当本地清理结果。模型切换、MCP 市场、完整 harness 和多平台聊天 UI 不进入本项目。

## 4. 领域对象：Environment，而不是一台机器一套设置

一个 Environment 包含：

- 所属 host 与用户身份；本地或远程。
- surface：browser / claude-code / desktop / ide-wrapper / service。
- 实际 executable 与已观察版本、启动入口。
- config root、credential scope、工作目录及启动配置。
- browser 实例、profile 或独立 user-data-dir；配对的扩展实例。
- 绑定的保护方案、规则版本、最近检查与验证范围。
- 归属关系：自行管理、外部工具管理、组织管理、仅发现。

用户界面使用“这台 Mac / Claude 专用浏览器”“VPS / 写作服务”等可改名标签；内部 ID 随机生成，不以邮箱、IP、机器序列号作为主键。

**同一 root 或共享凭据是关联事实，不强行复制成独立对象。** 重置其中一个 Environment 时，必须枚举会受影响的其他对象。最新官方认证说明也有配置根隔离的例外：某类不创建 API key 的 Console 登录存储在配置目录外。[S03]

## 5. 四条必须完整完成的用户旅程

### 5.1 初次安装 → 减少外发 → 继续使用

用户打开工具；本地轻量发现显示 CC 和浏览器环境。选择目标后，推荐“减少外发”方案；若检测到用户可能依赖有冲突的功能，只问是否保留该功能。预览说明会改哪些设置、作用于哪个入口、是否需要新启动。

用户确认；工具对准确来源写入变更，读回、检查冲突，并完成可自动化的验证。已有会话不被无声杀掉。最后提供“在此环境打开 Claude”或“安排目标重启”，而不是止步于“建议打开终端”。

### 5.2 账号异常/封禁 → 清理旧状态 → 保住内容 → 重建

用户进入“清理与重建”，选择受影响目标。工具先区分登录失效、代理故障、服务错误和用户已确认的封禁；没有确凿证据不把一个 403 判为封号，更不靠反复重试账号做诊断。

用户选择“保留工作内容，重建本地使用状态”。工具定位当前与共享凭据范围、后台实例、浏览器站点数据、配置来源、工作内容；生成明确计划。先冻结目标写入，再归档内容、移除选定状态、建立新环境；只把批准的类别迁入。

结束时显示本地清理是否完成、远端注销是否确认、哪些内容已归档、哪些需要重新登录。执行失败不抹去已完成步骤。新的登录始终使用正常官方流程；本工具不接收账户密码。

### 5.3 Mac 管理 VPS → SSH 中断 → 继续查询原任务

用户选择现有 SSH alias；确认首次主机身份后检查 runner。远程操作与本地用同一套页面，但每个对象持续显示所属主机。用户针对某一服务做变更，其他服务与 SSH 不受影响。

提交成功的任务取得 durable job ID。网络断开时显示“连接中断，远端任务状态待确认”；重连查询同一个 job。不能把“没收到 ACK”自动变成重新清理。

无 Mac 时，用户用同一 runner 的 CLI/TUI 查看、执行和恢复。Linux 上没有浏览器时，这些页面自然不存在。

### 5.4 日常保持 → 发现漂移 → 一键修复或接受新值

用户自愿启用本地漂移检查。升级 CC、其他管理器改配置、扩展被禁用或启动入口变更后，工具显示具体差异；提供“恢复我的方案”“接受当前值”“仅此环境忽略”。

自动修复只可用于用户预先授权且本工具拥有的低风险设置，不能后台注销、删历史、改外部代理、重启服务或关闭系统权限。它必须像一个省心的维护工具，而不是一个不断替用户夺回控制权的配置警察。

## 6. 信息架构与完整 UI

### 6.1 主体布局

桌面默认 1120×760，最低可用 900×640。左栏 200–224 px；顶部持续显示目标主机、当前环境与连接状态；主体以连续列表和分组表面为主，而不是满屏大卡片。

主导航仅四项：**环境、保护方案、清理与重建、记录与恢复**。设置与帮助在底部。环境详情的页内标签为“概况 / 外发与权限 / 本地状态 / 启动与来源”。网络连接观察是可展开的详情，不强制每个人阅读一幅拓扑图。

### 6.2 首页不是告警仪表盘

首屏的主问题是“你想处理哪个使用环境”。环境行显示名称、平台/入口、最近实际检查时间和最重要的一项变化；不显示综合安全分、封号概率、无意义计数，也不以橙红色填充未知项。

未安装工具时给出“添加现有环境”“建立专用环境”；不擅自下载安装 Claude。没有远程主机时不展示空的服务器控制中心。

### 6.3 保护方案编辑

先呈现用户能理解的结果：减少产品指标、关闭错误回报、保留或关闭反馈、浏览器权限范围、启动路径。每组显示功能影响和当前状态；展开才出现变量、文件来源、规则版本。

默认控件修改草案，不立即落盘；底部固定变更条显示“将修改 3 项 · 仅当前环境”。一次确认应用组合。个别可逆低影响动作可提供“立即应用”，但行为必须一致。

### 6.4 清理页面：以数据类别表达影响

必须并排显示“将处理”和“将保留”。不是把保留内容藏在长说明里。目标名称在危险动作按钮旁仍可见。

选择清理强度后，工具自动填好范围：修复登录、重置客户端、退役旧环境。用户只修改例外。邮箱站点、第三方身份提供商以及其他不直接属于目标的登录数据默认不选。

### 6.5 结果与恢复

执行预览在同一表面逐步转成实际结果：已完成、等待重启、范围受限、需继续处理、已保留。显示具体对象名和目标，不重复“发现的全局状态文件”。

“恢复配置”“查看工作归档”“继续重新登录”“检查是否回写”是独立动作。不能给不可撤销的注销或 Cookie 删除一个虚假的“撤销全部”。

### 6.6 视觉语法

这是桌面工具，不是企业防火墙控制台，也不是 Claude 仿官方皮肤。候选方向为浅冷灰/纸白底、深石墨文本、小面积冷青状态强调；危险色只用于真实的不可逆动作。具体配色是候选，不视为作者已接受。

以系统字体为主，正文 13–14 px，重要说明 14–15 px，页面标题 22–26 px；路径使用等宽字体并支持中部省略与完整复制。使用一套统一、授权清楚的矢量图标；仅为环境、路由、清理与恢复设计少量专有图形。首屏不需要巨大盾牌、拟物垃圾桶、拟终端粒子背景或装饰性流量地图。

动效负责解释变化：120–180 ms 的状态过渡、差异高亮、展开/收起；不让连接动画假装实时抓包。深浅主题、键盘焦点、屏幕阅读器、减少动画、状态不只靠颜色表达，均为整版要求。

### 6.8 日常使用的短路径

配对完成后，菜单栏提供“打开常用环境”“检查变化”“暂停本工具规则”和“最近一次任务”；用户不必每次进入设置编辑器。打开常用环境只复验与启动所必需的状态，不重新做全量扫描；规则或凭据范围已变化时才回到主界面说明。

切换导航不会丢掉目标；切换目标时，未提交的方案作为该目标的草案保存，不把它偷偷应用到新目标。详情用侧面板展开，关闭后回到原列表位置。键盘可完成目标选择、差异浏览与任务确认；破坏性按钮不能成为对话框默认回车动作。

多个目标使用同一保护方案时，先显示各自的实际差异，再一次授权提交独立任务。共享凭据或同一文件的重叠动作先合并；跨主机不是原子事务。某台 VPS 暂时离线，不阻止 Mac 完成已经独立获批的部分，任务总览保留各自结果。

## 7. 模块 A：发现、来源解释与环境登记

### 7.1 有限发现

默认只读当前用户常见安装元数据、明确的配置目录与用户选择的服务/工作区；不全盘递归，不读取整个 shell 环境，不扫描所有 Keychain 项，不读取浏览器 Cookie 值，也不检索会话内容来猜账号。

发现分两段：先返回可用环境，再按用户展开补充。大历史目录仅统计必要元数据，不要求为了显示 3 行摘要解码全部记录。用户可以直接添加路径和 SSH 目标。

### 7.2 来源链

对相关配置记录发现来源、优先级规则、最终推导值、运行时观察及生效时机。不同键有不同优先关系，禁止通用“shell 总是最高”的算法。[S04][S05]

支持 user/project/local settings、明确的 shell 配置、launch agent/service drop-in、已登记启动器。复杂脚本只做静态定位；“扫描配置”不能执行 shell 初始化文件、`apiKeyHelper`、项目 hooks 或 MCP 服务。

无法自动分析的来源不是一整项功能失败：可提供本工具拥有的启动配置，让新启动获得清楚的范围；但若更高层组织策略会覆盖它，就明确显示该限制。

### 7.3 配置写入

优先写入准确的产品级来源或本工具拥有的启动器，不往全局 shell 文件散落一串 export。必须更新已有 JSON 的指定字段，保留无关字段、文本内容和权限；已损坏或格式不支持的文件不整份覆盖。

对组织管理设置只解释，不通过更低层隐藏覆盖。对外部配置管理器拥有的文件先检测冲突，采用显式交接或局部受支持修改。

## 8. 模块 B：能实际应用的保护方案

### 8.1 内置方案

| 方案 | 意图 | 默认行为 |
|---|---|---|
| 保持功能 | 保留当前主要功能，处理有明确低代价的额外外发 | 基于实际功能使用情况产生方案，不保证零遥测 |
| 减少外发 | 用户主动减少产品指标、错误回报、反馈/调查 | 采用独立官方控制，展示 feature-flag 等依赖，更新能力默认保留 |
| 受控连接 | 在上面基础上限定由本工具启动的已支持网络路径 | 增加代理/浏览器规则与验证；启用系统强约束需要额外模块 |
| 自定义 | 有明确偏好的进阶用户 | 只覆盖选择的键；每项可见来源、影响与恢复方式 |

推荐项由检测结果决定，不能假定每个人都不使用 Remote Control，也不能因为某功能依赖 feature flags 就悄悄保留全部遥测。冲突由用户作一次有意义的选择。

### 8.2 首批 Claude Code 控制目录

需要逐版本验证并落到实际动作的项目包括：`DISABLE_TELEMETRY`、`DISABLE_ERROR_REPORTING`、`DISABLE_FEEDBACK_COMMAND`、`CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY`、`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`。总开关不是默认替代所有独立项；其作用范围、版本与功能影响必须随规则保存。[S01]

`skipWebFetchPreflight`、官方 marketplace 的自动安装与更新行为各自列项，不把它们当作总开关已处理。WebFetch 安全检查不自动关闭：用户明确选择时才应用，并解释失去的是哪项检查。安全软件、TLS 校验、浏览器反钓鱼能力不作为隐私套餐默认关闭对象。

### 8.3 产品遥测与自设 OTel 分开

用户自己的 OTel collector、日志管道和诊断系统可能服务于其工作需求。检测到相关设置时显示目的地来源与类别，不用 `OTEL_*` 通配删除。官方产品指标、主动反馈、用户自配监控和模型业务请求分开标记。[S26]

### 8.4 账户侧隐私设置

提供准确的官方账户隐私入口与状态记录；除非存在已验证的官方接口，不伪造自动修改。它不阻塞本机可完成动作。用户手动确认只记为“用户确认”，不记为本工具机器验证。

不能以账号训练偏好替代 CLI 外发控制，也不能因为本地关闭指标就宣称改变了云端数据保留政策。

### 8.5 启动后验证

每条设置记录 `effect_timing`：即时、下一次产品设置应用、下一次新启动、需浏览器/服务重启、未知。读回配置后，按适配器执行对应复验。当前文档显示 settings 中的 env 与 shell 修改并非相同的热更新语义，不能统一假设。[S05]

### 8.6 确切的默认值，而不只是方案名字

下表是首批方案的**设计默认**；只有在 adapter 验证支持的版本与认证方式中才生成写入动作。`保持`指不改变当前值，不能把它转换为删除或赋值 `0`。已有用户总开关若产生冲突，要在同一预览中处理，不能悄悄移除用户更严格的选择。

| 项目 | 保持功能 | 减少外发 | 受控连接 |
|---|---|---|---|
| `DISABLE_ERROR_REPORTING` | `1` | `1` | `1` |
| `DISABLE_TELEMETRY` | 保持；明确未承诺关闭指标 | `1` | `1`，除非用户选择保留冲突功能 |
| `DISABLE_FEEDBACK_COMMAND` | 保持，用户主动反馈可用 | `1` | `1` |
| `CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY` | `1` | `1` | `1` |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` | 不新增 | 不新增；以独立项表达范围 | 可选更广方案，不作为网络约束证明 |
| `skipWebFetchPreflight` | 保持 | 保持 | 保持；不默认关闭安全检查 |
| `CLAUDE_CODE_DISABLE_OFFICIAL_MARKETPLACE_AUTOINSTALL` | 保持 | 独立可选 `1` | 独立可选 `1` |
| 官方程序更新 | 保持 | 保持 | 保留所需更新路径或明确改为手动更新 |
| 用户 OTel、通用代理、云凭据 | 保持 | 保持 | 仅修改已获批的目标路由，其他保持 |

四个独立控制的机制和依赖来自官方说明；上表如何组合是本工具的产品选择。[S01][S05] “保持功能”不是全功能永不变化的保证：例如它不再展示质量调查，但不主动关闭指标/feature flags。选择保留 Remote Control 时，结果应明确“保留相关指标/feature-flag 通道”，不能继续沿用“指标已关闭”的标签。

浏览器方案独立组合：定位默认保留浏览器询问机制，用户选择“阻止此站点定位”后才针对站点写入；摄像头和麦克风不随遥测方案全关。选择“受控连接”时才建议该专用 profile 使用非代理 UDP 限制，并在有通话需求时显示影响。普通个人 profile 不自动变成专用 profile。

### 8.7 从“配好了”到“确实用上了”

应用方案的完成页提供受控启动入口，并能保存为菜单栏快捷动作或用户可见的终端入口。用户仍可使用原来的启动方式；工具区分“本工具启动并确认过”与“只发现、未确认”的实例。由 IDE 或服务启动时，适配器写入真正有效的来源，必要时安排该目标重启，不要求用户永远记得从我们的窗口打开。

日常快速复验只报告与上次方案有关的变化。未发生变化时给用户一个可以直接继续工作的状态，不重新要求一遍授权。

## 9. 模块 C：浏览器能力必须真实可操作

### 9.1 伴随扩展是一等组成，不是以后再说

Mac 应用负责计划与解释；扩展使用浏览器原生 API 执行目标 profile 内的操作。扩展也有独立小面板，可以查看本 profile 的状态、暂停规则和打开主应用。

配对通过 Native Messaging，浏览器发起通道。每个扩展安装实例有独立随机 ID 和配对凭据；应用用挑战及用户可见的短码确认实例，不只看扩展 ID。一个扩展 ID 可以出现在多个 profile，不能因此合并目标。[S10]

### 9.2 站点数据清理

内置“Claude 使用站点集”，按登录类型生成明确列表；登录域、应用域、账户管理域各有来源。邮件服务、Google/Apple 等身份提供商不被默认一并清理；用户可以单独加入并看见其退出其他业务的影响。

执行数据类型至少包含适用浏览器支持的 Cookie、localStorage、IndexedDB、service worker、Cache Storage；HTTP cache 另列。按浏览器区分 host/origin/registrable-domain/cookie-store 的真实边界。[S07][S11]

Chrome 的 Cookie 清理可能扩大到完整可注册域；Firefox 的 `removeCache` 不能被假装成站点级缓存删除。[S07][S12] 不可定向的类别提供明确的“整个当前 profile 缓存”可选动作，默认保留；不能因某 API 忽略过滤参数而悄悄清掉整个浏览器。

清理时冻结目标站点的新加载，关闭或隔离相关标签，处理 service worker 回写风险；没有必要关闭所有浏览器。执行后先做不重访目标站点的本地复验，再单独让用户重新访问。重新访问自然生成的新 Cookie 不能被误判为上次没删掉。

### 9.3 清理的验证等级

扩展 API 成功回调是“浏览器确认执行”；有额外列举能力的类型再做只读复查。浏览器不提供列举的存储，不能伪造“零条残留”的数字。

验收使用预种植的合成站点数据验证实际删除与邻域保留，而非只 mock 一个成功 Promise。用户真实页面中的存储值不出扩展进程；主应用接收类别、范围、执行结果，不接收 token 值。

### 9.4 WebRTC 与站点权限

WebRTC 提供按 profile 生效的原生策略，显示通话/媒体能力影响；不能把 `disable_non_proxied_udp` 翻译成“全设备无 IP 泄漏”。Chrome 有对应官方 API。[S08]

定位、摄像头、麦克风、通知等按照浏览器支持范围和站点粒度处理；不把它们默认改成全浏览器永久拒绝。权限控制返回值、实际有效值、控制来源三者一起检查。[S09][S13]

### 9.5 专用浏览器环境

用已安装、正常更新的浏览器建立独立 user-data-dir/profile，首次不复制个人 Cookie、密码、扩展或同步账号；用户主动选择以后再加入。工具创建方便的启动入口，复用时保持同一环境。

优先使用公开的启动机制，不直接编辑浏览器私有数据库；不附赠一份滞后的 Chromium。[S14] 浏览器单实例/进程复用必须实测，确保命令没有被已有个人浏览器窗口接管。

### 9.6 指纹与“环境一致性”

可本地展示语言、时区、浏览器版本及权限状态；它们用于解释当前暴露面。没有跨用户统计样本，不计算“唯一率”。不自动将系统时区改成代理出口所在地区，不生成随机 UA/Canvas/字体，不通过环境伪装营造安全结论。

有意减少暴露时，优先使用浏览器已有隐私能力和专用使用边界。当前 IP、ASN 或地理信息若需要查询，必须属于用户主动发起的网络诊断，不是启动后台请求。


### 9.7 扩展权限与控制权

| 能力 | 需要的权限/桥接范围 | 约束 |
|---|---|---|
| 站点数据清理 | `browsingData`，按浏览器验证的过滤参数 | 此 API 的能力可能比页面授权更广；executor 仍须自己校验已获批 profile、站点集、类别 |
| WebRTC 策略 | `privacy` | 显示 profile 级范围，检查其他扩展/组织策略控制权 |
| 站点权限 | 对应浏览器支持的 content settings/permissions API | 精确站点规则；不以缺少某 API 换成全局系统操作 |
| 与 Mac 配对 | `nativeMessaging`＋本地 host manifest | 精确扩展 ID＋独立安装实例配对；网页不能调用系统动作 |
| 网络规则/代理 | 按浏览器需要的 DNR、host、proxy 权限 | 用户启用此能力才申请可选权限；不给默认全网通配访问 |
| 目标标签识别与暂停 | 对已批准站点的必要 tab 元数据 | 只处理目标标签；不记录完整浏览历史，不读取页面正文 |
| Cookie 数量复查 | 必要时可选 `cookies` 与准确 host 权限 | 不取值回传；没有此权限仍可报告原生清理结果而非零残留 |

Host permissions 不是对所有浏览器高权限 API 的自动沙箱，必须有独立的 action 授权检查。未经用户启用，不申请 `debugger`、常驻全站 content script 或远程代码执行能力。

配对秘密仅保存在安装实例的本地存储，不能通过 browser sync 跨 profile 同步。复制 profile 导致实例身份重复时，标记冲突并重新配对；不把两个窗口当成一个可信目标。Native Messaging 采用有界小消息与关联 ID，工作归档不通过桥接传输，敏感页面值不进入 GUI。

## 10. 模块 D：网络解释、观察与真正的约束

### 10.1 两种模式，不能混标

**受控通道模式：** 用户无须安装内核级组件。由本工具启动的已适配 CC/浏览器使用独立的本地 CONNECT 代理与产品设置，观察并约束通过该通道的目的地。未经过它的流量不在覆盖范围，不能据此宣称进程绝不直连。

**强约束模式：** 安装平台专用组件后，额外限制目标进程/服务的直接出站。它须通过逃逸负例验证，才显示“目标直接出站受限制”。仅设置 `HTTPS_PROXY` 不算强约束。

用户不装高权限组件时，仍拥有完整的配置、防护、浏览器、重置和迁入功能；不能用灰色锁把普通功能绑在它上面。

### 10.2 本地出站通道

Rust runner 提供 HTTP CONNECT/适用的普通 HTTP 转发，绑定 loopback 或明确的私有 namespace 接口，不监听公网。按环境使用独立实例或有强身份绑定的通道。默认不解密 TLS、不装根证书、不保存请求正文或 Authorization。

支持把上游指向用户已有 HTTP/HTTPS proxy；SOCKS 上游由明确的转换适配器完成，而不是直接把 SOCKS URL 写给不支持的 Claude Code。[S02] 复杂的机场订阅、节点选择和协议实现不归本工具。

规则按用途和来源分类：必要业务、认证、更新、可选外发、用户服务、未知。相同域名用途混合时，优先依赖产品原生开关，不能以域名黑名单替代。

### 10.3 浏览器网络

使用原生 proxy 与 declarative request rules，按 profile/站点/规则的真实作用范围展示。[S15][S16] 不假定浏览器代理会自动约束 WebRTC、DNS、QUIC 或所有后台流量。

规则暂停有期限；暂停期间显示真实状态，期限到了再恢复本工具自己的规则，不改其他扩展。通话失败等功能问题可以定位到具体变更并单独撤回。

### 10.4 强约束的 Mac 实现

使用 Apple 支持的 Network Extension content filter 与最小权限的配置服务；签名、provisioning 与用户批准列为发行依赖。[S17]

按可验证的进程身份/应用范围建立约束，只允许本工具 proxy 及用户批准的具体本地服务。域名不可识别时不得用共享 CDN IP 推断为特定遥测。进程审计身份、浏览器 helper 归属和重启后的身份必须实测。

若某浏览器只能可靠识别到整个应用而不是其中一个 profile，就让用户明确选择应用级范围；禁止为了完成一个 profile 的动作，静默封住整个 Chrome 或 Terminal。覆盖能力不够时不显示强约束已开启，仍保留受控通道模式。

### 10.5 强约束的 Linux 实现

为受控启动的目标服务建立独立 network namespace，并用最小 privileged helper 配置仅通向本地代理的路径及必要的精确例外；systemd 适配使用受支持机制。[S21] 不修改宿主机默认路由或清空现有防火墙。

同时测试 IPv4、IPv6、UDP、DNS、子进程直连、继承 socket 和权限逃逸。目标不继承网络管理能力。已有服务需通过明确的重启/迁入启用，不能把正在运行的 arbitrary PID 当作已被迁入 namespace。

无权限或无 kernel capability 时返回具体限制，不把 `PrivateNetwork` 等配置存在当成执行成功。

### 10.6 观察输出

记录时间窗、目标身份、目的地主机/端口、通道、规则决定、少量字节计数与 provenance；不记录模型对话、完整 URL query 或 Cookie。HTTPS 不可见部分标注“加密内容不可分类”。

至少有一个允许的合成探针和一个应被拒绝的合成探针作为观测链正负对照。只说“60 秒内没有观察到某类连接”，不把沉默本身升级成“该流量不存在”。

### 10.7 DNS、出口与 WebRTC 诊断

本地配置检查默认离线。查询公共出口、DNS 路径或 STUN 都需要用户主动运行，并显示会联系哪些服务。可以使用项目自建的最小诊断端点或用户指定端点，但服务不应成为产品激活依赖。

DNS 加密与出口约束是不同结果；不能把关闭 53 端口当作所有 DNS 都走代理。没有 authoritative DNS 观察条件就只显示配置，不显示“DNS 泄漏测试通过”。普通 HTTP 回显证明的是该目标请求的出口，不能替代实际 CC/浏览器的目的地路由证明。


### 10.8 规则不应把正常工作变成逐请求审批

普通受控通道默认保留业务所需流量，阻断规则只采用已验证、用途足够明确的可选目的地；无法区分的混合域名靠产品设置处理。用户选择更严格的允许列表模式后，未知目的地才按该模式拒绝，并集中呈现可批准的域名与调用目标，不每次连接弹窗。

认证、更新、MCP、插件下载、浏览器内容资源与用户开发命令具有不同生命周期。按实际启用的功能生成依赖集合；需要新增目的地时，让用户选择一次性、当前会话或持续允许。例外有清楚的作用域和期限，不允许一个 `*` 以隐藏方式降级全部约束。[S02]

强约束模式的通道故障采用 **fail-closed，仅对已选目标生效**：代理不可用时停止该目标的受控请求，不自动转为直连。用户可以显式解除约束继续工作，但状态立即变成“约束已暂停”。断开 GUI、休眠、runner 更新和系统组件故障各有独立恢复测试；不能为了恢复 Claude 而切断 SSH 或接管整台主机的网络。

安装强约束组件前生成独立于 GUI 的本地恢复入口，能够撤销本工具拥有的规则。卸载按顺序撤销规则、停组件、恢复仍归本工具拥有的代理值，再清理配对；不留下一个指向不存在 localhost 端口的浏览器或服务。

## 11. 模块 E：完整清理与重建

### 11.1 三种配方

| 配方 | 使用意图 | 处理范围 |
|---|---|---|
| 修复登录 | 旧/失效登录、错误认证来源 | 针对凭据来源和目标站点状态，尽量保留其他客户端状态 |
| 重建客户端 | 账号异常后，希望重新建立本地使用状态 | 冻结目标、归档选中工作内容、移除已识别登录和运行状态、建立新环境、迁入 |
| 退役此环境 | 不再使用某个旧实例 | 退出/停止已选目标，移除已选本地状态、入口与本工具规则，保留或导出工作归档 |

“彻底”的含义是**目标范围内识别到的所有选中类别都被处理且复验**，不是删除机器上所有含 Claude 字符串的文件。

### 11.2 数据分类

- 凭据与认证选择：单独处理；远端撤销与本地删除分开记录。
- 客户端状态：schema 已识别的登录元数据、启动/项目状态等；混合文件按字段或明确整文件重建路径处理。
- 工作资产：会话、个人指令、记忆文本、项目资料；默认保留。
- 可执行扩展：hooks、MCP、插件、skills 中的执行配置；保留归档与重新启用分开。
- 诊断/缓存：与目标状态有关时可随配方处理；不以腾空间扩张范围。
- 浏览器状态：站点集、数据类型、store/profile 分开。

### 11.3 有序暂停

从精确 target 找到实际写入者与重启来源：进程、supervisor、launch agent、systemd、tmux、IDE 包装等。只暂停用户选定目标，记录原启动状态。自动重启策略必须先处理，否则刚删状态就可能回写。

先尝试正常结束；超过可配置等待时间后让用户选择延长、退出重置或强制结束已确认范围。发现共享 supervisor 承载其他实例时不能全局 stop。

### 11.4 注销与凭据清理

对适配版本优先使用官方 `claude auth logout`；`auth status`/doctor 等命令必须验证自身行为与输出，不在扫描时随意启动交互 agent。[S06] 原生命令可能涉及网络或令牌撤销，这个影响在计划里展示。

macOS Keychain 与文件 fallback、Linux credential file、独立 profile 与目录外共享认证都进入判定；不以猜测的 Keychain 服务名称批量删除。[S03] 当前账号已封禁或离线时，远端注销未必能完成；本地已清理与服务端撤销未知分别呈现。

“不再检测到本地凭据”不能证明已撤销服务器上的 token，更不改变账户封禁状态。

### 11.5 状态重建

优先生成新 root，并在官方机制允许的范围内准备新的启动入口；原地修复需要已知 schema、可恢复差异与静止的写入者。当前消费版 Desktop 没有公开确认的独立 profile 机制时，不默认传 Electron 参数假装隔离成功。

重建不是总是删除 `~/.claude.json`：此文件与目录内数据可能是混合用途；按版本配方保留需要迁出的配置。[S04][S25]

### 11.6 回写检测

清理后、重新登录前做本地静态复查；受控新启动后再次检查。若旧值因 shell、service、外部配置管理器或共享凭据重新出现，指出来源并提出针对性动作。只发现同名新文件不判为失败，需要比较状态类别和来源。

重建过程中产生的新会话和重新登录的凭据归属新状态，不应被下一次自动重试删除。


### 11.7 清理范围完整性

快速发现可以分页或截断；破坏性计划的目标枚举不可以隐式截断。每个类别要记录扫描是否穷尽、排除项、权限缺口、异常文件与稳定快照标识。只有“已知目标范围完整”才能承诺该类别清理完整；否则直接定位缺口，让用户修复访问权限或显式缩小并重新批准范围。

浏览器与文件系统分别有自己的覆盖结果，不能用文件清理成功掩盖扩展离线。任务可以部分完成，但摘要必须保留未完成对象。正常登录修复不自动升级成退役整个环境；每次扩张都需要新的差异与授权。

## 12. 模块 F：工作内容迁出与选择性迁入

### 12.1 三种包

**原始工作归档：** 保存用户选择的原始资料及 manifest，默认不包括凭据、Cookie、密钥与历史环境变量。混合文件不能可靠脱敏时加密归档并标明不自动迁入。

**可迁入内容包：** 只含被选定的会话/指令/记忆等类别。原始会话能否被新版本恢复由 adapter 决定；不盲目重写 session ID、路径编码或关系索引。

**配置方案包：** 只分享可移植设置、来源与要求；不携带真实路径、主机身份、账号邮箱、密钥或私人域名。导入时重新映射目标，不能自动修改接收方机器。

### 12.2 迁入默认

文本指令可以迁入但不触发运行；hooks、MCP server 和 plugin 的可执行配置默认保持待启用。用户可批量确认自己已有的配置，不需要逐行重新搭建。迁入结束显示“内容存在”和“运行配置已启用”的区别。

可选择在新环境继续会话；若格式不兼容，提供可阅读的本地归档与原始文件，不宣称已恢复可续聊会话。

### 12.3 完整性与容量

包有文件清单、类别、源版本、时间与完整性摘要。导入拒绝路径穿越、绝对路径、逃逸 symlink、压缩炸弹与覆盖未选目标。容量不足时在破坏性步骤前停下，用户可选新目录，不先删原始内容再尝试备份。

## 13. 模块 G：VPS、SSH 与离线终端

### 13.1 连接体验

复用用户已有 OpenSSH 配置与系统 agent；主机 alias 是显示入口，不把私钥复制到应用数据库。主机验证变化必须重新确认，不能自动忽略。[S20] 不导入 alias 时执行其任意 shell `Match exec` 等内容；真正连接才按用户选择使用系统 SSH。

runner 可通过已校验发布资产上传至用户目录，不要求 sudo；部署前展示目标、架构、下载来源、校验值与路径。文件传输使用 SFTP/受支持机制，不能把用户路径拼进无约束远端 shell。

### 13.2 执行权威

每台主机有自己的库存快照、job journal、加密恢复区和规则版本。Mac 保存展示缓存与 SSH 配置引用；远程私有状态默认不回传。

任务计划在目标 runner 生成或重新核验，GUI 不能拿旧的本地缓存直接决定远端删除路径。远程进程在 durable accept 后脱离 SSH 连接生命周期；支持 systemd user service 时验证 user manager 的存活条件，不假设退出登录后天然存在。

### 13.3 无 systemd 的情况

一次性前台 CLI 与本地维护仍可用。需要断线持续的任务使用经过验证的 runner 自管理 supervisor；若该环境会杀掉用户的所有进程，就明确不提供断线继续，改为可恢复的分步任务。不得为获得持久性静默启用 linger 或改系统登录策略。

### 13.4 终端等价能力

CLI/TUI 使用同一 recipes、planner、executor 和 receipt。支持发现、解释、创建方案、预览、执行、查询、恢复、导出、受控启动及设置管理。纯 CLI 提供稳定 JSON，非交互写操作需要准确 plan ID/hash 与显式授权；不接受一个无范围的 `--yes` 清整个机器。

## 14. 模块 H：漂移、更新与关系维护

### 14.1 监测的对象

仅监测已登记环境的相关配置摘要、版本、profile 配对状态、启动器和本工具规则。默认不开启；用户可以按环境启用。事件触发与低频 reconciliation 结合，不常驻扫描浏览器数据库或进程秘密。

### 14.2 修复控制

差异分为用户修改、外部工具覆盖、产品升级失效、来源不明。允许“接受当前值”，避免本工具无限反向改回。已预先批准的 owned 设置可自动修复；清理和注销仍需要任务授权。

### 14.3 规则更新

内置版本足够离线完成支持范围内的工作。网络更新显式启用，使用签名的声明式规则，不能下载并执行任意 shell。规则引擎只能调用编译进产品的有界 action；新增越权能力需要应用更新。

规则与程序分别记录版本，计划固定规则版本。更新后先验证，再激活；可撤回误发布规则。旧支持状态会降为“需要复查”，不会在没有检查的情况下继续亮绿。

## 15. 技术架构与单一执行权威

### 15.1 首选实现

**Tauri 2＋TypeScript/React GUI；Rust 共享核心与独立 runner；TypeScript 浏览器扩展；少量 macOS 原生桥接与可选 Network Extension。** GUI 不打包 Chromium，不把 Node/Python 运行时带到 VPS。Tauri 的进程与权限机制提供起点，不自动保证应用安全。[S22][S23]

相较纯 SwiftUI，选此方向是为了 UI/交互测试、现有前端开发积累与共享模型；不是因为必须给 Linux 做桌面。若实测原生集成代价反而占优，可换 SwiftUI 外壳，不能换掉同一核心和协议。

### 15.2 组件职责

```text
Mac GUI ── typed commands ── Local core / runner
    │                              │
    │                              ├─ Product / OS adapters
    │                              ├─ Planner + executor + verifier
    │                              ├─ Jobs + restore store
    │                              └─ Optional egress guard
    │
    ├─ Native Messaging host ── Paired browser extension(s)
    │
    └─ OpenSSH ── Remote runner ── same core + Linux adapters

Optional platform helper: only privileged, predefined operations
```

浏览器数据由浏览器的原生 API 执行；Keychain 由平台机制执行；产品设置和状态由对应 adapter 执行。GUI 不自带第二套清理逻辑。所有 mutation 进入统一计划与结果流程，但不能把跨浏览器、文件和网络动作伪装成一个原子事务。

### 15.3 仓库结构（建议）

```text
apps/desktop/             # GUI and Tauri wrapper
apps/runner/              # headless CLI / TUI / job runner
crates/core/              # domain, plans, outcomes, policies
crates/adapters/          # product, browser bridge, OS, SSH target
crates/egress/            # scoped proxy and verification
crates/storage/           # journal, receipts, encrypted restore metadata
platform/macos/           # native integration / optional extension
platform/linux/          # service and privileged namespace integration
extensions/browser/      # shared webextension + browser-specific adapters
rules/                   # signed declarative rules, no arbitrary scripts
contracts/               # schema and protocol versions
fixtures/                # synthetic only
tests/                   # contract, integration, end-to-end, failure injection
docs/                    # specification, decisions, support evidence
```

目录是可改的实施建议，不是为了多仓库或多进程而拆分。不能因有共享 core 就提前造一个通用插件 marketplace。

## 16. 数据契约

### 16.1 核心记录

| 记录 | 必需字段/语义 |
|---|---|
| Host | 随机 ID、平台、架构、用户作用域、连接引用、能力摘要 |
| Environment | host、surface、executable、config root、credential scope、启动上下文、ownership |
| Observation | 目标 revision、观察方式、时间窗、规则版本、证据能力、脱敏结果 |
| Finding | 具体问题、相关 observations、范围、可执行纠正、效果边界 |
| Policy | 意图、设置与约束、作用域、功能依赖、规则兼容范围 |
| Plan | 固定目标/快照/规则、操作 DAG、影响、保留集合、前置条件、授权 hash |
| Job | 唯一 ID、plan hash、durable state、每步状态、deadline、恢复入口 |
| Receipt | 实际执行对象、验证、未完成项、恢复能力、网络/账号副作用 |
| Archive | 类别、加密情况、manifest、保留策略、恢复限制 |

### 16.2 每个 Action 的契约

必须声明：对象选择方法、能处理的平台/版本、读取和写入类别、是否涉及网络、是否需权限/停进程、前置条件、执行方式、效果验证、幂等边界、失败恢复、是否可逆。

例如 `credential.logout` 与 `credential.remove_local` 不能是同一个不透明“清理” action；前者可能涉及服务端，后者只处理目标本地凭据。`browser.clear_site_data` 不能同时隐式请求 `history.delete_all`。

### 16.3 观察状态不单维度打分

分别保存：`configured`、`effective_context_confirmed`、`observed_in_test`、`enforcement_verified`。不是后者有了就推导所有前者/所有表面都覆盖；每个结论绑定目标、版本、入口与测试范围。

### 16.4 范例文件

随附 `examples/policy.synthetic.json` 与 `examples/reset-plan.synthetic.json` 是可解析的领域样例，不是生产规则、不含真实路径和凭据，也不是可直接执行的清理指令。实现期应从这些语义生成严格 schema，而非允许自由文本控制删除。

## 17. 操作执行、恢复与并发

### 17.1 操作状态机

```text
draft → planned → awaiting_approval → accepted
      → preparing → executing → verifying
      → completed | partially_completed | failed | cancelled

连接状态另存：connected / disconnected / reconnecting
效果不确定另存：needs_reconciliation
```

`accepted` 必须表示远端 journal 已持久记录、可凭同一 ID 查询，不只是 HTTP/stdio 收到一段数据。连接断开不是任务终态。

### 17.2 计划冻结

计划记录目标用户、真实路径/凭据范围、浏览器配对实例、root revision、规则版本、预期影响。用户批准之后对象变化使计划失效；不能重新扫描后把新出现的数据自动加入同一个删除计划。

### 17.3 文件操作

执行前重新检查文件身份、类型、所有者、权限与内容 revision；受保护根不能经 symlink 逃逸。按类别使用同卷原子替换或明确的可恢复过程。外部应用不一定遵守本工具锁，因此有冲突的写入者需要静止；仅“先比 hash 再 rename”不能宣称解决所有并发问题。

一次修改失败不继续覆盖同文件剩余内容。写后读回，恢复时只撤销仍与本工具写入值相同的字段；用户之后的编辑冲突需要合并预览，不整文件回滚覆盖。

### 17.4 外部副作用

文件修改、浏览器删除、凭据撤销不存在统一事务。计划按依赖顺序执行，记录可补偿/不可补偿步骤。对有副作用的命令超时，先 reconciliation，不盲目重跑。

Cookie 清理没有浏览器级幂等 key：若上次已执行但 ACK 丢失，再执行可能删掉用户刚重登的数据。因此桥接层 journal 必须跨 service worker 重启保存任务结果；结果不确定时冻结自动重试并重新确认目标状态。

### 17.5 超时与取消

每阶段有服务端 deadline，不依赖前端 fetch timeout。取消在安全边界生效；已经完成的不可逆步骤保留在 receipt 中。长操作报告对象级进度，不展示虚假百分比。扫描、备份、压缩、网络探针均有时间与容量上限。

## 18. 安全与隐私本身的产品要求

### 18.1 权限逐项申请

日常配置与用户目录操作不需管理员。Keychain、目标目录授权、浏览器配对、网络扩展、Linux namespace 分别说明理由。屏幕录制、辅助功能、全磁盘访问不作为初始化套餐。

### 18.2 不收集本来要帮用户减少的信息

默认没有 analytics、崩溃上传、远程字体、在线 license check。公开更新与网络诊断端点是用户可见、可关闭的网络活动；日志不包含账户令牌、Cookie、完整环境、聊天内容或设备指纹。

凭据只在必要本地执行路径短暂处理，不送 GUI 渲染层，不进入操作日志。导出支持包经过结构化字段白名单与脱敏预览；分享功能不一键上传。

### 18.3 配对与 IPC

Native Messaging manifest 限制扩展 ID；配对另验证 profile 实例。网页 content script 无权发起系统变更，扩展 worker 校验消息来源、类型与目标；不开放任意 `exec`、`read_file` 或绝对路径删除。

本地 IPC 使用用户权限目录和 OS peer identity 或同等级机制；远程走 SSH。来自网页、日志、文件名、规则描述的内容只能是数据，不可改变计划权限。GUI 禁止远程页面获得 native capabilities，路径/日志 HTML 转义。

### 18.4 恢复数据

配置差异优先做最小备份；含敏感内容的恢复包默认使用成熟认证加密格式/库，不发明密码协议。macOS 密钥由 Keychain 管理；Linux 无安全密钥存储时用用户口令或明确降低承诺，不把同目录明文 key 说成加密保护。

自动事务恢复数据默认建议 14 天、容量上限 2 GiB；用户主动生成的工作归档不自动过期。日志默认 30 天/64 MiB，网络元数据默认 24 小时/16 MiB；这些值在设置中可改，清理恢复区需要区分归档与临时备份。


### 18.5 本工具不成为新的残留来源

恢复配置时默认不恢复已注销的凭据，也不从旧环境重新注入 token；任何包含秘密的原始归档都与普通工作迁入隔离。用于内部冲突检测的秘密摘要应留在所属主机，低熵敏感值不能作为公开可分享的普通哈希暴露。

卸载与清理自身数据有独立预览：区分程序文件、规则、连接引用、普通日志、临时恢复副本和用户主动保留的工作归档。默认保留后者。销毁加密密钥可能使旧包无法恢复，不能作为无提示的“清缓存”。

## 19. 版本规则与未知状态

规则带 `source_refs`、`checked_at`、支持的产品与平台版本、行为测试、作用范围、撤回信息。官方文档是机制依据，不等于本机测试结果；社区 issue 是复现线索，不等于普遍事实。

未知版本允许有界发现、展示和已有公共配置的读回；涉及私有状态 schema、credential namespace 或不可逆删除时不能套用“差不多”的旧规则。用户仍可建立已支持的专用环境、保留原始归档，或更新 adapter；不能用一整屏未知替代完成已支持动作。

任何公共发行说明都应列：**实际能做的、适用的平台版本、需要的模块、仍未验证的组合**。不以测试数量代替真实行为覆盖。

## 20. 性能、成本与发布

### 20.1 体验预算（待实测）

- Mac 冷启动首屏目标 ≤2 秒；本地轻量发现首批结果 ≤3 秒。
- 快速检查目标 ≤10 秒；深检查与网络验证分开，支持取消。
- 空闲后台 CPU 目标平均 <0.5%；未启用观察/漂移时不常驻扫盘。
- GUI 空闲常驻内存目标 <180 MiB；runner 普通任务 <80 MiB，单独报告扫描/备份峰值。
- 单架构 Mac 下载目标 <50 MiB；Linux runner 目标 <25 MiB。超预算要解释依赖与价值，不为了追数字删掉核心功能。
- VPS 零 GUI runtime 依赖；普通使用不需要 Docker、Node、Python 或模型账号。

### 20.2 发行要求

Mac 正式面向非开发者发布要处理签名、公证、更新与卸载。Firefox 正式使用需要签名扩展；开发者临时加载不算最终安装体验。[S24] Chrome/Edge 有可持久使用的配套分发路径，首次安装的浏览器安全确认由用户完成，应用指导并自动配对复验。

规则更新失败不阻止离线清理；无激活服务器。程序升级与规则升级分别有版本和回退。卸载本工具提供保留或恢复它所改设置的选择，移除自己的 launcher/helper/extension pairing，不删除原有 Claude 工作内容。

### 20.3 发布者成本

没有在线后端也能交付大部分功能。需要单独预算的是代码签名、公证/开发者资格、浏览器分发、可选诊断服务与维护测试环境。不能用“免费”掩盖这些成本，也不需要为每个用户部署专属 VPS。

## 21. 错误设计

| 错误类别 | 用户看到的内容 | 下一步 |
|---|---|---|
| 目标已变化 | 预览后此环境的登录/配置发生变化 | 重新生成计划，不复用旧授权 |
| 配置被其他来源覆盖 | 指出上层来源和当前值 | 精确修复或接受当前设置 |
| 扩展控制权冲突 | 该设置由其他扩展/策略控制 | 显示来源，用户决定交接 |
| 无法停止完整写入者 | 仍有哪个目标在写 | 等待/取消/明确更大范围 |
| 执行后 ACK 丢失 | 结果待核对，不重复操作 | 查询 journal 或重新确认 |
| 备份空间不足 | 需要多少已知空间与目标位置 | 改位置，原始内容尚未删除 |
| 凭据范围不独立 | 哪些环境共享此登录 | 不单独注销，或批准完整范围 |
| 网络约束未生效 | 哪类直接连接仍可通过 | 修复组件或切换准确标注的模式 |
| 未支持 schema | 已保留哪些内容、哪一步不能执行 | 更新适配或使用新环境路径 |

技术错误码为稳定机器字段；界面说人话。部分完成不显示大绿勾掩盖尚未退出的登录或未处理的浏览器数据。

## 22. 完整验收与发布条件

详细用例在 `ACCEPTANCE.md`。整版至少同时通过以下六组结果，不能只完成其一就改称完整产品：

1. **实际应用方案：** 精确改动、启动上下文验证、功能影响可见、回退不伤后续编辑。
2. **真实浏览器操作：** Chrome/Edge/Firefox 测试范围内的数据、权限、WebRTC 与配对正确；邻域保留。
3. **清理到重建：** 旧状态处理、工作归档、选择性迁入、重新启动与回写检查连通。
4. **跨主机闭环：** Mac 与 Linux 的执行语义一致，断线/重启/ACK 丢失不重复破坏。
5. **外发能力可证明：** 配置、观察与强约束各有匹配证据；混合域名不误判，逃逸测试不能被忽略。
6. **人能用：** 初次配对、普通任务、失败恢复、升级和卸载都经真人任务测试，而非只有开发者录屏。

高权限强约束组件如尚未完成，其状态必须独立标记；不得用“全量防护已完成”宣传。其余完整生命周期也不能因为该模块难做而退化成只读检查器。

## 23. 实现顺序：解除关键依赖，不削减目标

先验证最容易推翻设计的四件事：真实浏览器 profile 配对与站点级删除；Claude 当前/旧版本的凭据隔离；产品实际启动上下文；Mac/Linux 强约束的进程覆盖边界。输出可复现实验与结果，而非泛泛调研结论。

随后并行推进：共享 core/journal；Mac 完整交互；browser adapters；Claude 状态与迁入；SSH runner；网络通道与可选平台约束。每条线都面对同一套合成旅程，不允许 UI、脚本与网络模块各自定义“完成”。

集成期从完整旅程验证安装→方案→使用→故障→清理→迁入→恢复→升级，不以“再加一个功能页面”的节奏推进。施工可以分批，交付要求不改成一个小切片。

## 24. 必须主动挑战的假设

**若用户只需要几个开关，为什么不发 shell 脚本？** 因为产品必须正确找到实际环境、维护状态、处理浏览器与凭据边界、执行完整重建并发现漂移。如果这些没有做出来，独立 App 的理由确实不足。

**若预设和全选让用户省心，为什么还要来源链？** 来源链是工具替用户作出正确动作的基础；普通用户无需展开。不能以“不打扰”为由把盲删藏起来。

**若一个选项更私密，为什么不默认最强？** 因为用户可能依赖受影响的功能，也因为调整本身未必覆盖真正的信息路径。方案要依据目标，不依据按钮数量。

**若 reset 保留了很多东西，还算彻底吗？** 用户选择清理的登录与状态应彻底处理；工作成果本来就不是清理目标。彻底的边界应可检查，而不是靠文件数量表现。

**若某配置更新后又变回去，是否说明应该改成只读文件？** 不是。先辨认真正写入者与配置权威；默认 chmod 锁死产品配置会制造新的故障。

**若完整网络约束太难，是否先画一个“已保护”？** 不能。可操作的本机与浏览器能力照样完整完成；网络约束单独验收。真实覆盖弱于需求时，必须修实现或修承诺，不能修文案掩盖。
