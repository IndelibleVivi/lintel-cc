# Lintel 操作指南

适用版本：0.1.0 开发候选。整理日期：2026-10-05。依据当前源码与各模块合同；这是开发候选的操作说明，发行与 runtime 状态见[当前状态](current-state.md)。

Lintel 帮你处理具体的 Claude 使用环境：减少指定的可选外发、管理浏览器权限与站点状态、保住工作内容、清理已识别的旧状态，以及在 Mac 上管理 Linux VPS 的同类任务。每次先认准目标，再查看实际变化，最后根据执行回执继续工作或恢复。

当前版本是 **0.1.0 开发候选**，可以按以下路径理解与试用已经接通的能力。正式浏览器安装、真实 Claude 认证、生产 VPS 和完整首次使用旅程仍有验收缺口；相应步骤会说明，不把某个模块的测试结果当作整套使用环境已验证。

## 如何开始

如果你已经拿到 Lintel 的本地构建 App，打开后从下面的任务表进入。当前仍是开发候选，源码仓库没有把正式签名、公证和非开发者安装验收视为完成。需要自己构建时，按照 [README 的本地构建与试用](../README.md#本地构建与试用) 准备 Rust、Node 和 macOS 构建环境。

Linux 只使用独立 runner/CLI，不需要安装桌面环境。Mac 可以在主机面板批准准备 App 内置的 Linux runner，见第 5 节；从源码取得 CLI 可用 `cargo build -p lintel-runner`，二进制在 `target/debug/lintel`。App 存在不代表终端已经能用 `lintel`，先确认所使用的二进制路径。

第一次只想熟悉操作，可按 README 启动 `dev:synthetic`；页面会明确显示测试空间。

## 先选一件要做的事

| 你的目标 | 当前从哪里进入 | 完成后应得到什么 |
| --- | --- | --- |
| 减少外发，然后继续用 Claude | 首页方案选择，或侧栏“保护方案” | 具体设置变更与读回结果；再打开所选环境的新会话 |
| 管理浏览器暴露、权限或旧登录 | 首页“浏览器” | 指定 profile 的配对、设置或站点清理回执 |
| 保住工作，换一个配置环境 | “工作保全”→“只生成工作归档”或“保全并准备新环境” | 加密工作归档、新配置目录、选定内容的迁入结果 |
| 处理登录异常、清理旧状态或退役 | “清理与重建”→相应配方 | 准确文件范围的处理结果；必要时新环境或退役状态 |
| 从 Mac 管理 VPS 与后台服务 | 顶部主机名称，或“设置与模块”→“主机与 SSH 连接” | 远端工作空间、原任务可查询的回执、独立服务恢复入口 |
| 检查变化、恢复配置或找回中断结果 | “环境详情”→“检查变化”；“记录与恢复” | 具体差异、接受或恢复的决定，以及原任务最新结果 |

这些是六条任务路径；目前侧栏仍是“环境 / 保护方案 / 工作保全 / 清理与重建 / 记录与恢复”。首页的箭头是“预览变更”，不会发送聊天消息或调用模型。

## 开始前：认准三个不同的目标

**主机**决定在哪里执行。顶部“当前操作目标”中，“本机”是当前 Mac；SSH alias 是那台主机的当前登录用户。远程横幅会显示“环境、计划与记录均来自这台主机”。如果当前没有环境、顶部尚无主机按钮，可从侧栏底部打开“设置与模块”，进入“主机与 SSH 连接”。

**环境**主要是登记的 Claude Code 配置目录。它不是项目代码目录，也不是自动隔离全部凭据的账号容器。进入“环境详情 → 概况 → 配置来源与验证范围”可以查看配置目录；“启动与来源”展示程序与配置根。操作前用主机、环境名称和完整路径一起确认目标。

**浏览器 profile**在“浏览器”面板单独选择和授权。它属于运行桌面 App 的这台 Mac；切到 SSH 工作空间不会把本机浏览器或本机代理变成 VPS 的浏览器或网络。一个配置根与一个浏览器 profile 也不会自动建立身份隔离关系。

### 添加已有环境，或建立空白环境

已有 Claude Code 配置目录：点“添加现有环境”，或侧栏“你的环境”旁的加号；在“登记已有目录”填写“环境名称”和“配置目录完整路径”，再点“添加环境”。登记本身不修改目录中的设置。

想从空白配置目录开始：点侧栏“新建环境”，选择“建立新环境”，输入名称后点“建立环境”。空清单也提供“建立专用环境”。这个动作创建新配置根，不复制旧登录、设置、hooks 或 MCP；随后仍需为它选择方案、启动 Claude，并按正常流程登录。想带走工作内容，使用第 3 节的“工作保全”。

新目录用于分开本地状态，不能阻止同一用户进程读取其他文件，目录外认证也可能共享。如果界面显示“测试空间 · 操作仅作用于合成数据”，你正在操作独立测试数据；这不是个人环境的扫描结果。普通网页显示“从桌面应用开始”时，没有本机执行通道。

## 1. 减少外发，然后继续使用 Claude

### 1.1 选择你愿意接受的功能取舍

1. 顶部选择目标主机与环境，打开侧栏“保护方案”。首页可直接选择方案后点箭头预览；需要检查 Remote Control 或逐项选择时，进入完整页面。
2. 选择“保持功能”“减少外发”或“自定义”。它们先修改草案；草案按主机和环境保存，不会随着切换目标直接应用。
3. 如果使用 Remote Control，勾选“保留 Remote Control”，填写“组织是否要求 Trusted Devices？”；不知道就保留“尚未确认”。Lintel 静态读取已安装版本，组织条件来自你的声明，页面的“当前配置条件 / 执行后预计条件”解释本次组合。
4. 如果页面列出已有冲突值，先决定是否允许解除。普通方案中的“允许在预览中解除……”会把准确字段删除纳入计划；自定义方案用“移除本环境覆盖”表达这一决定。
5. 点“预览变更”，核对“将修改”“将保留”“实际步骤”，确认目标后点“批准并执行”。如果结果或影响不合适，点“返回调整”。

| 方案 | 当前会做什么 | 适合什么时候 |
| --- | --- | --- |
| 保持功能 | 关闭错误回报与质量调查；保持产品指标与主动反馈的当前设置 | 想做较少修改，并保留现有功能取舍 |
| 减少外发 | 分别控制产品指标、错误回报、主动反馈与质量调查；按所选 Remote Control 条件处理冲突 | 想明确减少这几类可选外发 |
| 自定义 | 对七项已识别控制逐项选择“保持原值 / 关闭这一项 / 移除本环境覆盖” | 只想改特定项，或已有自己的取舍 |

七项自定义控制是产品指标、错误回报、主动反馈、质量调查、跨工具 telemetry 开关、feature-flag 获取和非必要流量总开关。展开“来源与恢复”可看准确变量、当前值与关闭语义。不要单凭 `0` 或 `false` 判断是否开启：其中部分变量只要是非空字符串就表示关闭；界面会按该变量的规则解释。

“保持原值”确实保留原字段；全选保持时不重写 settings。“移除本环境覆盖”只删除当前 root 的 user settings 字段，其他 shell、项目或组织来源仍可能影响运行。勾选“保留 Remote Control”不会暗中改写自定义的明确选择。当前七项编辑器未接入 WebFetch 安全预检查和 marketplace 控制；官方更新、用户自设 OTel、通用代理与执行配置不会随这些方案被通配清除。

### 1.2 看读回结果，再打开新会话

执行后看每个步骤的结果及“下一次新启动”要求。**“已配置”或“已读回”说明配置值已经处理；当前打开的 Claude 会话不会自动退出或重新读取。** 回执中的“打开 Claude”，或“环境详情 → 启动与来源 → 打开 Claude”，会使用这个环境的配置根打开新会话；没有找到 Claude 程序时，按钮不可用，先按你的正常安装流程准备 Claude，再“重新检查”。

macOS 的“已请求启动”表示请求已交给 Terminal。实际登录、会话是否可用以及其他 IDE／服务入口的行为，要在相应入口确认。当前没有把这次设置读回自动升级为实际 Claude 网络效果的验证结果。

**需要恢复：**到“记录与恢复”找到本次任务，点“查看结果 → 预览恢复”，查看将恢复的准确字段，再“批准并执行”。若字段在任务后被修改，Lintel 会保留后续编辑并提示冲突；先查看来源，按现状重新选择方案。恢复配置不是恢复整个旧目录。

### 1.3 还想控制经过代理的连接

在本机环境打开“环境详情 → 外发与权限 → 受控通道”。展开“下次启动的配置草案”，选择默认放行或阻止，再按需填写“显式阻止规则”“显式允许规则”和上游 HTTP / HTTPS 代理。

规则每行一个确切主机，后面可用空格与英文逗号列出端口，例如：

```text
example.invalid 443,8443
```

这是格式示例，不是需要添加的实际规则。省略端口适用于该主机全部端口；不自动匹配子域。显式阻止优先于允许，再看默认动作。没有内置“全部遥测黑名单”；阻止用途混合的 API 主机可能连正常请求一起阻止。

1. 编辑好草案后点“启动通道”。
2. 核对“当前生效的通道配置”和实际“本地地址”；它们来自运行中的代理读回。
3. 点“通过通道打开 Claude”，明确开启带代理上下文的新会话。
4. 点“刷新连接”查看实际经过通道的连接。没有完成事件不等于没有流量，仍保持的连接可能还未形成完成记录。

**改规则或恢复使用：**先“停止通道”，等待停止，再编辑草案、启动并重新打开客户端。通道重启可能换端口，旧客户端不会自动采用新地址。原任务已结束时先“清除旧通道”；关闭 Lintel 会停止通道，但不会退出已打开的 Claude。

这条路径约束的是经过代理的连接。直接 socket、UDP、全部 DNS、`NO_PROXY`、其他进程与客户端自行直连不在这个证明范围。当前没有进程级网络强约束；SSH 工作空间也不能从这里启动远端代理。需要控制浏览器站点时，接着使用下一节的“站点代理”，并填入实际在本机运行的端口。

## 2. 管理浏览器暴露、权限或旧登录

### 2.1 第一次连接一个 profile

在首页点“浏览器”，展开“连接一个新的 profile”。当前 App 自带扩展与本地连接组件，按页面三步走；普通使用这套 App 内置资源时不需要先下载源码或在终端编译。

**第一步：准备并加载扩展。**选择“目标浏览器”，点“预览扩展目录”，核对版本、文件范围与目录，再点“批准准备扩展目录”。完成后可以“在 Finder 中打开”或“复制目录路径”；Firefox 显示“复制 manifest 路径”。然后到你真正要操作的 profile 加载：

| 浏览器 | 在目标 profile 打开 | 按页面选择 |
| --- | --- | --- |
| Chrome | `chrome://extensions` | 开发者模式 → “加载已解压的扩展 / Load unpacked” → 已准备目录 |
| Edge | `edge://extensions` | 开发者模式 → “加载已解压的扩展 / Load unpacked” → 已准备目录 |
| Firefox | `about:debugging#/runtime/this-firefox` | “Load Temporary Add-on” → 目录内 `manifest.json` |

Chrome / Edge 共用一份稳定的 Chromium 扩展目录，但每个 profile 都要单独加载和配对。Firefox 当前为临时开发加载，退出浏览器会移除扩展；长期签名安装仍未交付。Chrome / Edge 仍需开发者模式，三种正式浏览器的完整非开发者安装旅程尚未验收。

**第二步：安装本地连接。**将目标 profile 管理页的准确 ID 填入“已安装扩展的 ID”；Firefox 使用页面给出的固定 ID。点“预览本地连接安装”，核对浏览器、授权扩展与注册位置，再“批准安装本地连接”。安装到稳定的当前用户目录，之后移动 App 不会改变注册所指的组件位置。

**第三步：核对这份 profile。**点“生成配对请求”，复制 App 显示的 12 位“配对短码”。在扩展的“连接桌面应用”中填入“应用内的配对短码”和“这份 profile 的名字”，点“提交配对请求”。回到 App，点“检查配对”，核对名字、实例和两端短码，然后点“短码一致，批准此 profile”。

**这一步的完成标准：**App 列出所选 profile 的“已配对”，并能看到“最近 20 秒收到轮询”。“当前离线”与“已配对”可以同时成立；前者表示最近没有连接，后者表示持久授权还在。准备目录、组件注册、profile 配对、当前在线是四件事。

**连不上或更新时：**先检查目标 profile 是否真的加载了扩展、本地连接是否给了准确 ID，再“检查配对”。短码过期就重新“生成配对请求”。出现“身份冲突，需重新配对”时，在需要使用的扩展里点“重复实例冲突：生成新身份重新配对”，重新完成上述配对。App 可预览并批准更新其拥有的扩展目录与本地连接；更新扩展文件后还要在浏览器重新加载。外部目录、被改动的组件或不一致的注册不会被覆盖，先看冲突详情；中断目录准备有“批准继续准备扩展”的独立恢复预览。

当前安装器只提供 Chrome、Edge、Firefox 的固定路径。选择 Chrome 不代表已经安装到 AdsPower，其他 Chromium 浏览器也不能借名称相近推断已支持。

### 2.2 选择一个实际需要的浏览器动作

在“目标 profile”选中已配对、在线且无冲突的实例，再选操作。App 中点“送到浏览器预览”只提交请求；到目标扩展中打开“查看来自桌面的待确认操作”，核对“确认实际影响”，勾选“我确认以上范围与功能影响”，再点“授予必要权限并执行一次”。扩展会按需要请求原生权限。

| 当前按钮 | 作用范围与取舍 | 如何恢复或继续 |
| --- | --- | --- |
| WebRTC | 整个 profile；“限制非代理 UDP”等策略可能影响通话 | 完成后“提交恢复预览”，在扩展再次批准；有效值或控制者改变时会提示冲突 |
| 站点权限 | 所选站点的定位、摄像头、麦克风或通知设为阻止 | 独立恢复本扩展所写规则；Firefox 当前需到浏览器权限面板手动处理 |
| 站点代理 | 所选站点使用本机 `127.0.0.1` 的实际 HTTP 代理端口，没有 DIRECT 回退 | 先确保代理已启动；恢复也需预览批准；Firefox 当前未接入 |
| 阻断站点 | 阻止所选站点全部请求，会影响整个站点功能 | “提交恢复预览”，或按下一行临时暂停 |
| 暂停规则 | 暂停本扩展的阻断规则 1–60 分钟 | 到期恢复；浏览器离线时在下次启动恢复；不会解除清理隔离 |
| 全 profile 缓存 | 删除整个所选 profile 的 HTTP cache，包含其他站点 | 这是独立不可恢复动作，需要单独确认 |
| 清理站点数据 | 处理选定站点与存储类型，需要准备、浏览器重启和再次批准 | 按下一小节完成两阶段流程；删除后不能恢复 Cookie 或站点数据 |

默认目标是 `https://claude.ai`，`https://console.anthropic.com` 需要主动勾选。邮箱、Google、Apple 或其他 SSO 站点不在这个内置清单中。浏览器设置读回不等于设备级 IP 隐藏，站点代理也不覆盖全部 DNS、WebRTC 或其他程序。

### 2.3 清理站点数据：两次确认，中间完整重启

1. 选择“清理站点数据”，核对“目标站点”和“将清理的数据类别”。Cookie 会影响相关登录；Chromium 的 Cookie 处理可能扩大到完整可注册域，扩展预览会列出实际扩大范围。
2. “送到浏览器预览”，在目标扩展核对并批准。第一阶段隔离请求、关闭目标标签及嵌入目标 iframe 的宿主标签，注销所选 Service Worker。
3. 看到“等待浏览器重启后继续”时，**其余存储尚未删除**。完整退出并重新启动这个浏览器；仅关一个窗口或重启扩展 worker 不等价于浏览器启动证据。
4. 在原准备回执选择“预览重启后继续删除”；也可从 App 原任务点“送到浏览器预览重启后继续”。在扩展再次核对并批准，这次才执行其余存储删除。
5. 查询并看清删除回执；确认结果后，在扩展原回执点“已核对结果，解除站点隔离”。然后自行重访站点、按正常流程登录。

不要用“暂停规则”代替解除清理隔离。两阶段隔离会继续保留，避免在尚未核对时自动重访；新的登录数据也不会因为查询旧任务而被再次删除。完整重启后如果扩展未重新加载或未记录启动世代，工具会拒绝继续，先恢复扩展的有效连接，保留原准备记录。

Firefox 不支持本版本的站点级 Cache Storage / HTTP cache 清理，也未完成容器后台停写验证。当前临时扩展退出会被移除，不能把这条开发加载路径当作已验收的持久重启清理方案。独立 Chromium 临时测试 profile 已有真实完整重启与合成站点存储的验证；这不证明正式 Chrome、Edge、Firefox 或真实 claude.ai 的认证清理已完成。

**回复丢失：**在“浏览器”面板的原任务点“查询原任务”；“其他浏览器任务”可选更早记录。不要为同一不确定删除另发新操作。设置恢复与数据删除的边界见第 6 节。

## 3. 保住工作，或换一个配置环境

### 3.1 只把工作收好

首页“工作内容”和侧栏“工作保全”进入同一个独立入口。默认“只生成工作归档”：选择个人指令、记忆文本、会话资料，核对元数据概览，再点“预览保全计划”。归档准入会另行完整核对内容；概览不是备份。

“另存加密包的完整路径”可留空，归档保存在 Lintel 的 state；填写时须是**当前目标主机**上的完整文件路径，父目录已经存在、无符号链接且文件名尚未使用。已有文件不覆盖。预览中能查看冻结的目的地与文件数量；执行还会核对同一个目录对象，目录被替换或更换挂载时须重新预览。升级前没有冻结目录身份的旧显式输出计划也须重新预览，已完成的原任务仍可查询。

设置至少 12 个字符的归档口令并再输入一次，核对计划后“批准并执行”。自己保管口令；Lintel 不保存，遗失后无法解锁。成功回执为“完成”，给出工作归档路径、所选类别和文件数。此任务只生成加密工作包，不建立环境、不注销、不修改原 settings 或工作文件。

### 3.2 保全后准备新环境

在同一页选择“保全并准备新环境”，选择工作类别，按需填写新环境名称。预览显示加密归档、创建配置根、选择性迁入的实际顺序。批准后先生成归档，再建立新根并读回迁入文件；成功属于该任务自己的“完成”。

原 `CLAUDE.md` 放在新根；`projects` 中的记忆 Markdown 与会话 JSONL 进入 `lintel-imports` 待用区。已有待用区内容可再次保全而不产生重复嵌套。活跃工作与待用区出现同名内容或文件／目录冲突时，内容都保留，重复项在待用区加 `lintel-N-` 文件名前缀；独立包迁入的计划按同一规则冻结实际目标，已有目标文件仍不覆盖。批准执行时会在目标文件系统的临时空文件目录复核整批名称；例如 Linux 包的大小写不同文件在 macOS 被视为同名时，会在创建新环境或迁入正文前整批拒绝，显示 `migration_path_conflict`。原包仍可阅读；整理源内容重新归档或选择区分这些名称的文件系统。不复制凭据、settings、hooks、MCP 或插件，不宣称可直接续聊旧会话。旧目录、旧登录与原运行进程保留，它们是覆盖范围的说明。

结果页可“为新环境选择保护方案”，随后在准确配置根正常登录、启动并核验。如果原环境由 systemd service 运行，创建新根**不会改绑 service**；原 service 仍指向旧环境。恢复旧服务、调整新环境的启动配置是分别核对的动作。

旧版 `plan_reset` / TUI 的“新环境重建”仍为已有调用者保留，历史回执继续显示“部分完成”（旧状态尚未清理），不会重写为新任务状态。App 的工作保全使用新任务语义。

### 3.3 读取或迁入已有工作包

首页“工作归档”、工作保全页“阅读或迁入已有工作包”和“记录与恢复 → 查看归档”都可打开面板。任务回执的“查看工作归档”会选中当前包。

1. 选择“当前主机的任务归档”，或“独立加密包”并填写当前目标主机上的 `.age` 完整路径。即使这里没有原任务记录，独立包也能读取。
2. 输入口令，点“解锁并查看”；核对清单、类别、容量，点击文件阅读只读文本。单文件展示前 1 MiB，完整原文件保留在包中。
3. 在“选择性迁入”选择已登记的目标环境和类别，点“预览迁入计划”。已有目标目录须属于当前执行器用户，并允许访问／写入；已知归属或权限障碍会在整批正文写入前拒绝，Lintel 不自动修改权限。批准前核对目标根、文件清单和冻结包。
4. 再用同一口令批准执行。包在预览后变化会拒绝；同名目标文件不覆盖。整批目标路径在写入正文前核对，已有文件挡住父目录时先拒绝；已有目录权限保留，新建父目录为 `0700`，迁入文件为 `0600`。冲突时换一个专用环境或缩小类别后重新预览。

保全／重建若在新 root 创建或登记时中断，先查询原任务：`new_root` 和 `new_environment_id` 是创建前保存的准确意图，create 步骤完成才证明登记成功。目录可能已产生，但未登记时界面不提供新环境保护方案入口；先核对该路径与原回执，不重跑创建。

工作归档与状态备份的路径也可能只是发布意图。回执会将未读回的路径标为“待核对”；只有工作归档读回完成才提供查看按钮和任务归档选择。原路径继续保留，可按原任务核对，或将确认存在的包作为独立文件检查；不会因查询重跑发布。新文件使用系统原子不覆盖 rename；目标文件系统／内核不支持时返回 `atomic_publication_unsupported`，已有内容保留。

口令只驻留当前面板或待批准计划的临时内存；关闭后清除。解锁不会运行归档内容。独立工作包保持 `lintel.work/1` 兼容，旧合法包和历史任务来源仍可读取。

### 3.4 同机与 Mac ↔ VPS 的迁入

同机直接使用已有任务或独立包路径。跨主机先把**加密包文件**通过你已经信任的系统 SSH/SFTP/scp 或可移动存储带到目标机器，再切到该主机，用那里的绝对路径解锁和计划迁入；不要传整个 Lintel state、凭据或明文请求。App 不自动搬运文件，也不把本机路径映射到 VPS。

例如明确确认系统 SSH alias 与目标目录后，可以从系统终端使用：

```sh
scp -o StrictHostKeyChecking=yes /absolute/path/work-package.age approved-alias:/absolute/destination/work-package.age
```

选择未使用的目标文件名并独立检查 transfer 结果；这是系统文件传输，执行与覆盖规则由该工具拥有，不属于 Lintel 的冻结 import 计划。随后在目标执行器读取、校验、选择类别和批准 import。CLI 的无明文落盘输入方式见 [Agent 指南](agents.md#portable-work)。本机 browser / proxy 不随工作包迁移。

**大文件或归档失败：**当前准入是单文件 8 MiB、合计 32 MiB、10,000 文件，另有扫描条目与时间预算。超限会明确拒绝，不把截断结果称为完整归档；保留原资料，重新选择确实需要的类别。中途失败先看原任务的已完成步骤和产物，不重新创建包或重复迁入。执行中的归档步骤会记录目的地；路径存在不等于写后核验已完成，包实际存在时可用原任务解锁，核对原回执与产物。

“状态备份”与“工作归档”是不同产物：清理时保存的混合客户端状态备份不支持自动迁入。工作包不包含全部认证、执行配置或云端资料，也没有“恢复全部”。

回执中的状态备份路径会在写入前保存；有路径不等于备份已完成。以对应步骤的写后读回结果为准，中断时查询原任务并核对该目标，勿重复提交清理。

## 4. 处理登录异常、清理旧状态或退役环境

先确认你想处理的范围。Lintel 不把网络错误或一个失败响应自动判定为封禁；这条路径处理本地可识别状态，不改变服务端账号状态。

| “清理与重建”中的配方 | 当前实际范围 | 做完还要确认什么 |
| --- | --- | --- |
| 修复本地登录 | 处理预览中的本地凭据文件；可显式选择官方注销 | Keychain、目录外认证与服务端撤销分别看结果 |
| 清理并重建 | 加密归档工作及已识别混合客户端状态，处理准确文件，建立新环境并迁入 | 新环境启动、正常登录，以及浏览器等独立范围 |
| 退役此环境 | 处理准确状态文件并停用该环境的 Lintel 启动入口；保留原工作目录 | 不是卸载 Claude、删除整目录或恢复已删凭据 |

“修复本地登录”当前针对已识别 `.credentials.json`；后两种还处理预览列出的混合 `.claude.json`。默认 root 和专用 root 的路径可能不同，必须以“已识别的本地范围”为准。不要把名称中的“清理”理解成扫描并删除整机所有 Claude 文件。

### 按顺序准备、执行与核对

1. 顶部确认主机、环境和配置目录，选择配方。
2. 先停止这个环境的终端、IDE 与自动重启来源。如果它由 Linux systemd 服务运行，在“目标后台服务”按第 5.3 节单独检查并批准暂停。
3. 点“刷新范围”，看准确文件路径、存在状态与写入者提示。确认后勾选“已关闭目标的终端、IDE 与自动重启来源”。检测到仍运行或无法归属的 Claude 写入者时，预览会被阻止；不要只靠勾选绕过复查。
4. 需要核对认证时，点“显式检查认证来源”。这个动作会执行该环境的官方认证状态命令，普通发现不会自动执行它。需要官方注销时，再勾选“同时请求官方注销”。共享认证范围、外部认证来源或无法核对的输出会阻止该注销路径；它可能联系服务端。
5. “清理并重建”与“退役此环境”还要至少选择一种工作类别并设置归档口令；全部取消时 App 会阻止预览并提示重新选择。“修复本地登录”不要求工作归档。点“预览这份计划”，核对“将处理 / 将保留”、不可恢复步骤和所有准确对象，再“批准并执行”。
6. 查看回执的逐步结果、“本地清理”“服务端撤销”、归档路径与新配置目录。未选官方注销时，结果保留“部分完成”；即使官方 CLI 报告已退出，服务端 token 撤销仍单独是“未验证”。
7. 如果旧登录也存在于浏览器，点“浏览器工作空间”，按第 2.3 节独立处理所选 profile。新环境的登录由你在官方入口正常完成。

**实际顺序：**状态备份与工作加密归档 →（清理并重建）创建新环境并迁入 →（若选择）官方注销与状态核验 → 精确旧文件移除 →（退役）停用启动入口。预览与回执采用这个顺序。后续注销失败时归档和新环境可能已经存在；回执保留完成步骤、路径、结构化错误 code/phase/recovery，后续删除停止。查询原任务不会再次创建环境或注销。

**遇到冲突：**如果预览后文件、程序或登录来源改变，重新核对当前范围并生成新预览；如果已经提交且结果不确定，先按原任务 ID 查询。操作中发现新文件或旧状态重新出现，会保留新状态并停止后续动作，不自动再次删除。若回执记录隔离目录，保留它并按所列路径核对，不要把恢复等同于直接覆盖当前新文件。

**需要恢复：**可恢复的配置走原任务“预览恢复”；删除的凭据和浏览器数据没有自动恢复。退役后可回“环境”页点“重新启用环境”，恢复登记与启动资格，但不会复原已删凭据；必要时重新登录。已暂停服务的恢复仍是独立任务，不会因为清理完成或关闭窗口自动发生。

当前完整 Desktop、IDE、macOS 服务及其他 supervisor 的定位与停写尚未完成。它们出现在你的真实使用链路时，需要独立核对；不要把 Claude Code 的已识别文件处理结果当成这些入口已经清场。

## 5. 从 Mac 管理 VPS 与后台服务

### 5.1 连接正确的 SSH 用户

打开“主机与 SSH 连接”。先展开“连接前需要什么？”，确认已有可用的系统 SSH Host alias、可信的主机身份记录，以及 OpenSSH 或系统 agent 已能提供密钥。Lintel 的非交互连接不会弹出密码输入框。

1. 在“SSH Host alias”选择或填写已有别名，点“登记主机”。这里填写 alias，例如 `writing-server`，不是 `user@host`、命令或 SSH 参数。
2. 已有可用 PATH runner 时，点“连接并管理”。只有 Claude Code、没有 Lintel runner 的主机不能直接管理。
3. 需要准备 runner 时，点“检查并准备运行器”。核对系统、架构、SSH 用户、版本、大小，再展开“查看安装与校验详情”。
4. 确认准确目标后点“批准并安装这个运行器”。App 上传自身携带的静态 runner，完成文件、权限与实际能力核验后显示“运行器已就绪”。
5. 点“连接并管理”，进入远程工作空间；再登记或选择该用户的 Claude 配置环境。

安装范围属于**当前 SSH 登录用户**。如果 Claude 由另一个用户运行，使用那个用户的 alias；以 root 登录不等于自动管理每个普通用户环境。当前支持 Linux x86_64 / arm64 的候选资源；App 缺包或目标条件不满足时会给出限制。准备过程不修改 PATH、shell 启动文件、sshd、Claude 配置，也不在 VPS 上编译或自动 sudo。

**安装中断：**从“安装记录”点“核对原安装”，确认原目标和同一文件。它只核验原安装，不重新上传。不要通过移除并重新登记主机绕过未核对记录。运行器版本更新后，有版本绑定的旧任务继续使用其冻结的旧 runner；较早的无绑定记录保留原兼容路径。

**连接失败：**按错误中的阶段和具体原因排查。需要时打开“查看本次错误输出”，或“复制排查摘要”；修复后点“重新检查连接”。host key 未知或变化时，先用你的系统 SSH 流程核对主机身份，Lintel 不自动忽略。若已经提交执行，连接恢复后查询原任务；重连成功后也不要重复提交原操作。

### 5.2 执行任务、断线查询与打开会话

连接后，保护方案、清理、工作归档与记录使用同一套界面，计划由远端 core 针对远端状态生成。确认框会持续显示所属 alias。

远端任务先持久接收，再在后台执行。“已接收”表明原任务已记下，不等于修改已经完成。回执会显示实际托管方式：符合当前主机条件时使用 systemd 单任务后台服务；其他条件下显示“断线后的继续执行未获保证”。这些托管事实不构成重启后续跑承诺。

断线或 App 重开后：

1. 打开“主机与 SSH 连接 → 持久提交记录”。
2. 找到原 alias 和原任务 ID，点“查询原任务”。
3. 点“查看完整回执与恢复”，进入原主机、原环境的完整结果。
4. 若仍“已接收 / 执行中 / 待核对”，继续核对原结果；只有看到明确的逐步结果后，才决定恢复或另建新的后续计划。
5. 配置恢复点“预览恢复”，服务恢复点“预览恢复服务”，各自批准。

远端结果窗的“查询最新结果”使用原任务 reconnect。记录页手填 ID 使用只读 job lookup；共同 controller 会保留已有提交记录的冻结 runner，主机升级后仍使用原绑定。未知 ID 不创建提交记录，误查尚未提交的计划不会阻止它按原批准提交。已有但无 digest 的旧记录保留 PATH 查询兼容路径；已提交／不确定任务仍只核对，不删除记录或重发。

主机列表的“移除”只移除 Lintel 登记，原任务、系统 SSH 配置与远端文件保留。“撤销移除”可重新登记。已经移除的 alias 仍可查原任务，要打开完整恢复流程需先重新登记；移除不是取消或删除任务。

要开始交互使用，从“环境详情 → 启动与来源 → 打开 Claude”，或结束状态的任务回执点“打开 Claude”。App 请求 macOS Terminal 通过同一严格 SSH alias、绑定 runner 和真实终端启动选定环境，不发送 prompt。**这个交互会话随 SSH 连接结束，与后台变更任务不同。** “已请求启动”以后，去 Terminal 确认真实会话。

隔离 OpenSSH 与真实 disposable Linux VM 已验证符合既有条件的 system/user manager 在真实 PAM logout 后继续并完成原任务，以及 reboot 后按原 ID 核对；不符合条件的 setsid 路径受限。生产 VPS、aarch64 runtime 与所有普通用户 manager 场景仍未验收。遇到中断只核对原任务，Lintel 不自动启用 linger、改登录策略或换一种启动方式再发一次。

### 5.3 暂停一个明确绑定的 systemd 服务

在远端“清理与重建”选择“修复本地登录”“清理并重建”或“退役此环境”，展开“目标后台服务”。单纯“工作保全”不显示这个面板。

1. “管理器”选“当前用户”，或在 runner 已是 root 时选“系统服务（需 root）”。
2. 填写完整“服务 unit”，如 `example.service`，点“检查服务”。不接受通配符或命令。
3. 核对“配置绑定”是否就是当前 root，以及自动重启、主进程和触发来源。
4. 点“预览暂停服务”，查看准确 unit、原状态与持久暂停项，然后“批准并执行”。
5. 核对暂停结果，再返回“清理与重建”；仍需关闭该环境的交互终端、IDE 和其他写入者。

暂停会阻止这个服务重新启动，并读取实际服务状态与 cgroup 证据。它持续到你独立批准恢复，不因关闭 App、SSH 断开或窗口关闭自动撤销。适配器只接受能明确绑定配置根的有限 systemd 服务，无法确认绑定、存在可能影响邻居的关系或使用不支持来源时，会拒绝而不扩大范围。

**恢复：**在暂停回执点“预览恢复服务”，或重新“检查服务”后选同名按钮。它核对原 unit 与暂停项，只移除原任务拥有的暂停项；原先运行的服务才重新启动，原先停止的保持停止。外部编辑冲突会保留现状与暂停项，先核对来源，不删除记录后强行重试。

**清理并重建后的服务选择：**新环境产生新 root，当前流程不会自动将原 service 改绑到新 root。“恢复服务”恢复的是原服务与原绑定。决定继续旧服务还是配置一个指向新环境的服务之前，先看清回执和绑定；当前没有把“重建客户端 → 改绑服务 → 新环境验证”做成自动完成的闭环。

## 6. 检查变化、恢复配置、找回结果

### 6.1 手动检查漂移

在“环境”页展开“环境详情”，找到“上次之后，有什么变化？”，点“检查变化”。结果列出已管理设置相对基线的差异：

- 想恢复之前的取舍，点“重新应用方案”，回到保护方案重新预览并批准。
- 接受现在的值，点“接受当前值”；这会把当前值记为此环境的基线，不会把设置重新改回去。
- 没有差异，表示当前检查范围内没有待处理变化，不是全机、浏览器或网络都已受控。

当前没有已启用的后台定时漂移、菜单栏快速动作或自动规则更新。软件升级、切换入口或外部工具改过设置后，主动“重新检查”和“检查变化”。

### 6.2 按任务记录恢复，不恢复整套旧状态

“记录与恢复”可按“全部环境 / 当前环境”筛选，或搜索“记录、环境或任务 ID”。“全部环境”仍属于当前主机。点“查看结果”阅读逐步回执，再选可用的后续动作。

| 想恢复什么 | 用什么入口 | 恢复边界 |
| --- | --- | --- |
| Lintel 写入或删除的设置字段 | 任务回执“预览恢复” | 只处理原任务字段；保护后续编辑 |
| 工作资料 | “查看工作归档”→解锁→“预览迁入计划” | 选择类别和目标；拒绝覆盖同名内容；不恢复凭据和执行配置 |
| systemd 服务状态 | 原暂停任务“预览恢复服务” | 原 unit、原任务拥有的暂停项与原 active/inactive 状态 |
| 退役环境的启动资格 | “环境”页“重新启用环境” | 恢复登记状态，不能恢复已删凭据 |
| 浏览器可恢复设置 | 浏览器任务“提交恢复预览”，或扩展“预览恢复此项设置” | 核对当前控制者／有效值，撤回本扩展拥有的改动 |
| Cookie、已删除站点数据、官方注销 | 没有通用撤销 | 使用正常重新登录流程；不要期待“预览恢复”找回这些数据 |

### 6.3 看懂状态，再决定下一步

| 看到的状态 | 目前能说明什么 | 下一步 |
| --- | --- | --- |
| 已配置 / 已读回 | 指定配置或设置已处理、读回 | 按新启动要求继续；不推断全部运行效果 |
| 已接收 | 远端已持久记录原任务 | 查询最终结果 |
| 执行中，或 `verifying` | 任务仍处于执行／核验阶段 | 保留原 ID，查询最新结果 |
| 已完成 | 回执所列步骤完成 | 看范围、限制与后续启动要求 |
| 部分完成 | 部分目标完成，另有明确未做或未知范围 | 看未完成步骤；新环境重建保留旧状态就会如此 |
| 未完成 | 至少一部分未成功 | 查看已经完成的步骤、错误和可恢复项 |
| 待核对 / 结果待核对 | 请求或副作用状态不能确定 | 查询原任务；不重复提交清理 |
| 等待浏览器重启后继续 | 清理准备完成，其余存储尚未删除 | 完整重启目标浏览器，再批准继续删除 |
| 已请求启动 | Terminal 接受了启动请求 | 在真实终端确认启动与登录 |

当前少数状态可能保留英文，如 `verifying`；不要仅凭颜色推断成功。执行窗有“查询最新结果”时，用它查询原任务。关闭结果窗后，可展开“执行连接中断？用原任务 ID 找回结果”，输入原计划或任务 ID，点“查询原任务”。远端 App 重开后的入口见第 5.2 节。

### 6.4 准备支持资料

在“记录与恢复”底部点“预览支持资料”，先看脱敏结果，再按面板提供的复制或保存动作取得 JSON。它只包含白名单内的平台、版本、计数和能力信息，不包含环境名、目录、设置正文、令牌或会话；分享由你决定，不自动上传。SSH 的“复制排查摘要”是另一项手动排障动作。

帮助入口还提供开发者 GitHub、Lintel 源码说明、VPS 101 与 SSH 排障手册。Day / Night / System 是外观选项；首页 Clawd、“陪它玩”、风景册与小游戏不会执行环境操作。

## 只有终端时：独立 CLI

CLI 不依赖 GUI 启动或 Tauri。源码安装与升级、机器可读 schema、秘密 stdin、批准、原任务 wait、恢复、browser/SSH/network 的有限适配见 [Agent CLI 指南](agents.md)。

```sh
lintel version --json
lintel capabilities --json
lintel describe plan_policy --json
lintel env list --json
lintel policy plan --environment <environment-id> --preset reduce --no-keep-remote-control
lintel plan show <returned-plan-id>
lintel job submit --plan <returned-plan-id> --approval <returned-plan-hash>
lintel job wait <returned-plan-id> --timeout 30s
lintel restore plan --job <original-job-id>
```

静态 version/capabilities/schema/describe 不发现个人目录、不运行 Claude，也不初始化 state。显式 `env list` / `discover` 可能登记默认根并保存 inventory；快捷 discover 和 raw `request` 返回同一 runner 能力。

普通 JSON 命令 stdout 只有一个 `ok/data` 或 `ok/error` 对象；拒绝退出非零。成功提交只表示 durable ACK，必须查询 `data.status`。接受后失败保留原任务回执和 code，不变成重新提交理由。`job wait` 超时返回 `wait_timeout` 与原 plan ID，永不重发。`network serve` 明确是前台 NDJSON stream，独立于 App 通道。

旧的 `request`、`submit`、`inspect ID`、`jobs`、`job ID`、`tui`、`launch ID` 继续可用。TUI 的 `apply` 仍是明确批准，无回显口令从真实 TTY 读取；`launch` 只在真实 TTY 打开准确程序与配置根，不接受 prompt 或伪装为 detached mutation job。不存在通用 `--yes` 或 `restore --all`。

完整目标仍包括更多认证与入口适配、系统级网络约束、浏览器持久安装与专用启动、服务迁移闭环、定时漂移、菜单栏、升级卸载与正式签名分发。这些继续属于 Lintel 的范围，不能通过从使用指南中删掉它们就视为整版完成。

路径 preflight 在创建临时目录前持久记录 `migration_probe:{path,status}` 和执行中的 `migration_preflight` 步骤。正常清理确认后 status 为 `removed`；无法确认清理则为 `retained` 并停止正文迁入。worker 中断会保留 `executing` 与原路径；按原 job 查询核对目录，查询不删除或重跑它。App 回执显示尚需核对的检查目录。只核对原任务创建的空文件范围，额外内容保留，不把临时目录当成新配置环境。
