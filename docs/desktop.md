# 桌面使用与界面约定

Lintel 桌面使用 Tauri 2 + React。`src/App.tsx` 管理主机与环境选择、草案、计划和执行回执；`src/api.ts` 将同一 typed core 请求送到本机或当前 SSH 主机。浏览器和本机网络通道使用各自有限的 native commands。界面不合成登录清空、保护成功或网络强约束状态。

## 日常使用

1. 在顶部确认主机与环境。首页是聊天式的结构化操作框：选择环境及“减少外发 / 保持功能”，箭头只生成预览，不调用模型。完整功能取舍在“保护方案”中调整。
2. 对照计划中的“将修改 / 将保留 / 实际步骤”，批准一次执行。执行结果区分已完成、部分完成、已接收和待核对；字段读回不等于运行效果已验证。
3. 首页“环境详情”包含概况、外发与权限、本地状态、启动与来源。完整路径可查看和复制；手动刷新重新读取状态。漂移检查列出差异，可重新应用方案或接受当前基线，不会自动清理。
4. “记录与恢复”保存真实回执，可按环境或文字筛选。可恢复的配置先检查后续编辑；连接中断时用原任务 ID 查询，不能把没收到响应当成未执行。
5. 脱敏支持资料先在本地预览，可复制或保存 JSON。不会自动上传。

草案按主机和环境区分，保存在当前 webview 的 localStorage，修改草案不会直接落盘。任务与恢复记录由所属主机的 core 保存；关闭窗口不删除记录。关闭 Lintel 会停止本机启动的代理通道，已打开的客户端不会自动退出。

## 清理、工作归档与迁入

“清理与重建”提供四条独立路径：

| 路径 | 当前处理范围 |
| --- | --- |
| 新环境重建 | 加密归档所选工作，建立独立配置根并迁入；旧目录与登录保留，结果明确为部分完成。 |
| 修复本地登录 | 核验写入者已停，处理预览中的本地凭据文件；可显式选择官方注销。 |
| 清理并重建 | 先归档工作与已识别的混合客户端状态，处理精确文件，再建立新环境并迁入。 |
| 退役此环境 | 处理精确状态范围并停用本环境的启动入口；原始工作目录保留。重新启用不恢复已删除凭据。 |

后三条路径要求用户先确认目标终端、IDE 和自动重启来源已关闭。core 会复查写入进程，不能归属的 Claude 写入者会阻止清理；不会全局杀进程。界面显示识别到的文件、存在状态和覆盖范围，不读取或展示凭据内容。

“显式检查认证来源”才会运行目标 Claude 的认证状态命令。选择官方注销会调用该环境的官方 `auth logout`，可能联系服务端；共享认证范围或版本 schema 无法验证时拒绝。未选择注销时，Keychain 与目录外认证保持未知，不能将文件处理完成称为完整退出登录。浏览器、Desktop、IDE 与外部 supervisor 的范围单独处理。

工作归档需要至少 12 个字符的口令。口令只在当前表单及请求中临时使用，不写入草案、localStorage 或任务记录。“记录与恢复 → 工作归档”或结果中的“查看工作归档”可解锁文件清单、阅读最多 1 MiB 的单个原始文本，并选择类别迁入另一环境。迁入仍生成计划并单独批准；同名文件冲突拒绝覆盖。指令可放入对应位置；会话与记忆保存在 `lintel-imports` 待用区，不自动启用 hooks/MCP，不宣称旧会话可续聊。

## 浏览器与网络

首页或清理页的“浏览器工作空间”提供配对、WebRTC、站点清理、站点权限、站点代理、站点阻断、临时暂停规则和独立的全 profile HTTP cache 清理。Firefox 不支持的站点权限、站点代理和 CacheStorage 适配明确显示限制。

首次安装可在桌面预览 Native Messaging host 注册：选择浏览器、精确扩展 ID 和已有 host 可执行文件，核对将写入的 manifest，再批准注册。此流程不下载程序、不修改任意目标路径，也不代替 profile 短码配对。开发扩展与 host 的取得方式见 [浏览器指南](browser.md)。

桌面提交只准备请求，用户仍需在目标扩展中核对与批准。站点清理先隔离请求、关闭相关页面并注销 Service Worker，随后显示“等待浏览器重启后继续”；用户重启该浏览器并再次批准后才删除其余存储。已完成的数据删除不可恢复，清理隔离需在扩展内单独解除。可恢复的 WebRTC、权限、代理与阻断设置提供独立恢复预览。提交前保留操作 ID；回复丢失时查询原任务，不自动创建新 ID 重做。

本机环境详情的“外发与权限”包含受控代理通道：输入确切阻止域名和可选 HTTP(S) 上游，启动或停止通道、通过通道打开 Claude、刷新真实连接事件。规则表单是下次启动的草案；当前状态接口不回传运行中的规则与上游，空白草案不能用于判断当前配置，修改前须先停止通道。它不修改系统代理、不解密 TLS，也不覆盖客户端直接 socket、全部 DNS、UDP 或其他进程。当前 SSH 工作空间不会把本机代理标为远端已受保护。

## SSH 工作空间

顶部主机入口或设置中的“主机与 SSH 连接”读取系统 SSH Host alias，保存连接引用，并由用户发起连接。远端需已有 runner；桌面不自动安装、更新软件或改 SSH 配置，不收集密码或私钥。严格 host key 核验失败时应先通过系统 SSH 核对主机。

连接后，环境、计划、清理、归档和记录均来自该主机，使用同一套界面。执行调用固定 `lintel submit`，接受回执与最终完成分别呈现；“查询最新结果”和主机面板的持久提交记录查询原 job。SSH 中断后不自动重新提交 mutation。后台 worker 的实际存活仍受远端 OS/session 生命周期影响；真实主机验收与 synthetic/fake-SSH 证据分开，见 [远程指南](remote.md)。

浏览器配对与本机通道属于这台桌面主机，不随 SSH 目标转移。远端交互式打开 Claude 尚不支持；桌面明确提示使用系统 SSH 进入相应主机与环境，不会向 runner 发送本机启动请求。

## 外观与本地字体

Day / Night / System 直接切换外观，并在当前 webview 记住选择。聊天式首页保留结构化操作框，Clawd 陪伴招呼语。点按角色可发现爱心、热茶、小花、读书、打盹、生日帽、星星和小伙伴八个场景；彩蛋只改变角色，不调用模型或改变配置。眨眼与轻微漂浮尊重系统减少动态效果设置。

Clawd 采用固定 SVG 像素几何，避免 Unicode block 在不同字体中变形。形状对照 [Clawd 形象参考](https://pbs.twimg.com/tweet_video_thumb/G2C8pCLaMAAy2P1.jpg) 与 [Claude Code TUI 实际截图](https://zenn.dev/tutupizizizi/articles/claude-code-clawd-mascot)，自行编写渲染与场景，不下载参考图作为产品资源。Clawd 形象属于 Anthropic；Lintel 是独立工具。

`src/styles.css` 负责颜色、布局与交互样式；`src/Clawd.tsx` 负责角色表现。字体优先使用可选的本地 Anthropic Sans / Serif / Mono，并提供系统 fallback，无远程字体请求。字体文件没有确立再分发许可，因此只放在忽略的 `public/local-fonts/`，不进入 Git。显式本地准备命令：

```sh
cd apps/desktop
node scripts/local-fonts.mjs /absolute/path/to/authorized-font-directory
```

此命令仅读取六个精确字体文件名，不扫描来源项目。**Vite 会把 public 资源包含在本地构建中；含这些字体的 candidate build 不得视为可公开分发包。** 干净 checkout 不含它们，使用系统字体正常工作。正式分发前需要解决字体权利或使用无这些文件的构建。

应用名称与原始图标源是 `src/brand.svg`；Tauri 生成的其他平台 icon 不代表对应平台已验收。

## 开发与验证

```sh
cargo build -p lintel-runner
cd apps/desktop
npm ci
npm run dev:synthetic
npm run typecheck
npm run build
npm run desktop:build
```

同时开发时可用 `LINTEL_FIXTURE_PORT=1422 npm run dev:synthetic`，默认仍是 1420。fixture bridge 的端口、Origin 与 Host 校验使用同一配置。合成模式所有 core 状态与发现都位于临时目录，界面持续标明测试空间；原生浏览器、SSH、认证命令与网络模块不会在网页中伪造成功。新增请求必须进入明确 allowlist；登记路径不能逃出合成 home。

主要桌面尺寸为 1120×760，最低 900×640，可收起侧栏。浏览器渲染不能代替 WebKit/native runtime、真实主机或正式浏览器验收。未完成的安装、发行和全产品能力以 [当前状态](current-state.md) 为准；本文件描述源码接入，不将它等同于正式发布。
