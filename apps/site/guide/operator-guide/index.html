Lintel 操作指南

简体中文（canonical） · English · 文档入口

适用版本：Lintel 0.1.0 Preview / 开发预览。依据当前源码与各模块合同；这是尚未正式发行的操作说明，候选与 runtime 状态见当前状态。首次试用可先读 中文 quickstart / English quickstart。

Lintel 帮你处理具体的 Claude 使用环境：减少指定的可选外发、管理浏览器权限与站点状态、保住工作内容、清理已识别的旧状态，以及在 Mac 上管理 Linux VPS 的同类任务。每次先认准目标，再查看实际变化，最后根据执行回执继续工作或恢复。

当前版本是 0.1.0 Preview，可以按以下路径理解与试用已经接通的能力。正式浏览器安装、真实 Claude 认证、生产 VPS、真实首次使用与非开发者安装仍有验收缺口；相应步骤会说明，不把某个模块的测试结果当作整套使用环境已验证。

如何开始

如果你已经拿到 Lintel 的本地构建 App，打开后从下面的任务表进入。当前仍是开发候选，源码仓库没有把正式签名、公证和非开发者安装验收视为完成。需要自己构建时，按照 README 的本地构建与试用 准备 Rust、Node 和 macOS 构建环境。

Linux 只使用独立 runner/CLI，不需要安装桌面环境。Mac 可以在主机面板批准准备 App 内置的 Linux runner，见第 5 节。独立 CLI 候选提供 macOS arm64、Linux x86_64 与 aarch64 包，取得匹配的候选后不需要 Rust 或 GUI；按 Agent CLI 指南 校验并解包到新版本目录，明确选择 executable，升级保留旧目录与原任务。自行从源码取得 CLI 可用 cargo build -p lintel-runner，二进制在 target/debug/lintel。App 存在不代表终端已经能用 lintel，先确认所使用的二进制路径。

第一次只想熟悉操作，可按 README 启动 dev:synthetic；页面会明确显示测试空间。

当前 App 源码支持简体中文 / English。“设置与模块”里的语言选择默认跟随系统，也可明确选择并在本机记住；本指南使用中文控件名称。语言切换保留当前目标、已填写表单与批准计划，不提交操作。工作原文、文件路径、CLI 命令与原始诊断保持原样。旧本地候选不会随源码更新，具体版本见当前状态。

开始前：认准三个不同的目标

主机决定在哪里执行。顶部“当前操作目标”中，“本机”是当前 Mac；SSH alias 是那台主机的当前登录用户。远程横幅会显示“环境、计划与记录均来自这台主机”。没有任何环境时也能使用顶部主机按钮；侧栏底部“设置与模块”同样提供“主机与 SSH 连接”。

环境主要是登记的 Claude Code 配置目录。它不是项目代码目录，也不是自动隔离全部凭据的账号容器。进入“环境详情 → 概况 → 配置来源与验证范围”可以查看配置目录；“启动与来源”展示程序与配置根。操作前用主机、环境名称和完整路径一起确认目标。

顶栏常显主机和环境名称，主机按钮左侧是没有外框的橙色 >_，光标默认静止。点击后完整配置路径、环境 ID 与客户端路径向下展开，可复制路径；再次点击图标、关闭按钮或 Escape 收起。展开时正文顺势下移，外部点击保留详情，切换目标自动收起；默认收起不影响计划预览中的准确目标核对。

在“设置与模块 → 外观 → 动态效果”分别开关界面动画、Logo 光标慢闪与终端光标慢闪。默认保留 Logo 慢闪、终端静止；三项只在本机保存，系统减少动态始终优先。关闭界面动画保留拖动与主动游戏操作，跑道背景和装饰静止。

浏览器 profile在“浏览器”面板单独选择和授权。它属于运行桌面 App 的这台 Mac；切到 SSH 工作空间不会把本机浏览器或本机代理变成 VPS 的浏览器或网络。一个配置根与一个浏览器 profile 也不会自动建立身份隔离关系。

进入“环境详情 → 关联组件”可检查当前 root 的有限配置来源、静态 CLI 选择、认证位置，以及原任务中的确切服务与处理记录。可填写当前目标主机上的项目绝对目录，再点“刷新组件”核对 project/local/MCP 来源；不会创建目录或启动它们。账号仍显示未知，Desktop／IDE 显示暂不支持，浏览器保持本机独立模块。原服务记录会重新检查 unit；无法核验时保留未知，不把旧暂停结果当作当前状态。点“核对原任务”只查询当前主机上的原 ID。

添加已有环境，或建立空白环境

已有 Claude Code 配置目录：点“添加现有环境”，或侧栏“你的环境”旁的加号；在“登记已有目录”填写“环境名称”和“配置目录完整路径”，再点“添加环境”。登记本身不修改目录中的设置。

想从空白配置目录开始：点侧栏“新建环境”，选择“建立新环境”，输入名称后点“建立环境”。空清单也保留侧栏“新建环境”和首页“添加现有环境”。这个动作创建新配置根，不复制旧登录、设置、hooks 或 MCP；随后仍需为它选择方案、启动 Claude，并按正常流程登录。想带走工作内容，使用第 3 节的“工作保全”。

新目录用于分开本地状态，不能阻止同一用户进程读取其他文件，目录外认证也可能共享。如果界面显示“测试空间 · 操作仅作用于合成数据”，你正在操作独立测试数据；这不是个人环境的扫描结果。普通网页显示“从桌面应用开始”时，没有本机执行通道。

1. 减少外发，然后继续使用 Claude

1.1 选择你愿意接受的功能取舍

  1. 顶部选择目标主机与环境，打开侧栏“保护方案”。首页可点“开始一项任务”→“选择保护方案”进入；需要检查 Remote Control 或逐项选择时，进入完整页面。
  2. 选择“保持功能”“减少外发”或“自定义”。它们先修改草案；草案按主机和环境保存，不会随着切换目标直接应用。
  3. 如果使用 Remote Control，展开“Remote Control 与版本条件”，勾选“保留 Remote Control”，填写“组织是否要求 Trusted Devices？”；不知道就保留“尚未确认”。Lintel 静态读取已安装版本，组织条件来自你的声明，页面的“当前配置条件 / 执行后预计条件”解释本次组合。
  4. 如果页面列出已有冲突值，先决定是否允许解除。普通方案中的“允许在预览中解除……”会把准确字段删除纳入计划；自定义方案用“移除本环境覆盖”表达这一决定。
  5. 点“预览变更”，核对“配置字段”“将保留”“实际步骤”，确认目标后点“批准并执行”。如果结果或影响不合适，点“返回调整”。
方案当前会做什么适合什么时候
保持功能关闭错误回报与质量调查；保持产品指标与主动反馈的当前设置想做较少修改，并保留现有功能取舍
减少外发分别控制产品指标、错误回报、主动反馈与质量调查；按所选 Remote Control 条件处理冲突想明确减少这几类可选外发
自定义对 v5 规则识别的 27 项控制直接选择适用动作，可单项或显式进入批量编辑只想改特定项，或已有自己的取舍

自定义列表由当前 core 的 v5 规则驱动，共 27 个已识别字段：七项隐私开关（产品指标、错误回报、主动反馈、质量调查、跨工具 telemetry 开关、feature-flag 获取和非必要流量总开关）加上 OTel 数据收集、内容记录、exporter／接收端、指标身份属性、调查改走自设 OTel 与 WebFetch 控制。每行直接选择动作；按类别、关键词或“只看待改”筛选。批量编辑单独进入，只提供全部所选项共同适用的动作，隐藏在其他筛选结果中的选择会明确计数；更新的是草案，仍须预览批准。每项“说明与原值”保留完整当前值、来源与数据去向，规则详情保留准确变量、语义、默认值、版本与依赖。原始 API 正文直接选择关闭／内联／本机目录，目录只填路径。逐项撤销与整体撤销可回到未修改状态。不要单凭 0 或 false 判断是否开启：其中部分变量只要是非空字符串就表示关闭；界面会按该变量的规则解释。OTEL_EXPORTER_OTLP_HEADERS 只显示“已遮蔽（凭据）”，其值永不进入普通输出。

“不更改”保留原字段；全部不更改时 App 不启用空预览。“开启”对 DISABLE_* 开关与 default_on 字段都是删除该键。“关闭”按语义写关闭值：隐私开关写 "1"，正向 Boolean 内容开关写 "0"，default_on 写 "false"，exporter 写 "none"，其余自由取值字段只能移除。“移除本环境覆盖”只删除当前 root 的 user settings 字段，其他 shell、项目或组织来源仍可能影响运行。“设为指定值”通过单独的 custom_values 通道给出合法字符串，请求头不接受新值；遮蔽的原接收端可替换为普通地址，新凭据／查询参数地址须从私有高级配置编辑。若移除或替换已有遮蔽值，预览会要求归档口令，先加密保全再修改，恢复使用原任务的所选字段。勾选“保留 Remote Control”不会暗中改写自定义的明确选择。WebFetch 工具控制已作为 CLAUDE_CODE_DISABLE_WEB_FETCH 进入目录；官方更新与 marketplace 自动安装控制仍不在这份编辑器里，用户自设 OTel、通用代理与执行配置不会随这些方案被通配清除。

保存个人默认时，只保存支持的普通意图与有限值；地址、目录和凭据值不会保存。页面显示被省略的字段，本次草案仍保留，不能把保存默认当作执行计划。完整操作和类型区别见桌面自定义保护。

1.2 看读回结果，再打开新会话

执行后看每个步骤的结果及“下一次新启动”要求。“已配置”或“已读回”说明配置值已经处理；当前打开的 Claude 会话不会自动退出或重新读取。 回执中的“打开 Claude”，或“环境详情 → 启动与来源 → 打开 Claude”，会使用这个环境的配置根打开新会话；没有找到 Claude 程序时，按钮不可用，先按你的正常安装流程准备 Claude，再“重新检查”。

macOS 的“已请求启动”表示请求已交给 Terminal。实际登录、会话是否可用以及其他 IDE／服务入口的行为，要在相应入口确认。当前没有把这次设置读回自动升级为实际 Claude 网络效果的验证结果。

需要恢复：到“记录与恢复”找到本次任务，点“查看结果 → 预览恢复”，查看将恢复的准确字段，再“批准并执行”。若字段在任务后被修改，Lintel 会保留后续编辑并提示冲突；先查看来源，按现状重新选择方案。恢复配置不是恢复整个旧目录。

1.3 还想控制经过代理的连接

在本机环境打开“环境详情 → 外发与权限 → 受控通道”。展开“下次启动的配置草案”，选择默认放行或阻止，再按需填写“显式阻止规则”“显式允许规则”和上游 HTTP / HTTPS 代理。

规则每行一个确切主机，后面可用空格与英文逗号列出端口，例如：

example.invalid 443,8443

这是格式示例，不是需要添加的实际规则。省略端口适用于该主机全部端口；不自动匹配子域。显式阻止优先于允许，再看默认动作。没有内置“全部遥测黑名单”；阻止用途混合的 API 主机可能连正常请求一起阻止。

  1. 编辑好草案后点“启动通道”。
  2. 核对“当前生效的通道配置”和实际“本地地址”；它们来自运行中的代理读回。
  3. 点“通过通道打开 Claude”，明确开启带代理上下文的新会话。
  4. 点“刷新连接”查看实际经过通道的连接。没有完成事件不等于没有流量，仍保持的连接可能还未形成完成记录。

改规则或恢复使用：先“停止通道”，等待停止，再编辑草案、启动并重新打开客户端。通道重启可能换端口，旧客户端不会自动采用新地址。原任务已结束时先“清除旧通道”；关闭 Lintel 会停止通道，但不会退出已打开的 Claude。

这条路径约束的是经过代理的连接。直接 socket、UDP、全部 DNS、NO_PROXY、其他进程与客户端自行直连不在这个证明范围。当前没有进程级网络强约束；SSH 工作空间也不能从这里启动远端代理。需要控制浏览器站点时，接着使用下一节的“站点代理”，并填入实际在本机运行的端口。

1.4 查看 IPv4 / IPv6 出口，审阅共享设置

打开“环境详情 → 外发与权限”，或无环境时在首页“查看这台主机的网络”。先展开“本次测试目标与路径”确认 HTTPS 回显端点；点“测试实际出口”查看主机默认与当前通道的四格 IP、耗时和具体失败。没有通道显示未测试；这一次请求不证明其他应用的路由。测试会向目标暴露出口 IP，没有后台公网请求。

Mac 每个服务旁的“预览关闭 IPv6”／“预览仅链路本地”冻结服务身份、完整原配置和前测。核对“宿主共享”、影响和完整配置后，批准写入与同目标复测；可能出现系统授权。它影响此服务的其他应用，退出 App 不撤销。结果分别显示配置步骤和出口前后对照；超时或 IPv4 成功不算防泄漏证明。“查看结果 → 预览恢复”独立批准完整恢复，后续改动冲突会保留。响应丢失时“查询原任务”，不再次提交。

网络或通道变化、重新启动到同端口、目标变化或结果超过五分钟会使前测失效，预览重新测试。严格 IPv4 在受控通道“下次启动的配置草案”里选择，停止／启动后核对读回；只控制 Lintel 建立的目标／上游 socket。Linux 工作空间只读观察和实测，在目标 runner 执行；没有整机关闭按钮。详细边界及 CLI 见 网络指南。

2. 管理浏览器暴露、权限或旧登录

2.1 第一次连接一个 profile

在首页点“浏览器”，展开“连接一个新的 profile”。当前 App 自带扩展与本地连接组件，按页面三步走；普通使用这套 App 内置资源时不需要先下载源码或在终端编译。

第一步：准备并加载扩展。选择“目标浏览器”，点“预览扩展目录”，核对版本、文件范围与目录，再点“批准准备扩展目录”。完成后可以“在 Finder 中打开”或“复制目录路径”；Firefox 显示“复制 manifest 路径”。然后到你真正要操作的 profile 加载：

浏览器在目标 profile 打开按页面选择
Chromechrome://extensions开发者模式 → “加载已解压的扩展 / Load unpacked” → 已准备目录
Edgeedge://extensions开发者模式 → “加载已解压的扩展 / Load unpacked” → 已准备目录
Firefoxabout:debugging#/runtime/this-firefox“Load Temporary Add-on” → 目录内 manifest.json

Chrome / Edge 共用一份稳定的 Chromium 扩展目录，但每个 profile 都要单独加载和配对。Firefox 当前为临时开发加载，退出浏览器会移除扩展；长期签名安装仍未交付。Chrome / Edge 仍需开发者模式，三种正式浏览器的完整非开发者安装旅程尚未验收。

第二步：安装本地连接。将目标 profile 管理页的准确 ID 填入“已安装扩展的 ID”；Firefox 使用页面给出的固定 ID。点“预览本地连接安装”，核对浏览器、授权扩展与注册位置，再“批准安装本地连接”。安装到稳定的当前用户目录，之后移动 App 不会改变注册所指的组件位置。

第三步：核对这份 profile。点“生成配对请求”，复制 App 显示的 12 位“配对短码”。在扩展的“连接桌面应用”中填入“应用内的配对短码”和“这份 profile 的名字”，点“提交配对请求”。回到 App，点“检查配对”，核对名字、实例和两端短码，然后点“短码一致，批准此 profile”。

这一步的完成标准：App 列出所选 profile 的“已配对”，并能看到“最近 20 秒收到轮询”。“当前离线”与“已配对”可以同时成立；前者表示最近没有连接，后者表示持久授权还在。准备目录、组件注册、profile 配对、当前在线是四件事。

连不上或更新时：先检查目标 profile 是否真的加载了扩展、本地连接是否给了准确 ID，再“检查配对”。短码过期就重新“生成配对请求”。出现“身份冲突，需重新配对”时，在需要使用的扩展里点“重复实例冲突：生成新身份重新配对”，重新完成上述配对。App 可预览并批准更新其拥有的扩展目录与本地连接；更新扩展文件后还要在浏览器重新加载。外部目录、被改动的组件或不一致的注册不会被覆盖，先看冲突详情；中断目录准备有“批准继续准备扩展”的独立恢复预览。

当前安装器只提供 Chrome、Edge、Firefox 的固定路径。选择 Chrome 不代表已经安装到 AdsPower，其他 Chromium 浏览器也不能借名称相近推断已支持。

3. 保住工作，或换一个配置环境

3.1 只把工作收好

首页任务选择中的“工作保全”和侧栏“工作保全”进入同一个独立入口。默认“只生成工作归档”：选择个人指令、记忆文本、会话资料，核对元数据概览，再点“预览保全计划”。归档准入会另行完整核对内容；概览不是备份。

“工作容量预检”随所选范围重新检查元数据，列出单文件超过 256 MiB、所选合计超过 1 GiB、文件超过 10,000 或扫描未完整覆盖的阻塞项。受阻时不能点“预览保全计划”；取消类别或排除具体原件后可重新检查。预检通过只是容量判断，正式计划仍会读取并核对全部所选原件。冻结计划另受 16 MiB 持久记录预算约束，深路径与大量完整落点也可能触及上限；预览在保存前明确拒绝，缩小精确选择后可重新预览，不生成不可读计划或接收任务。当前源码沿流式路线完整保全限额内的大文件；超过新限额仍明确拒绝，排除它不会删除或截断原件。旧 runner 可能仍报告更低限额，以本次容量报告为准。

点“按项目／会话／文件选择”会分页读取原件元数据，首次列出时选中当前类别内全部原件。项目组选框选择该路径组内的文件；标准会话与它的 subagents 文件共同列为一个会话组，其他会话按准确路径独立显示，单文件选框可分别调整。“排除超限文件”只取消当前类别中大于该 runner 单文件限额的原件；缺少容量报告时这个按钮不可用。分组不读取正文、不猜实际项目 cwd。搜索只改变显示，搜索结果中的组选框只作用于匹配原件；“选择当前类别全部原件”始终作用于整个当前类别。

文件勾选只保留在当前主机／环境的本次页面；离开页面后重新选择，口令和原件内容不保存到草案。刷新不会加入新文件；已选路径消失时须核对并移除失效选择，不能把缺失当通过。扫描不完整或 runner 不支持文件清单时无法进入精确批准；可显式改回整类保留再预览。精确预览显示“批准中的原件范围”，归档和新环境准备使用同一冻结清单；执行前选中内容改变会拒绝，未选文件改变不会扩大清单。没有权限、链接、特殊文件或扫描预算不足都不能当作空目录或完整覆盖。

“另存加密包的完整路径”可留空，归档保存在 Lintel 的 state；填写时须是当前目标主机上的完整文件路径，父目录已经存在、无符号链接且文件名尚未使用。已有文件不覆盖。预览中能查看冻结的目的地与文件数量；执行还会核对同一个目录对象，目录被替换或更换挂载时须重新预览。升级前没有冻结目录身份的旧显式输出计划也须重新预览，已完成的原任务仍可查询。

设置至少 12 个字符的归档口令并再输入一次，核对计划后“批准并执行”。自己保管口令；Lintel 不保存，遗失后无法解锁。成功回执为“完成”，给出工作归档路径、所选类别和文件数。此任务只生成加密工作包，不建立环境、不注销、不修改原 settings 或工作文件。

3.2 保全后准备新环境

在同一页选择“保全并准备新环境”，选择工作类别，按需填写新环境名称。预览显示加密归档、创建配置根、选择性迁入的实际顺序，以及已冻结的新环境 ID、完整配置 root 和逐文件落点。规划不会创建该 root；若批准前目录被外部占用或父目录身份改变，须重新预览。批准后先生成归档，再建立新根并读回迁入文件；成功属于该任务自己的“完成”。

本轮 App 默认将所有选中内容准备为待用资料；只有明确勾选“启用已审阅的个人指令”才将 CLAUDE.md 放在客户端会发现的根指令位置。旧 raw protocol-1 caller 保留原来的指令默认。projects 中的记忆 Markdown 与会话 JSONL 进入 lintel-imports 待用区。已有待用区的参考指令、记忆和会话可再次保全而不产生重复嵌套；活跃与参考指令并存时分别保留，重名参考仍按个人指令分类，不自动启用。活跃工作与待用区出现同名内容或文件／目录冲突时，内容都保留，重复项在待用区加 lintel-N- 文件名前缀；独立包迁入的计划按同一规则冻结实际目标，已有目标文件仍不覆盖。批准执行时会在目标文件系统的临时空文件目录复核整批名称；例如 Linux 包的大小写不同文件在 macOS 被视为同名时，会在创建新环境或迁入正文前整批拒绝，显示 migration_path_conflict。原包仍可阅读；整理源内容重新归档或选择区分这些名称的文件系统。不复制凭据、settings、hooks、MCP 或插件，不宣称可直接续聊旧会话。旧目录、旧登录与原运行进程保留，它们是覆盖范围的说明。

结果页可“为新环境选择保护方案”，随后在准确配置根正常登录、启动并核验。如果原环境由 systemd service 运行，创建新根不会改绑 service；原 service 仍指向旧环境。恢复旧服务、调整新环境的启动配置是分别核对的动作。

旧版 plan_reset / TUI 的“新环境重建”仍为已有调用者保留，历史回执继续显示“部分完成”（旧状态尚未清理），不会重写为新任务状态。App 的工作保全使用新任务语义。

迁入计划中的“这些文件，会放在这里”列出本次选中文件的包内来源和最终完整位置（旧计划使用相对上方配置 root 的路径）。同名文件的新名称已在这里确定；展开可检查逐文件摘要与加密包身份。核对这份清单后再批准，解锁包的文件列表本身不是最终落点。

侧栏“会话与资料”、工作保全页“阅读或迁入已有工作包”和“记录与恢复 → 查看归档”进入同一阅读工作区。任务回执的“查看工作归档”会选中当前包。

  2. 输入口令，点“解锁并查看”；核对清单、类别、容量，点击文件按需阅读。“结构化阅读”显示已识别的角色、时间、正文与工具记录，“原始文本”保留未知格式回退；普通文本文件只启用原始文本，旧消息响应缺少结构化记录时显示限制并可返回原始文本；“下一页”显示明确字节位置。每页有界，完整原文件仍在包中；文件数不等于可恢复会话数。 首次读取立即显示“正在核验工作包并读取这一页”；翻页期间标明下方仍是上一页，新页完成后才替换。顶部状态持续显示正在核验的主机与操作，以及同一队列中的等待请求。离开页面会清除页面中的口令、正文和选择，但已提交的读取仍继续；等待期间其他同队列请求要等它结束。迟到结果不会恢复已离开的资料页。
  3. 在“准备到另一个配置环境”选择已登记的目标环境和类别，单独决定是否启用已审阅的个人指令，点“预览迁入计划”。已有目标目录须属于当前执行器用户，并允许访问／写入；已知归属或权限障碍会在整批正文写入前拒绝，Lintel 不自动修改权限。批准前核对目标根、文件清单和冻结包。

工作归档与状态备份的路径也可能只是发布意图。回执会将未读回的路径标为“待核对”；只有工作归档读回完成才提供查看按钮和任务归档选择。原路径继续保留，可按原任务核对，或将确认存在的包作为独立文件检查；不会因查询重跑发布。新文件使用系统原子不覆盖 rename；目标文件系统／内核不支持时返回 atomic_publication_unsupported，已有内容保留。

口令只驻留当前面板或待批准计划的临时内存；关闭后清除。解锁不会运行归档内容。独立工作包保持 lintel.work/1 兼容，旧合法包和历史任务来源仍可读取。

3.4 同机与 Mac ↔ VPS 的迁入

同机直接使用已有任务或独立包路径。跨主机先把加密包文件通过你已经信任的系统 SSH/SFTP/scp 或可移动存储带到目标机器，再切到该主机，用那里的绝对路径解锁和计划迁入；不要传整个 Lintel state、凭据或明文请求。App 不自动搬运文件，也不把本机路径映射到 VPS。

例如明确确认系统 SSH alias 与目标目录后，可以从系统终端使用：

scp -o StrictHostKeyChecking=yes /absolute/path/work-package.age approved-alias:/absolute/destination/work-package.age

选择未使用的目标文件名并独立检查 transfer 结果；这是系统文件传输，执行与覆盖规则由该工具拥有，不属于 Lintel 的冻结 import 计划。随后在目标执行器读取、校验、选择类别和批准 import。CLI 的无明文落盘输入方式见 Agent 指南。本机 browser / proxy 不随工作包迁移。

大文件或归档失败：当前源码准入是单文件 256 MiB、合计 1 GiB、10,000 文件，另有扫描条目与时间预算。超限会明确拒绝，不把截断结果称为完整归档；保留原资料，重新选择类别或有限原件，可单独排除超限会话。中途失败先看原任务的已完成步骤和产物，不重新创建包或重复迁入。执行中的归档步骤会记录目的地；路径存在不等于写后核验已完成，包实际存在时可用原任务解锁，核对原回执与产物。

大文件仍使用兼容的 lintel.work/1 加密包。每次解锁、清单、阅读或迁入都会完整认证包内所有文件和尾部，再从私有暂存中取有限页面；只选某个类别也不跳过其他内容的校验。因此大包的一页阅读仍会花费完整解密与核验时间。Lintel state 所在磁盘需要容纳全部展开原件；另有目标磁盘上的密文或逐文件发布临时空间。正常结束和返回错误会清除当前操作的解密暂存；进程被强制结束时可能留下 state 下 .lintel-work-stage-* 的私有暂存，Lintel 不自动扫除历史目录。不要把临时空间当作又一份长期备份。 远端预览／阅读仍受单次 SSH 的 60 秒及 2 MiB 响应边界限制；较慢的大包可能返回 transport_unknown，这不证明包损坏。可在目标机用独立 CLI 核对；若原执行已接受，只查询原 ID，不重复提交。

reader 另设有限 JSON 元数据／密文预算及 scrypt log N ≤ 20 的成本上限；过高成本包明确拒绝，不降低其加密强度。age 的 KDF 自身需要内存，流式正文不代表零内存占用。旧版本的 reader 可能拒绝新容量的大包；先用匹配的新版本核对。

“状态备份”与“工作归档”是不同产物：清理时保存的混合客户端状态备份不支持自动迁入。工作包不包含全部认证、执行配置或云端资料，也没有“恢复全部”。

回执中的状态备份路径会在写入前保存；有路径不等于备份已完成。以对应步骤的写后读回结果为准，中断时查询原任务并核对该目标，勿重复提交清理。

CLI 状态绑定只证明观察字段一致；它不认证来源，也不能识别只发生在 Keychain 内且没有反映到状态输出的同账号 token 世代变化，最终复查到 logout 之间仍没有覆盖所有外部写入者的原子保证。真实 Keychain、文件 fallback 与服务端撤销仍需独立验收。

遇到冲突：如果预览后文件、程序或登录来源改变，重新核对当前范围并生成新预览；如果已经提交且结果不确定，先按原任务 ID 查询。操作中发现新文件或旧状态重新出现，会保留新状态并停止后续动作，不自动再次删除。若回执记录隔离目录，保留它并按所列路径核对，不要把恢复等同于直接覆盖当前新文件。

需要恢复：可恢复的配置走原任务“预览恢复”；删除的凭据和浏览器数据没有自动恢复。退役后可回“环境”页点“重新启用环境”，恢复登记与启动资格，但不会复原已删凭据；必要时重新登录。已暂停服务的恢复仍是独立任务，不会因为清理完成或关闭窗口自动发生。

当前完整 Desktop、IDE、macOS 服务及其他 supervisor 的定位与停写尚未完成。它们出现在你的真实使用链路时，需要独立核对；不要把 Claude Code 的已识别文件处理结果当成这些入口已经清场。

5. 从 Mac 管理 VPS 与后台服务

5.1 连接正确的 SSH 用户

打开“主机与 SSH 连接”。先展开“连接前需要什么？”，确认已有可用的系统 SSH Host alias、可信的主机身份记录，以及 OpenSSH 或系统 agent 已能提供密钥。Lintel 的非交互连接不会弹出密码输入框。

  1. 在“SSH Host alias”选择或填写已有别名，点“登记主机”。这里填写 alias，例如 writing-server，不是 user@host、命令或 SSH 参数。
  2. 已有可用 PATH runner 时，点“连接并管理”。只有 Claude Code、没有 Lintel runner 的主机不能直接管理。
  3. 需要准备 runner 时，点“检查并准备运行器”。核对系统、架构、SSH 用户、版本、大小，再展开“查看安装与校验详情”。
  4. 确认准确目标后点“批准并安装这个运行器”。App 上传自身携带的静态 runner，完成文件、权限与实际能力核验后显示“运行器已就绪”。
  5. 点“连接并管理”，进入远程工作空间；再登记或选择该用户的 Claude 配置环境。

安装范围属于当前 SSH 登录用户。如果 Claude 由另一个用户运行，使用那个用户的 alias；以 root 登录不等于自动管理每个普通用户环境。当前支持 Linux x86_64 / arm64 的候选资源；App 缺包或目标条件不满足时会给出限制。准备过程不修改 PATH、shell 启动文件、sshd、Claude 配置，也不在 VPS 上编译或自动 sudo。

旧安装显示“已核实 · 当前绑定已更新”时，表示当前运行器继续保持后来选定的版本；核对旧记录不会切回去。“已核实 · 尚未绑定”的历史记录需要重新预览与批准才能启用。

安装中断：从“安装记录”点“核对原安装”，确认原目标和同一文件。它只核验原安装，不重新上传。也可直接点错误提示下的“核对这份未确认安装”；原结果未确认前，已经提前生成的另一份安装预览同样不能上传。不要通过移除并重新登记主机绕过未核对记录。运行器版本更新后，有版本绑定的旧任务继续使用其冻结的旧 runner；较早的无绑定记录保留原兼容路径。

连接失败：按错误中的阶段和具体原因排查。需要时打开“查看本次错误输出”，或“复制排查摘要”；修复后点“重新检查连接”。host key 未知或变化时，先用你的系统 SSH 流程核对主机身份，Lintel 不自动忽略。若已经提交执行，连接恢复后查询原任务；重连成功后也不要重复提交原操作。

5.2 执行任务、断线查询与打开会话

连接后，保护方案、清理、工作归档与记录使用同一套界面，计划由远端 core 针对远端状态生成。确认框会持续显示所属 alias。

远端任务先持久接收，再在后台执行。“已接收”表明原任务已记下，不等于修改已经完成。回执会显示实际托管方式：符合当前主机条件时使用 systemd 单任务后台服务；其他条件下显示“断线后的继续执行未获保证”。这些托管事实不构成重启后续跑承诺。

断线或 App 重开后：

  1. 打开“主机与 SSH 连接 → 持久提交记录”。
  2. 找到原 alias 和原任务 ID，点“查询原任务”。
  3. 点“查看完整回执与恢复”，进入原主机、原环境的完整结果。
  4. 若仍“已接收 / 执行中 / 待核对”，继续核对原结果；只有看到明确的逐步结果后，才决定恢复或另建新的后续计划。

要开始交互使用，从“环境详情 → 启动与来源 → 打开 Claude”，或结束状态的任务回执点“打开 Claude”。App 请求 macOS Terminal 通过同一严格 SSH alias、绑定 runner 和真实终端启动选定环境，不发送 prompt。这个交互会话随 SSH 连接结束，与后台变更任务不同。 “已请求启动”以后，去 Terminal 确认真实会话。

隔离 OpenSSH 与真实 disposable Linux VM 已验证符合既有条件的 system/user manager 在真实 PAM logout 后继续并完成原任务，以及 reboot 后按原 ID 核对；不符合条件的 setsid 路径受限。生产 VPS、aarch64 runtime 与所有普通用户 manager 场景仍未验收。遇到中断只核对原任务，Lintel 不自动启用 linger、改登录策略或换一种启动方式再发一次。

5.3 暂停一个明确绑定的 systemd 服务

在远端“清理与重建”选择“修复本地登录”“清理并重建”或“退役此环境”，展开“目标后台服务”。单纯“工作保全”不显示这个面板。

  1. “管理器”选“当前用户”，或在 runner 已是 root 时选“系统服务（需 root）”。
  2. 填写完整“服务 unit”，如 example.service，点“检查服务”。不接受通配符或命令。
  3. 核对“配置绑定”是否就是当前 root，以及自动重启、主进程和触发来源。
  4. 点“预览暂停服务”，查看准确 unit、原状态与持久暂停项，然后“批准并执行”。
  5. 核对暂停结果，再返回“清理与重建”；仍需关闭该环境的交互终端、IDE 和其他写入者。

暂停会阻止这个服务重新启动，并读取实际服务状态与 cgroup 证据。它持续到你独立批准恢复，不因关闭 App、SSH 断开或窗口关闭自动撤销。适配器只接受能明确绑定配置根的有限 systemd 服务，无法确认绑定、存在可能影响邻居的关系或使用不支持来源时，会拒绝而不扩大范围。

恢复：在暂停回执点“预览恢复服务”，或重新“检查服务”后选同名按钮。它核对原 unit 与暂停项，只移除原任务拥有的暂停项；原先运行的服务才重新启动，原先停止的保持停止。外部编辑冲突会保留现状与暂停项，先核对来源，不删除记录后强行重试。

清理并重建后的服务选择：新环境产生新 root，当前流程不会自动将原 service 改绑到新 root。“恢复服务”恢复的是原服务与原绑定。决定继续旧服务还是配置一个指向新环境的服务之前，先看清回执和绑定；当前没有把“重建客户端 → 改绑服务 → 新环境验证”做成自动完成的闭环。

6. 检查变化、恢复配置、找回结果

6.1 手动检查漂移

在“环境”页展开“环境详情”，找到“上次之后，有什么变化？”，点“检查变化”。结果列出已管理设置相对基线的差异：

  • 想恢复之前的取舍，点“重新应用方案”，回到保护方案重新预览并批准。
  • 接受现在的值，点“接受当前值”；这会把当前值记为此环境的基线，不会把设置重新改回去。
  • 没有差异，表示当前检查范围内没有待处理变化，不是全机、浏览器或网络都已受控。

当前没有已启用的后台定时漂移、菜单栏快速动作或自动规则更新。软件升级、切换入口或外部工具改过设置后，主动“重新检查”和“检查变化”。

6.2 按任务记录恢复，不恢复整套旧状态

“记录与恢复”可按“全部环境 / 当前环境 / 待处理”筛选，或搜索“记录、环境或任务 ID”。“全部环境”仍属于当前主机。点“查看结果”阅读逐步回执，再选可用的后续动作。

6.5 管理本地数据、身份与配置，然后用配方连续操作

这一小节把单项目标收成一条常见旅程：选环境 → 关闭不需要的内容记录 → 保全并清理选中残留 → 执行并复查 → 继续启动使用。常规同目标任务一份完整预览、一次批准；中间的备份、修改、校验由工具完成。

本地数据与身份：“环境详情 → 本地状态 → 本地数据与身份”列出已知位置表（加你明确加入、最多 8 个的绝对目录）中的工作内容、运行残留、身份材料与插件配置，只读路径、类别、大小和时间，可按类别、项目片段、时间与大小筛选并分页。默认只勾选可清理的运行残留；工作内容需另选，unclassified 位置不默认删除，身份位置只报存在性、不进入清理目标。选中后可“仅精确清理”或“归档并清理”，后者先写独立 lintel.residue/1 加密备份再删除。选中的原件若属于工作内容，需要显式“允许选择工作原件进行删除”或改用工作保全。身份区默认遮蔽，点“显示原始值”才在本页内存读取 userID 并可复制，不写入 localStorage、普通快照、支持导出或日志；“重置本地客户端标识”先将完整原始客户端状态与明确选中的备份加密保全，再移除 userID 并逐值保留其他键，不顺带注销或清凭据。已有的 lintel.residue/1 备份可用“读取与恢复残留备份”独立解锁并按包内原路径恢复，已有文件不覆盖，不作为工作 import。

可选：一份计划、一次批准。 本地数据面板可勾选“同时减少正文记录”“同时重置本地客户端标识”，把内容记录关闭、标识重置与所选残留合成一份 client_workflow 清单；同一文件不能同时属于配置、身份和残留步骤。执行仍是一次预览、一次批准，执行中各步骤的成功与跳过分别记录。

变化与对照：“环境详情 → 变化与对照”的“变化与对照”保存脱敏语义快照并比较两份快照或两个已登记环境，可按新增／删除／修改筛选。逐项“接受所选当前值”只形成比较基线，不是恢复来源；想恢复原值仍用原任务或加密备份。“将普通配置应用到目标环境”只复制已识别普通字段并显示目标 diff，登录凭据与本地身份不随普通配置方案复制。轻量变化检查在打开环境或经 Lintel 启动时只读有限配置来源，有变化或读取不完整时留提示；没有常驻 watcher。

高级配置编辑：对明确选择的 user／project-local JSON 配置提供严格校验、逐字段遮蔽 diff 与原任务恢复。写入复用现有计划链：批准前复查摘要，写前生成 age 加密 lintel.config/1 备份，发布后读回；恢复只改原任务字段并保留后续无关编辑，凭据值（如 OTEL_EXPORTER_OTLP_HEADERS、带凭据的接收端 URL）与未识别键默认遮蔽。组织强制配置保留其权限边界。

快捷配方：“保护方案”和“清理重建”页内提供三条可编辑配方。“减少正文记录”关闭已知内容记录字段并保留指标；“清理运行残留”使用本地数据视图当前选中的残留；“保住工作并重建”归档并迁入选中的工作内容。配方只保存方案与有限字段选择等非秘密意图，切换主机或环境后草稿与原任务绑定不漂移；每次运行都按当前主机与环境重新生成计划，绝不重放旧审批。保存了不同意图的个人默认（例如开启内容记录）会改按实际意图标注为“个人默认”，不沿用内置名称承诺。

在 App 交给 Agent

侧栏“终端与 Agent”，以及环境、计划、回执中的“交给 Agent”携带当时的准确目标。按“选定 CLI → 核对执行上下文 → 审阅 → 复制”进行：输入实际 executable 完整路径，点“核对 CLI 与上下文”。检查只执行固定静态命令，有限时间／输出，无 shell、不发现个人目录、不初始化 state、不启动 Claude。

核对 product、协议、平台、候选身份以及 App／CLI 的 HOME、state、uid/euid。sidecar 缺失显示候选未知；checksum 匹配不等于来源认证。App 有原环境、计划或任务时必须沿用 App state 与原用户，保留 ID 与 runner 绑定；Lintel 不迁移 state 或修改 PATH。选定 CLI 自己的 state 只适用于没有原对象的独立接口核对。

操作交接包包含任务、目标、执行器、state、原 ID/hash、已观察状态和准确查询命令。accepted／uncertain 指向原 ID 查询，没有新提交。它不含口令、工作正文、完整 state 或凭据；复制不会产生新的执行授权。需要正文时使用第 3.5 节独立选择和审阅。取得 CLI 与可复制命令见Agent 指南。

App 本地短帮助随构建，帮助页显示版本与 docs revision。已知 clean revision 的完整指南链接锁定该提交；dirty／未知构建明确显示“最新开发说明”，不冒充候选对应文档。

只有终端时：独立 CLI

CLI 不依赖 GUI 启动或 Tauri。候选包校验／独立版本安装与升级、源码构建、机器可读 schema、秘密 stdin、批准、原任务 wait、恢复、browser/SSH/network 的有限适配见 Agent CLI 指南。候选是明确选择的本地版本，未提供自动更新或正式签名发行。

lintel version --json
lintel capabilities --json
lintel describe plan_policy --json
lintel env list --json
lintel policy plan --environment <environment-id> --preset reduce --no-keep-remote-control
lintel plan show <returned-plan-id>
lintel job submit --plan <returned-plan-id> --approval <returned-plan-hash>
lintel job wait <returned-plan-id> --timeout 30s
lintel restore plan --job <original-job-id>

静态 version/capabilities/schema/describe 不发现个人目录、不运行 Claude，也不初始化 state。显式 env list / discover 可能登记默认根并保存 inventory；快捷 discover 和 raw request 返回同一 runner 能力。

普通 JSON 命令 stdout 只有一个 ok/data 或 ok/error 对象；拒绝退出非零。成功提交只表示 durable ACK，必须查询 data.status。接受后失败保留原任务回执和 code，不变成重新提交理由。job wait 超时返回 wait_timeout 与原 plan ID，永不重发。network serve 明确是前台 NDJSON stream，独立于 App 通道。

旧的 request、submit、inspect ID、jobs、job ID、tui、launch ID 继续可用。TUI 的 apply 仍是明确批准，无回显口令从真实 TTY 读取；launch 只在真实 TTY 打开准确程序与配置根，不接受 prompt 或伪装为 detached mutation job。不存在通用 --yes 或 restore --all。
