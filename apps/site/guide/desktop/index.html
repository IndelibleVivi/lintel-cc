桌面使用与界面约定

简体中文（canonical） · English · 文档入口

Lintel 桌面使用 Tauri 2 + React。src/App.tsx 管理主机与环境选择、草案、计划和执行回执；src/api.ts 将同一 typed core 请求送到本机或当前 SSH 主机。浏览器和本机网络通道使用各自有限的 native commands。界面不合成登录清空、保护成功或网络强约束状态。

完整从目标到结果的说明见 operator-guide.md；App 帮助提供六条目标路径、关键场景指南与 Agent CLI 入口。链接仍只打开固定命名 HTTPS 文档。

日常使用

  1. 在顶部确认主机与环境。首页默认是安静的伙伴空间，点击“开始一项任务”展开六类目标；当前目标持续显示，空环境也有主机、创建／登记、浏览器与 CLI 入口。选择环境后在专业工作区生成预览，不调用模型。完整功能取舍在“保护方案”中调整：会静态识别已安装产品版本，逐项解释变量值，并显示 Remote Control 的版本／Trusted Devices 条件。组织条件只记录用户声明，不读取账号；未知信息不能当成可用证明。已有冲突值需要明确勾选解除，准确删除项进入批准预览。
  2. 对照计划中的“将修改 / 将保留 / 实际步骤”，批准一次执行。执行结果区分已完成、部分完成、已接收和待核对；字段读回不等于运行效果已验证。
  3. 首页旁的“环境详情”展开概况、外发与权限、本地状态、启动与来源、关联组件及检查时间。首页任务选择中的“工作保全”与侧栏同名入口进入同一独立任务。侧栏“会话与资料”拥有独立阅读布局，“终端与 Agent”核对执行器并交接操作元数据。保护方案、清理与重建、记录与恢复从侧栏进入。完整路径可查看和复制；手动刷新重新读取状态。漂移检查列出差异，可重新应用方案或接受当前基线，不会自动清理。
  4. “记录与恢复”保存真实回执，可按环境或文字筛选。可恢复的配置先检查后续编辑；连接中断时用原任务 ID 查询，不能把没收到响应当成未执行。
  5. 脱敏支持资料先在本地预览，可复制或保存 JSON。不会自动上传。

草案按主机和环境区分，保存在当前 webview 的 localStorage，修改草案不会直接落盘。任务与恢复记录由所属主机的 core 保存；关闭窗口不删除记录。关闭 Lintel 会停止本机启动的代理通道，已打开的客户端不会自动退出。

顶栏常显主机、环境、语言和三枚外观图标。“本机”／主机名称左侧只放橙色 >_，没有外框或附加箭头，光标默认静止；点击后“当前操作目标”沿下方展开，正文顺势下移，没有悬浮卡片。可核对主机、环境名称、完整配置目录、环境 ID 与已识别的客户端路径，并复制路径。完整路径默认收起；再次点击图标、关闭按钮或 Escape 收起，Escape 返回图标；已打开的 modal 优先接收 Escape。外部点击和焦点离开保留展开，避免正文突然重排；切换主机或环境自动收起。“外观 → 动态效果”可独立控制界面动画、Logo 光标慢闪与终端光标慢闪；默认界面动画／Logo 慢闪开启、终端光标静止，只保存本机偏好。系统 reduced motion 优先于三个开关，关闭界面动画不改变单独的光标选择；拖动和主动开始的游戏保留操作反馈，跑道背景／粒子／装饰步态静止。此展开只改变界面；批准预览仍完整展示冻结目标与落点。

界面语言

App 支持简体中文 / English，默认跟随系统。顶部入口只显示实际界面语言 EN／中文 与小箭头；点开原生选择菜单后才显示「跟随系统／简体中文／English」，避免把语言模式与旁边的外观 System 混淆。跟随系统时入口仍显示当前实际语言，设置中显示完整的选择方式、标签与说明，键盘焦点保持可见。顶部语言选择器与“设置与模块”提供手动选择，并只在当前 webview 的本机存储中保存。macOS native command app_preferred_languages 从 CoreFoundation 只读取得最多 8 个有界语言标识，bundle 的 Info.plist 声明 en / zh-Hans；网页／合成运行使用浏览器语言作为 fallback。不支持的语言回到 English。app_set_language 只接受 en / zh-CN，同步普通 macOS 菜单的文字，保留原生动作与快捷键。此路径不读取 Claude 配置、账号或工作内容，不改动系统语言。

切换立即更新界面和 html.lang，保留当前页面、目标、草案、输入和已冻结的计划／hash，不重新提交或批准操作。Clawd 继续使用这次打开选中的同一句问候及对应翻译，不重新随机、不重复消费日期彩蛋；日期与数字按当前 locale 格式化。翻译随 App 打包，无网络请求。core 已知的静态标题、步骤、保留范围与能力说明通过 i18n-presentation.ts 在显示层投影；未知／旧 runner 文案原样显示，原 plan 与 receipt 不改写。UI 自有错误保留文案 key，在当前 locale 下显示。用户命名、路径、命令、设置字段、任务 ID、工作原文与原始诊断不作语言改写。CLI、扩展 popup、官网及外链文档保留各自语言；候选是否已包含本次源码更新见当前状态。

自定义保护

“保护方案”的“自定义”按隐私与外发、内容记录、OTel 与接收端、身份与功能分组展示当前 v5 规则识别的 27 项控制。每行直接选择操作，名称旁显示本环境配置与“待预览”状态；普通模式没有批量勾选框。可搜索、按类别筛选或只看待改项，撤销单项或全部草案；没有待改项或仍有必填值时，预览不可用。原值、来源与接收端／落盘位置在“说明与原值”中展开，完整语义、默认值、版本与依赖再收在规则详情中。当前配置读回与配方／个人默认有独立的按需入口，不重复堆在编辑列表里。

批量修改先点“批量编辑”，勾选具体项或“选择当前结果”，再选共同适用的动作并点“更新 N 项草案”。筛选不会偷偷丢掉其他选择，面板标明有多少项在当前结果之外。批量只更新草案，一次完整地送入后续预览；“结束批量选择”退出选择状态，已经更新的草案仍保留，可用逐项或整体撤销。

  • 不更改： 保留原字段。全部不更改时，App 不启用空预览。
  • 开启／关闭： 表示功能或信号的方向，不能把变量的 0／false 当作通用开关。DISABLE_* 类关闭写 "1"、开启移除关闭值；正向 Boolean 关闭写 "0"、开启写 "1"；default_on 关闭写 "false"、开启通过删除恢复默认；exporter 关闭写 "none"。WebFetch 使用正向工具名称呈现。
  • 移除本环境覆盖： 删除当前配置根 user settings 的准确字段，其他来源或默认值可能重新生效；它不保证功能关闭。地址、请求头和长度上限没有独立的“关闭”值，因此只显示这一种移除操作。旧草案的等价动作仍保留兼容。
  • 填写取值： 地址、数字、exporter 以及高级原始变量值有各自的编辑入口；非法或缺失值在对应行提示。OTEL_EXPORTER_OTLP_HEADERS 不接受新值；已有凭据接收端保持遮蔽，但可用空输入替换成不含凭据的地址。含凭据或查询材料的新地址必须从“环境详情 → 变化与对照”的私有高级配置编辑，不能进入普通计划输出。

“原始 API 正文记录”直接选择关闭、内联记录或写入本机目录。目录模式只填写完整路径，App 生成 core 所需的 file:<目录>；内联模式不需要填写实现字符串。两者的数据去向不同，完整原值与细则仍可展开核对。本机文件不代表已上传。

预览显示准确修改和预计 Remote Control 条件；“Remote Control 与版本条件”中的保留选项不会改写明确的自定义选择。移除或替换已有遮蔽内容时，预览要求口令并先加密保全，恢复仍使用原任务与所选字段。切换 preset 保留自定义草案；主机与环境分别隔离。保存个人默认只保存支持的普通意图／有限值，不保存地址、目录和凭据值；若有省略，显示具体字段，当前草案不被替换，存储失败也明确提示。下次应用仍生成新计划。旧 runner 未返回 supported_presets: custom 时，保留草案并禁用自定义预览；更新 runner 后重新检查。规则升级后旧待执行计划须重新预览，原任务与恢复保留。

同一表单可用于本机与 SSH 环境；远端仍经固定 JSON 请求和 durable submit。WebFetch 工具控制已作为 CLAUDE_CODE_DISABLE_WEB_FETCH 进入目录；官方更新与 marketplace 自动安装控制仍不在这份编辑器里，见 core 的准确范围。

清理、工作归档与迁入

“关联组件”独立读取有限来源，在 settings 内容损坏时仍可查看；只展示 hooks/MCP 是否声明，不展示命令或凭据。原任务与当前观察分开，主机切换会丢弃晚到结果；旧 runner 缺少操作时显示明确错误。容量预检随工作类别刷新；发现阻塞项时禁用保全预览，分类取消后重新检查，不删除或截断原件。

“工作保全”提供只生成加密包、保全并准备新根两个目标；两者成功为完成，旧登录保留。工作归档面板可从任务或独立绝对路径打开，清单和选择性迁入不依赖源机器 state；密文文件的跨主机传输由用户明确使用系统工具完成。详细步骤见 人类操作指南。

WorkFileSelection.tsx 在同一工作页提供项目路径组、会话文件组和单文件选择，加载有界 metadata 页并拒绝缺页／变动，不读取会话正文。文件搜索只改变显示，超限文件可明确排除；选中路径不持久保存到草案，新出现文件不自动加入。WorkCapacity 使用同一选择重新预检，PlanReview 展示批准中的原件范围与已有冻结落点；runner 未确认 exact selection 时不开放批准。旧 runner 清单错误明确显示，不隐式变回整类。

“清理与重建”提供三条独立路径：

路径当前处理范围
修复本地登录核验写入者已停，处理预览中的本地凭据文件；可显式选择官方注销。
清理并重建先归档工作与混合客户端状态、建立新根并迁入，再官方注销（若选）与精确文件移除。
退役此环境处理精确状态范围并停用本环境的启动入口；原始工作目录保留。重新启用不恢复已删除凭据。

后三条路径要求用户先确认目标终端、IDE 和自动重启来源已关闭。core 会复查写入进程，不能归属的 Claude 写入者会阻止清理；不会全局杀进程。界面显示识别到的文件、存在状态和覆盖范围，不读取或展示凭据内容。

“已识别的本地范围”先显示类别、文件名与存在状态，点击文件行展开准确完整路径；“刷新范围”重新观察。记录页的“会话启动记录”可粘贴原启动或续聊请求 ID，只读核对原结果，不重新启动会话或复制工作正文。

“显式检查认证来源”才会运行目标 Claude 的认证状态命令。选择官方注销会调用该环境的官方 auth logout，可能联系服务端；共享认证范围或版本 schema 无法验证时拒绝。未选择注销时，Keychain 与目录外认证保持未知，不能将文件处理完成称为完整退出登录。浏览器、Desktop、IDE 与外部 supervisor 的范围单独处理。

工作归档需要至少 12 个字符的口令。口令只在当前表单及请求中临时使用，不写入草案、localStorage 或任务记录。“记录与恢复 → 工作归档”或结果中的“查看工作归档”可解锁文件清单、按需分页阅读结构化消息、工具与未知记录及原始文本，并选择类别迁入另一环境。迁入仍生成计划并单独批准；同名文件冲突拒绝覆盖。默认资料保存在参考区；明确勾选“启用已审阅的个人指令”才放入客户端发现的指令位置。会话与记忆保存在 lintel-imports 待用区，不自动启用 hooks/MCP，不宣称旧会话可续聊。

启动与原生续聊预览共用“启动来源核对”：root、明确 cwd 与有限上级候选、managed 文件／drop-ins，以及 hooks／MCP／helper／plugin 是否有声明。存在项和访问受限项直接显示，已检查未发现项可展开；没有提供该清单的旧 runner 不能在 App 批准新启动。认证文件与共享 profile 只查看元数据，Keychain、账号、Terminal shell、worktree 主 checkout 与实际加载保持未核验。选择前后来源变化需要新预览；原启动请求仍只查询。归档与迁入不自动启动或登录。

启动请求报错时保留原 ID，先核对原启动请求。只有 core 读回未尝试的原计划时才能“重新核对启动目标”，保留稿件与 cwd，生成新 ID 并撤回旧审阅；已有 intent／结果仍只查询。

本地数据、身份、变化与配方

“环境详情 → 本地状态”的“本地数据与身份”面板按有限已知位置表（加你在计划中明确加入、最多 8 个的绝对目录）列出工作内容、运行残留、身份与登录材料、插件配置，只读路径、类别、大小与时间。可按类别、项目片段、时间和大小筛选并分页；默认只勾选可清理的运行残留，工作内容需另选，unclassified 位置不会默认删除，身份位置只报告存在性、从不进入清理目标。选中后可“仅精确清理”或“归档并清理”，后者先写独立 lintel.residue/1 加密备份再删除。这一面板的合成计划可把“减少正文记录”“重置本地客户端标识”与所选残留合成一份计划、一次批准。

“身份与登录材料”只识别已核实的 userID 与账号痕迹 oauthAccount，默认只显示存在性；点“显示原始值”后才在本页内存读取 userID，可复制，但不写入 localStorage、普通快照、支持导出或日志。“重置本地客户端标识”先对完整原始客户端状态及你明确选中的备份加密保全，再移除 userID 并逐值保留其他键；它不注销、不清凭据，是否由客户端重新生成按重新检查的结果展示。已有的 lintel.residue/1 备份可用“读取与恢复残留备份”独立解锁与按原路径恢复，已有文件不覆盖，也不作为工作 import。

“环境详情 → 变化与对照”的“变化与对照”面板保存脱敏语义快照并比较两份快照或两个已登记环境，可按新增／删除／修改筛选；“接受所选当前值”只形成比较基线，不是恢复来源。跨环境“将普通配置应用到目标环境”只复制已识别普通字段、显示目标 diff，登录凭据与本地身份不随之复制。轻量变化检查在打开环境或经 Lintel 启动时只读有限配置来源并在有变化或读取不完整时留下提示，没有常驻 watcher。

“高级配置编辑”对明确选择的 user／project-local JSON 配置提供严格校验、逐字段遮蔽 diff 与原任务恢复：写入复用现有计划链，批准前复查摘要，写前生成 age 加密 lintel.config/1 备份，恢复只改原任务字段并保留后续无关编辑，凭据值与未识别键默认遮蔽。

“保护方案”和“清理重建”页内的“快捷配方”面板提供三条可编辑配方：“减少正文记录”关闭已知内容记录字段并保留指标，“清理运行残留”使用本地数据视图当前选中的残留，“保住工作并重建”归档并迁入选中的工作内容。配方只保存方案与有限字段选择等非秘密意图，切换主机或环境后草稿与原任务绑定不漂移；每次运行都按当前主机与环境重新生成计划，绝不重放旧审批。

每条配方按名称、说明、目标与选项摘要排列，右侧保留一个“应用配方”；“编辑”和“保存为个人默认”位于次级操作行。当某主机／环境保存的个人默认与内置预置不同（例如在“减少正文记录”槽位中开启内容记录），该条改显示“个人默认 · 方案名”与按实际意图生成的说明，不再沿用原预置承诺；恢复或没有保存意图时保留原名。当前页面对应的目标有轻强调，其他目标仍可应用并进入对应页面。Recipes.css 是这一组布局的唯一样式入口。

浏览器与网络

首页或清理页的“浏览器工作空间”提供配对、WebRTC、站点清理、站点权限、站点代理、站点阻断、临时暂停规则和独立的全 profile HTTP cache 清理。Firefox 不支持的站点权限、站点代理和 CacheStorage 适配明确显示限制。

首次连接在首页“浏览器”→“连接一个新的 profile”按三步进行。先选择浏览器，点击“预览扩展目录”，核对版本、文件范围与当前用户目录后“批准准备扩展目录”；App 已包含两种正式站点配置的开发包，无需用户拿源码或运行构建。准备后可在 Finder 打开、复制目录路径，并按旁边说明在目标 profile 加载。Chrome / Edge 使用同一固定 Chromium 目录，Firefox 选择 manifest.json 临时加载。受管更新保持路径，随后需在浏览器重新加载；外部或改动过的文件拒绝覆盖，切换浏览器会撤回原预览。第二步填入准确扩展 ID，点击“预览本地连接安装”。App 内置 Native Messaging host，无需单独构建或填写程序路径。预览显示版本、大小、固定组件位置、注册文件和授权 ID；详细内容可对照 manifest 与组件 SHA-256。批准后安装到当前用户的 Lintel 固定目录，移动 App 不改变浏览器所指向的组件位置。已有相同注册可核对；已有本安装器管理的版本先展示更新预览，其余冲突保留并拒绝覆盖。批准前复查整份计划，文件或注册变化需重新预览。

安装只完成组件与精确 extension ID 授权，不表示 profile 已配对或在线。继续生成配对请求，复制 App 的 12 位短码，在目标扩展输入并提交请求，核对两端短码后在 App 另行批准。App 缺少组件时给出具体提示；扩展仍是开发安装，未签名／上架，独立 Chromium 的真实持久安装／完整重启清理已通过，正式 Chrome/Edge/Firefox、AdsPower 与非开发者旅程尚未验收。App 内目录准备、各浏览器加载与独立 CLI host 的用法见 浏览器指南。

桌面提交只准备请求，用户仍需在目标扩展中核对与批准。站点清理先隔离请求、关闭相关页面并注销 Service Worker，随后显示“等待浏览器重启后继续”；用户重启该浏览器并再次批准后才删除其余存储。已完成的数据删除不可恢复，清理隔离需在扩展内单独解除。可恢复的 WebRTC、权限、代理与阻断设置提供独立恢复预览。提交前保留操作 ID；回复丢失时查询原任务，不自动创建新 ID 重做。

本机环境详情的“外发与权限”包含受控代理通道：查看代理实际采用的默认动作、允许／阻止规则与端口、HTTP(S) 上游，启动或停止通道、通过通道打开 Claude、刷新真实连接事件。当前生效配置由 native 读回；下次启动草案按环境保存在 webview 内存中，停止后可基于读回值修改，再明确启动。切换环境不会串用旧请求的响应。它不修改系统代理、不解密 TLS，也不覆盖客户端直接 socket、全部 DNS、UDP 或其他进程。当前 SSH 工作空间不会把本机代理标为远端已受保护。

IPv4 / IPv6 与共享网络

同一“外发与权限”的 IpNetworkPanel 提供四格实测、复制 IP、有限刷新、前测有效性、所选 macOS 服务预览与原任务恢复；NetworkResults / NetworkEvidence 共用计划与回执展示。没有 Claude 环境时可从首页明确打开同一 panel，不建立第二个 executor。NetworkState::dispatch_core 将 probe/preview 绑定到实际 App live 通道实例，执行前同端口的新实例也需重新预览；原任务查询与恢复不依赖旧通道存活。完整配置与 auto-reprobe 进入正常审批 Modal，Flow.environment:null 不套用 Claude root，不开放“打开 Claude”。退出 App 停止通道，但不撤销宿主 IPv6。Linux SSH 使用同一 panel 的只读实测，走目标 runner，不调用本机探针。开发 synthetic bridge 禁止真实 host 操作；network-ui 的配置、回显和 invoke 均为合成证据，真实 WebKit／OS 写入仍未验收。

SSH 工作空间

顶部主机入口或设置中的“主机与 SSH 连接”读取系统 SSH Host alias，保存连接引用，并由用户发起连接。远端连接需要 Lintel runner，安装 Claude Code 不等于安装 runner；缺少 runner 的 Linux 主机可先在下述安装卡预览并批准准备。“连接前需要什么？”提供准备说明和 SSH 排障链接。登记或连接本身不安装、更新软件或改 SSH 配置，不收集密码或私钥。严格 host key 核验失败时应先通过系统 SSH 核对主机。

每个已登记 alias 旁提供“移除”，成功后可“撤销移除”。这里只改 Lintel 登记，不修改 ~/.ssh/config、known_hosts 或远端文件。移除当前工作空间会回到本机，原来的持久提交记录仍可查询；重新登记不会重提原任务。移除失败时保留列表项，并显示原因。

连接错误显示 alias、失败阶段、具体原因、排查建议和可用的退出码。“查看本次错误输出”展开限长的 stderr 片段；带口令或批准信息的请求不展示该片段，原始错误不写入任务记录。“复制排查摘要”不包含 stderr，避免直接复制其中的主机名或本机路径。“重新检查连接”由用户显式触发，只核验连接与读取环境；执行出错时继续查询原任务，不提供自动重提按钮。

连接后，环境、计划、清理、归档和记录均来自该主机，使用同一套界面。执行调用固定 lintel submit，接受回执与最终完成分别呈现；“查询最新结果”和主机面板的持久提交记录查询原 job。桌面重开后在持久提交记录“查询原任务”，再选“查看完整回执与恢复”：只读核对原环境并进入该 alias 的完整结果与记录；配置恢复或服务恢复仍需单独预览和批准。已移除 alias 只允许原任务查询，先重新登记才能准备恢复。关闭面板或切换主机后，迟到回执不恢复已关闭流程或串入另一主机。SSH 中断后不自动重新提交 mutation。接收回执显示实际后台托管方式：满足条件的 Linux 主机使用 system／user transient service；setsid 明确显示断线续跑限制，unit 详情可展开。审批前说明这些条件，旧回执不补造托管事实。后台 worker 的实际存活仍受远端 OS/manager 生命周期影响；真实主机验收与 synthetic/fake-SSH 证据分开，见 远程指南。

环境详情的“检查变化”将读取结果、错误、等待状态和“接受当前值”绑定到当次主机／环境。切换目标后迟到响应丢弃，切回同一环境也不复活旧检查；接受只作用于当前展示的检查目标。

浏览器配对与本机通道属于这台桌面主机，不随 SSH 目标转移。环境详情的“启动与来源”和已完成任务回执都有“打开 Claude”。远端先通过 plan_launch 冻结配置 root、独立项目 cwd 与程序，批准后请求 macOS Terminal 通过同一严格 SSH alias、原 runner 和真实 PTY 调用 launch_request ID HASH。原生续聊走独立 plan_resume／resume_request，口令在 SSH Terminal 再次无回显输入。controller 先保存一次尝试，回复丢失只查询原启动 ID；旧 CLI launch ENV_ID 保留 root-as-cwd 默认。远端 core 复查准确身份，App 不注入 prompt；SSH 断开会结束交互会话，与持久后台任务不同。launch_requested 仅表示 Terminal 接受请求，实际登录和运行状态在终端确认。远端回执处于 accepted/executing/verifying 时，启动按钮保持不可用；先查询原任务到结束状态，再打开新会话。失败信息会滚入可见范围。

帮助与开发者说明

侧栏“帮助”离线提供六任务路径、目标／预览／批准／原 ID 核对四步、会话阅读与 CLI 交接说明，并提供 Faye 的 GitHub、Lintel 源码与说明，以及 Infra Field Guide 的 VPS 101 和连接排障章节。Lintel 是独立工具，项目仓库提供源码、使用说明与当前验收状态。frontend 与 native 共用 contracts/documentation-resources.json，桌面只通过 resources.rs 中有限 resource ID 打开固定 HTTPS 文档链接；clean 构建只把 Lintel 自己的 docs 链接锁定到同一源码 revision，开发构建标明 unknown／最新开发说明。独立指南使用它自己的 main，标为“独立指南 · 最新版”。不接受任意 URL，不附带配置、错误或凭据。网页预览使用普通外链，macOS App 使用系统浏览器。打开失败时保留可复制链接。

远端运行器

顶部主机面板的“检查并准备运行器”支持 Linux x86_64 / arm64。安装卡显示目标、SSH 登录用户、大小、状态和一个主要动作；完整路径、SHA-256 与影响说明在可展开详情中。UID 0 显示为 root；安装与管理以当前 SSH 用户为范围，Claude 由其他用户运行时应选择那个用户的 alias。批准后才上传 App 内文件，核验执行权限与实际 runner 能力后显示“连接并管理”。丢回包立即改为“结果待核对”，从同一记录继续核验；关闭面板不会丢失持久安装状态。已有 PATH runner 可直接连接。安装范围、构建资源与真实 runtime 限制见远程指南。

外观与本地字体

Day / Night / System 直接切换外观，并在当前 webview 记住选择。工作区垫着一层环境光：Day 是右上晨光与左下一点草木色，Night 是月光与几颗静态小星；光亮来自 CSS 渐变，不加载图片，也不随内容滚动。首页使用居中的 Clawd、原创时段问候与留白，任务选择在明确点击后展开；角色保留光晕与地面软影；躲藏或弹飞时地影收起。任务选择面板以两列独立选择呈现；默认首页只保留上次目标与待核对数量入口；专业编辑保持连续分组。任务卡、方案、记录与模态沿用柔和投影与细线，控件有可见 focus。点按角色可发现爱心、热茶、小花、读书、打盹、生日帽、星星、小伙伴、月亮和零食；按住会拥抱，拖动可抱起，快速甩动松手会弹飞。快速连续戳三下变成 ><，六下会躲起来，留下可点击的脚脚；也可在口袋里点“哄回来”。角色下方“陪它玩”打开喝茶、跳跳、摘月亮、小憩与游玩入口；“摘月亮”触发角色的月亮回应，后续互动或 Escape 可重置，角色聚焦时上方向键可跳跃。这些互动不调用模型或改变配置。眨眼、漂浮、起飞与跳跃动画尊重系统减少动态效果设置。

首页滚到顶部，在空白区域下拉，松手超过阈值后主 Clawd 起飞并展开口袋菜单；滚轮向上越过顶部也可触发。未拉够、取消手势或 Escape 会收回。“陪它玩”也支持直接点击与键盘打开；菜单浮在角色旁边，工作区位置不变。口袋内可与角色互动，或进入风景册和小游戏。关闭游玩面板后焦点回到“陪它玩”。文字选择、表单与环境详情中的操作不作为下拉起点。

“去看月亮”打开四幅自行绘制的字符点阵风景：月下山湖、雨夜小屋、海边灯塔、星野营火。深浅字符绘制云、山、水和建筑；Clawd 用独立的橙色块面、两只眼睛及四只单行短脚保持清楚轮廓。整幅画按比例缩放，不压扁角色。画中 Clawd 可收集小星星，风景册独立切换暖纸／夜色。风景参考了 Claude Code 整幅夜景截图 的负空间、点阵层次和角色关系；图形由本地代码绘制，不分发该截图。下拉菜单依据产品要求自行实现，未声称逐帧复刻官方移动端动效。

“Clawd 跳一跳”与官网共用一个游戏实现。Clawd 是一整块连续的像素剪影——一个方正的横身体下面直接伸出四条又短又直的腿，不再单独画脚；普通跑动时身体保持水平，四条短直腿分两组交替迈动，始终连着身体，没有横向小脚；起跳伸展、落地短暂压低。当前源码中，按下跑道或“跳一下”立即起跳；轻点保持原高度，持续按住在这次上升中增加高度，松手只停止加高，不会补跳。空格／上方向键相同；加高窗口 0.26 秒封顶，持续按住不会在落地后自动连跳。普通星星按轻跳轨迹摆放，保留小幅高低变化；较高障碍上的星星会一起上移，避免普通越障时从它上方掠过（每颗 +25 分），每第四颗是高处的大星星（+50 分），需要更高的跳跃。跑道保留原来的单色像素／字符风格山线、云与日月，仅在同一主题墨色中增加树林和庭院标记；石头、书本、花盆与栅栏有各自尺寸，间距有疏有密，较高／较宽障碍之后留出恢复距离。普通跳仍可越障，持续按住用来够高处星星。P 或按钮暂停，碰撞可重开，初速为 260px/s，连续渐增至 350px/s；落地前的短暂输入可接续下一跳。暂停、失去焦点／窗口切换、隐藏／离屏、pointercancel／丢失 capture 和卸载都会清除未完成输入与加高状态；触摸纵向滑动仍可通过 pointer cancellation 接续。切去风景册、关闭面板会释放动画与监听，再次打开只启动一个实例。Day／Night／System 跟随 App；减少动态效果时停用背景移动、尘点、迈腿／伸展与落地缩放，玩家主动按下的跳跃仍然保留。最高分沿用本机 webview 的 lintel.clawd.runner.best，官网在各自浏览器保存独立成绩。它不依赖网络、模型或外部服务。

即时起跳／按住加高、高星、单色三场景与四类障碍属于当前共享源码；现有 e1a2df4 App 候选仍保留旧玩法，不随源码更新。新玩法的纯逻辑与 built-App Chromium／合成 UI 证据不代替 native WebKit 验收，网站生产状态也须按当前状态独立核对。

首页 Clawd 采用固定 SVG 像素几何，小游戏复用该轮廓，风景册用固定字符网格避免字体改变角色比例。形状对照 Clawd 形象参考 与 Claude Code TUI 实际截图，自行编写渲染与场景，不下载参考图作为产品资源。Clawd 形象属于 Anthropic；Lintel 是独立工具。

src/styles.css 负责颜色、布局与交互样式；src/Clawd.tsx 负责角色与情绪，src/ClawdFlightMenu.tsx 负责下拉菜单，src/ClawdPlayroom.tsx 负责风景册与小游戏的 React 挂载／卸载，src/clawd-landscapes.ts 负责四幅字符画。小游戏的唯一实现是 apps/site/clawd-game.mjs 与同名 CSS，由官网直接加载、App 通过 Vite 打包；旧 React runner 已移除。普通跑动胸口保持水平，两组短直腿交替抬起与前后移动，支撑腿保持贴地；起跳保持弹道，真正落地后短暂收势。暂停与 reduced motion 使用静态轮廓，玩法、星星高度与本地成绩保留。角色互动与风景册样式各在同名前缀 CSS 中。字体优先使用可选的本地 Anthropic Sans / Serif / Mono，并提供系统 fallback，无远程字体请求。字体文件没有确立再分发许可，因此只放在忽略的 public/local-fonts/，不进入 Git。显式本地准备命令：

cd apps/desktop
node scripts/local-fonts.mjs /absolute/path/to/authorized-font-directory

此命令仅读取六个精确字体文件名，不扫描来源项目。开发服务器可使用这些本地字体；默认 npm run build 和 npm run desktop:build 排除 public/（当前仅含可选本地字体）与字体加载列表，使用系统 fallback，已有本地字体文件保留。只有显式 npm run build -- --mode local-candidate 才把它们带入本机候选；此类候选不得视为可公开分发包。此处只解决构建夹带字体的边界，签名／公证、扩展发布和正式分发仍未完成。

App 图标 master 是 src/brand.svg，Tauri 使用提供的五个 exports（PNG、ICNS、ICO），图形为陶土横梁、两根中性色支撑和右下光标。App 内 Brand() 使用同一几何并跟随 Day / Night tokens；侧栏 lintel_、分割线和 2.6 秒慢闪保留，reduced motion 下静止。可编辑展示资产与使用边界见 视觉身份。构建包含图标不代表正式 macOS / Linux launcher 已验收。

开发与验证

在“清理与重建”选择修复登录、清理并重建或退役时，可展开“目标后台服务”。输入准确 .service 名称，选择当前用户管理器或系统管理器（runner 须为 root），点击“检查服务”；该动作只读取绑定与状态。确认 unit 确实属于选定配置根后，预览暂停计划，再批准执行。暂停回执或再次检查已暂停的 unit 可准备独立恢复计划；外部 unit 编辑冲突会阻止恢复并保留修改。服务操作完成后返回清理范围，仍需关闭交互终端／IDE 并核对其他写入者。

此能力限于 Linux systemd 的明确绑定服务，不自动 sudo、不修改邻居服务或 enablement。具体来源、暂停项、限制与 CLI 操作见 服务指南。任务回包丢失时只查询原 ID，不能通过再次提交恢复连接。当前 UI 的合成 manager 旅程证明操作与布局；真实 Linux VM、生产 VPS和 native WebKit 证据分别记录。

cargo build -p lintel-runner
cd apps/desktop
npm ci
npm run dev:synthetic
npm run typecheck
npm run build
npm run desktop:build

desktop:build 的 pre-build 会从 extensions/browser/src 构建非 fixture 的 Chromium / Firefox 扩展，生成 browser-extension-bundle 资源，并编译现有独立 browser host。App 随包包含这两种扩展和当前平台 host；构建本身不会准备用户扩展目录或注册浏览器。目前只支持匹配 Rust host 的 native 构建，跨架构／universal App 构建会明确拒绝。开发时可运行 npm run prepare:browser-extension 与 npm run prepare:browser-host 准备资源；复制目录和注册都仍需在 App 中预览并批准。前端 npm run build 不运行这些安装器。

同时开发时可用 LINTEL_FIXTURE_PORT=1422 npm run dev:synthetic，默认仍是 1420。fixture bridge 的端口、Origin 与 Host 校验使用同一配置。合成模式所有 core 状态与发现都位于临时目录，界面持续标明测试空间；原生浏览器、SSH、认证命令与网络模块不会在网页中伪造成功。新增请求必须进入明确 allowlist；登记路径不能逃出合成 home。

主要桌面尺寸为 1120×760，最低 900×640，可收起侧栏。浏览器渲染不能代替 WebKit/native runtime、真实主机或正式浏览器验收。未完成的安装、发行和全产品能力以 当前状态 为准；本文件描述源码接入，不将它等同于正式发布。

本地 Preview 候选

候选提供方应同时提供准确 source revision、平台和构建说明。当前 App 候选为 macOS Apple Silicon，没有正式 distribution signing／notarization；macOS 下载拦截仍可能阻止打开，不能把本地构建能启动视为普通用户下载验收。解压到一个新的版本目录后打开其中的 Lintel.app，不要覆盖旧候选；App 自带所需 native 组件，不需要在试用机器安装 Rust、Node 或开发服务器。首次试用使用自己创建的合成资料，并按 quickstart 的预览、批准和原 ID 查询顺序核对。 从脚本或自动化启动后，应将 Lintel 窗口切到前台再操作；本次 macOS 验收观察到后台窗口暂时空白、点击 Dock 中的 Lintel 后恢复。不要因此删除 state 或重新提交已接受的任务；恢复显示后仍查询原 ID。该观察与完整原生矩阵、普通下载后的 Gatekeeper 验收分别记录。

升级时退出旧 App，保留旧版本及 Lintel state，再从新目录启动新 App；不要并行运行两个版本来执行同一任务。移除候选只需退出 App 后删除自己解压的候选目录。App 移除不会自动撤销已批准的配置、更改 Claude、删除工作包或独立安装的 browser host／remote runner；相关恢复应先通过各自批准流程完成，并保留回执与原 ID。

审批与结果接续

迁入审批展示 core 冻结的最终清单：来源相对路径、冻结的完整配置 root／最终落点、类别、启用用途与大小；旧 import_manifest 保留相对路径合同，摘要与包身份可展开；文件长路径可换行，保留准确原值。计划的配置字段和文件迁入分开呈现。弹窗标题、目标与操作区保持可见，正文按可用高度独立滚动，多项回执动作允许换行。

记录页保留环境筛选与搜索，另有“待处理”集中呈现执行中、中断和未完成结果。配置中断核对说明、独立恢复入口与任务 next_steps 跟随实际回执显示；未决运行器安装错误可直接查询原 install ID。旧安装已被取代与已核实但未绑定分别显示，不暗示当前版本被切换。
