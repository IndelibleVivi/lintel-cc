Troubleshooting by observed result

简体中文 · English · Documentation

Keep the host, configuration path, original task/request ID and error code first. Do not delete Lintel state merely to start over; the original record may be the evidence needed to resolve the result.

What you seeNext actionExplanation
A web page displays the UI but cannot operate locallyUse npm run dev:synthetic for the source trial, or the native app for real environmentsPlain frontend development and the website have no real execution channel
The app works, but the shell cannot find lintelSelect the standalone CLI's absolute path; inspect version --json and context --jsonInstalling the app does not modify PATH; see Agent CLI
accepted or ok:true, with no clear outcomeQuery the original job and inspect status, steps and coverageReception, request handling and task completion are distinct
SSH disconnects, waiting times out, or needs_reconciliation appearsReturn to the original host/state and query the original ID; decide on restoration separatelyDo not resubmit the same destructive action; see Remote
Approval is rejected, a preview expires or the target changesRead the target again, generate and review a new planDo not reuse a stale hash or bypass target checks
Restore is blocked by a field conflictInspect edits made after the task and decide from current valuesLater edits are preserved; restore applies only to owned fields
Package reading is slow or preflight rejects capacityCheck the current runner limits, exact selection and temporary disk space; reduce the selection preciselyEach page requires whole-package decryption/verification. Archive and native-resume limits are separate; see Work
Browser cleanup waits for a follow-upVerify the original profile/operation, then perform the documented full restart and second approvalQuitting the app or closing a tab is not a full browser restart
A running Claude session does not reflect changed settingsInspect readback and launch a new session with the selected rootExisting processes do not refresh their environment automatically
Custom protection has many rows, or only a few should changeFilter first and choose actions per row; enter Bulk edit explicitly when neededBulk offers only common applicable actions and counts selections outside the filtered result; see Protection
A personal default's name does not match its configured intentRead the "personal default · name" and actual description, not only the recipe slotSaved intent that differs from a built-in recipe is labelled from its semantics and every run still needs a fresh preview
IPv6 or proxy results say untested or failedCheck the host, channel and echo target; test only after explicitly choosing itUntested does not mean blocked or leak-free; see Network
App updates, remote installation or browser host is unavailableCheck release configuration, platform and bundled resourcesSource support, packaged resources and a working instance are checked separately

A useful issue report

Include version/candidate source, OS/architecture, app or CLI entry point, target type, reproduction steps, original ID and error code. Redact paths while retaining useful structure. Do not attach credentials, passphrases, raw sessions, work packages or complete state to a public issue; prefer a synthetic reproduction.

Consult Core / CLI for mechanisms and current status (Chinese) for verified platforms and candidates.
