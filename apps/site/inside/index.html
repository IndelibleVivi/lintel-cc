FOUR PATHS / CLEAR OWNERS

四条执行路径

配置读回、代理观察、浏览器操作与 App 更新不是同一份证据。

  1. 01

    环境与文件

    本机 core 或目标 runner 持有清单、冻结计划、文件操作与原任务。SSH controller 发送有限请求，不替远端宣布完成。

    Core 与 CLI
  2. 02

    浏览器

    本机 Native Messaging host 协调配对；已配对扩展拥有 profile 原生操作。清理要经过真实重启和第二次批准。

    浏览器指南
  3. 03

    网络

    通道只约束经过它的连接；配置读回与实际出口实测分别记录。直接 socket、UDP 与 DNS 不在同一个证明里。

    网络指南
  4. 04

    App 更新

    native updater 负责检查、验签、批准安装和明确重启；记录独立于 core job。当前没有公开 feed。

    安装与更新

PLAN / APPROVAL / RESULT

一次操作怎样留下来路

生成并保存计划→审阅准确范围→durable accepted→执行→核对原任务

冻结计划

准确目标、选择内容或字段变化绑定计划 ID 与 hash。条件改变后重新预览，不复用旧批准。

原任务

accepted 只表示持久接收；completed、部分完成、失败与待核对分别看得到。

独立工作包

加密包保存选中的原始字节，可在独立 state 中读取；阅读、迁入与原生续聊是不同操作。

NOT A MAGIC BUTTON

设计边界

不是
通用清理器、指纹伪装或账号解封工具。
不默认
上传工作内容、遥测、账号或整机环境清单。
不推断
配置已读回不等于全部网络已受控；本地目录隔离不建立账号或 OS 沙箱。
不隐藏
未验收平台、缺失资源和不支持的语法返回具体限制。
